# SkillNet診断：説明の論理に沿ったデータ収集（2026-11-03）

目的は、失敗現象・内部の経路・介入による変化を区別して、次に何を改善すべきか判断すること。DMP・Aの保留を維持する。スライドの結論に合う例を選ぶのではなく、固定した対象の成功・失敗・無変化をすべて記録する。

## 1. 説明の順序と必要な証拠

| 順序 | 問い・示したい範囲 | 必要なデータ | 避ける解釈 |
|---|---|---|---|
| 1 問題の所在 | 未見の組み合わせで何が難しいか | 原文・言い換え・手順文の対応成否とタスク別差 | 平均差だけで全タスクの弱点としない |
| 2 観測された失敗 | 対象・段階・接触のどこで逸脱するか | 公式目標、把持proxy、行動、動画の同じ時間軸 | 最初の未達目標を因果的な失敗原因と呼ばない |
| 3 何を選んでいるか | スキル入力とexpert選択の違い | 生のスキルID、変換後ID・mask、18層×行動トークンのexpert ID | expert0を把持などの意味的スキルと名付けない |
| 4 条件を利用しているか | スキルの内容変更が経路と行動へどう効くか | 同じ画像・自己状態・ノイズでのID変更、除去、順序変更。ノイズ変更も対照 | 経路が変わるだけで有益な利用としない |
| 5 何を変えると直るか | 明示した残り操作で復帰できるか | 同じ到達状態から全体指示／残り操作指示／全体指示再実行 | 別の状態からの再試行を同一状態介入と呼ばない |
| 6 次の研究判断 | 計画・進捗認識・操作制御のどれが候補か | 介入の成功・不成功と再現対照を一緒に提示 | oracle診断の成功を実行可能な新方式の性能としない |

既存の途中評価と限界は[11-02診断](dmp_stop_and_diagnosis.md)。現在のスキル一覧はタスク固定で、モデルは意味的スキルIDを一つ出力するのではなく、スキル一覧に条件付けられたMoE expertを層・トークンごとに選ぶ。この二つを図と表で混同しない。

## 2. 今回の固定した開発用収集

実行前に`.skillnet-state/outputs/memory-pilot/skillnet-interventions-20261103/manifest.json`へ固定した。

- 対象：LIBERO-Skill task03「ボウルを下段引き出しに収納して閉める」、task07「ボウルを皿に置いて電子レンジを閉める」、各公開初期状態0・1。既存結果を見て選んだ開発用4例で、最終テストではない。
- 公開SkillNet-90を固定。学習なし、n=10、replan=5、環境seed=7、queryノイズseed=(7+初期状態ID)×100000+query番号。
- 基準走行は各400制御ステップ。公式800ステップ評価の成功率とは比較しない。
- 最初に「置く」の公式目標が3ステップ以上連続成立した後の再計画境界を保存する。そこに到達しない例は欠損として理由を残し、成功する別例に差し替えない。
- その到達状態から各200ステップで、元の全体指示、注釈planの最後の操作だけの指示、元の全体指示の再実行、を比較する。skill/object列、画像、自己状態、予算、ノイズ規則は揃える。
- 同じ初期状態から実行済み行動を再生して、環境・コントローラーの履歴を再現する。全MuJoCo状態の最大差≤1e−7、入力画像のhash一致を必須とする。確認不通過なら因果比較しない。
- 診断サンプラは、既存公開サーバーとの最初の行動の最大差≤1e−4を確認する。通常の失敗は再試行しない。初回準備で出力変換の7行を10行と誤認した検査エラーは、行動実行前に保存・修正した。
- 時間上限90分。診断サーバー1台、XLA PREALLOCATE=false・メモリfraction .24、CPU affinity14–19・4スレッド。収集器は20–25・1スレッド。既存抽象指示評価に変更を加えない。

## 3. 同一観測での介入と内部記録

基準走行の初期観測と、置く目標成立後の保存観測で以下を比べる。画像と自己状態は固定。変える入力は各行の一つだけ。

| 条件 | 変えるもの | 役割 |
|---|---|---|
| original | なし | 基準 |
| reverse_skills | スキルID列の順序だけ | 位置なし経路の負の対照。内容を間違える介入ではない |
| wrong_skill_ids | 固定置換0→3、1→4、3→0、4→1 | スキル内容の利用。object列は固定 |
| no_skills | スキルmaskをすべてfalse | 条件経路を除去した診断。分布外の入力でもある |
| remaining_instruction | promptだけを最後の操作文へ | 言語で残り操作を明示するoracle診断 |
| noise_only | queryノイズseedだけ | 条件変更による行動差の参照スケール |

各再計画で最終デノイズ反復の18層×10行動トークンのexpert ID、選択expert出力の重み付きL2ノルム、共有expert出力のL2ノルムを保存する。主な図は実際に実行する先頭5トークンだけを使う。全デノイズ時刻の解析ではない。

重み付き出力ノルムは振幅の記述で、因果寄与率ではない。共有expertが大きくても、選択expertの小さな変化が接触や成否に重要な可能性がある。多数のqueryを独立エピソードとして統計検定しない。

## 4. 成果物と結果の読み方

収集するものは、各条件の動画、全実行行動、再計画時のsim状態と入力画像hash、保存観測、rawスキルIDと変換後ID、expert選択、ノルム、全公式目標の達成履歴。初回の画像・観測そのものも保存する。大きな生データはローカル出力下に置き、外部へ自動公開しない。

再集計は以下で行う。進行中でも集計できるが、完了済み結果と記録中のqueryを区別する。

```bash
python skill_moe/skillnet/examples/skill_conditioning/analyze_interventions.py \
  .skillnet-state/outputs/memory-pilot/skillnet-interventions-20261103
```

生成物：`analysis/summary.json`、`expert_utilization.csv`、`expert_utilization.png`、`report.md`。図の分母には基準走行だけを用い、同じ状態からの繰り返し分岐を追加サンプルとして混ぜない。

- expertが変わり行動差が小さい場合：ルーティングへの反応と出力への影響が異なる候補。スキル不要とは結論しない。
- 残り指示だけで復帰する場合：その状態での指示解釈・進捗・次操作選択が有力候補。自動で残り操作を選べるかは別問題。
- 残り指示でも失敗する場合：操作制御、対象位置、状態認識、予算不足などが残る。動画と接触を確認する。
- 元の指示の再実行が再現しない場合：数値差・環境再現を先に調べ、介入効果を断定しない。

この4例の結果だけでモデル選択や論文の主張を確定しない。介入の成否を見て調整したタスクは開発用のままとし、後段で未使用の組み合わせと複数学習seedを分けて評価する。

## 5. 収集中に見つかった計測上の問題と追加コホート

最初の計測付きサンプラは4例の初回入力で既存公開サーバーと完全一致した。一方、9タスクすべての初期観測へ広げた監査ではtask09で最大0.001332の差が出たため、事前の同等性基準により8タスク完了時点で止めた。失敗した方策試行ではなく、内部計測によるXLAの浮動小数点評価の差を含む可能性がある。元の停止記録は変更しない。

追加の`reference_initial_survey`では、同じ保存済み9観測について行動を既存公開サーバーから取得し、計測付き出力を別に保存して条件ごとの差を記録する。したがって、行動感度は公開経路の結果、expertの図は近似的な補助計測として区別する。重み・学習・既存評価の設定は変えない。

また、最初の「置く」目標成立後の保存点には、把持proxyがtrueの例や、まだ閉じるコマンドが続く例があった。目標述語の成立を把持解除の完了と同一視しない。`released_followup_manifest.json`で、同じ4例から「置く目標が安定成立・把持接触なし・直前5行動は開くコマンド・残るfixture目標は未達」の最初の保存点を選ぶ追加比較を固定した。

この追加比較の元指示・残り指示・元指示再実行は各200ステップ、行動は既存公開サーバーを使用する。expert記録は別経路の補助計測で、各問い合わせの行動差を記録する。最初のコホートと合算せず、再現検査・結果・欠損を分けて報告する。追加収集は30分のwall-time watchdog付きで、終了後は専用診断サーバーを解放する。
