# 追加可能な運動スキルメモリのための表現学習

検討日: 2026-10-25（日本時間）。論文の方法を比較した設計案であり、以下の比較モデルの実装・学習結果ではない。
既存SkillNetの評価確認と、新しく提案するスキル表現の有効性は区別する。

## 結論

最初の主案は、短い状態・行動列から連続潜在表現を学習するVAE系のスキルモデル。
FIST / SPiRL / Play-LMPを参照し、運動エンコーダと、その表現を使って実際の行動を出す共有デコーダを学習する。
記憶件数は潜在次元・エキスパート数と独立に増やせる。
ただし、記憶追加だけでデコーダの表現能力が拡大するわけではない。

固定長の運動区間で最初の基準モデルを作り、その後にLOVE / CompILE型の境界学習と圧縮を比較する。
検索用の状況表現と、実行用の運動表現は分ける。
DMPは形状表現の解釈可能な比較対象として残すが、最初から少数基底に制約しない。
3〜4個のエキスパートは、必要性が確認できた段階で共有デコーダの構成として検証する。

## なぜ再構成だけでは足りないか

LOVEが扱う問題は、軌道を正しく再構成できる分解が複数存在すること。
例えば、軌道全体を一つのコードにする場合も、毎ステップ別コードにする場合も、
再構成性能だけでは排除できない。
したがって、「再構成できた」「潜在空間がクラスタに見えた」だけでは運動スキル発見の証拠としない。

今回の表現に求める性質は、実行可能性、異なる状況での再利用、複数の経験間での共有、
区間をつないだ際の動作、更新前の記憶との互換性。
これらは仮説として実験で評価する。

## 最初に学習するモデル

運動区間を ξ=(s_t, a_t, ..., s_(t+H)) とする。

- 運動エンコーダ: q_phi(z | ξ)。短い実演全体から運動表現を推定。
- 共有の低位方策: pi_theta(a | s, z, phase)。現在の状態と運動表現から行動を生成。
- 必要に応じた選択モデル: p_psi(z | 現在の観測, 目標, 検索結果)。推論時に使える情報から候補を選ぶ。

これはFIST等を参照した今回の構成案であり、各論文のモデルをそのまま再記述したものではない。
潜在表現が固定次元でも、記憶するベクトルの件数は固定されない。

最初の学習目的は行動の条件付き尤度と、潜在事後分布への弱い正則化。
その後、必要性をアブレーションで確かめながら、運動の到達結果の予測や、
同じ運動の許容される変換に対する整合性を加える。
圧縮・境界学習まで一度に足さず、どの目的が何を改善したかを切り分ける。

### 入力と粒度

- 初期の運動エンコーダは、ロボット状態・行動を主入力とし、物体名やスキルラベルを使わない。
- 可能なら手先の相対位置、相対姿勢、速度、グリッパー状態を使う。絶対位置・外観だけへの依存を減らす。
- 姿勢と接触、グリッパーの変化を捨てない。平行移動や時間正規化が不適切な動作も分けて評価する。
- 初期区間長はH=10,20,40ステップなどで比較する案。これは文献の推奨値ではなく、今回の探索候補。
- 固定窓モデルはaction-chunkの潜在モデルという位置づけ。自動的に運動プリミティブを発見したとは呼ばない。
- その後、最短・最長区間長を制約した境界学習と記述長の目的を比較する。

小さなエンコーダ・デコーダから始め、zが無視されていないかを測る。
強力なデコーダに任せると、zを使わず行動を予測する退化があり得る。
zを固定・シャッフル・交換したときの再構成および実行性能を必ず比較する。

## メモリの構成

初期の一件は「新しい意味ラベル」ではなく、一つの具体的な運動経験を表す。
必要なら後から経験をまとめた代表スキルを作る。

| 保存要素 | 用途 |
| --- | --- |
| 検索キー k | 現在の状況や目的に対し、その経験が使えるかを判定 |
| 実行用表現 z | 共通デコーダを条件付ける |
| 開始条件・到達結果・区間長 | 適用可能性、接続、時間の管理 |
| 表現・デコーダの版 | 更新による互換性の管理 |
| 少量の参照軌道 | 再符号化・リプレイ・忘却評価。総メモリ容量に算入 |

検索キーと実行表現を同一にすることは前提としない。
「似た外観」と「同じ運動を再利用できること」は一致しないため、比較実験で確かめる。
FISTは学習した距離と現在・未来状態の条件付けを参照できるが、こちらの運用時に
実際の未来状態を入力してはいけない。目標は指定・予測・過去経験からの選択で得る。

検索・方策学習で、正解の運動そのものや同じエピソードの隣接窓を容易に検索できると評価が過大になる。
訓練・評価はエピソード単位で分け、さらに条件・動作の組合せを保留する。

## 追加と継続学習

1. 現在のデコーダで再現でき、既存経験と異なる運動なら、新しいzを登録できる。
2. 似た経験なら代表化・統合する。ただし稀な運動の保持と比較する。
3. 再現できない場合は、元経験を保留し、デコーダの追加学習が必要かを判定する。
4. デコーダ更新時は、限られた過去経験のリプレイと旧モデルからの蒸留を比較する。
5. 表現を更新する場合は、検索キーの再索引とzの再符号化を別々に管理する。

新しいzを保存したこと、新しい運動を実行可能になったこと、新しい組合せで目的を達成できたことは別の評価。
Stellar VLAの知識更新、SkillMemoの容量管理との差分は、この具体的な性能と保存コストで確認する。
無限個のスキルを有限モデルで無条件に表現できるとは仮定しない。

## 実験の順序

1. DMP形状パラメータと、状態・行動の連続潜在モデルで、保留した実演の再構成を比較。
2. 同じ潜在表現を、適用条件が合う別の開始状態から実行して再利用を評価。
3. 固定窓と、境界・圧縮を学ぶモデルを比較し、区間長・接続・成功率を測る。
4. 検索なし、ランダム検索、状況キー検索、学習キー検索を比較。
5. メモリだけ追加する場合と、共有デコーダも更新する場合を比較し、新旧双方の性能を測る。
6. 有用な表現が得られてから、SkillNetへ連続潜在の投影を介して接続し、flow-matchingで行動生成を適応する。

初期段階ではVLM全体を学習し直さず、運動モデルの問題を限定する。
既存SkillNetのskill ID埋め込みを連続潜在へ置き換えるには入力契約と学習経路の変更が必要。
単に既存のMoE数を変えたり、整数IDを追加したりする作業ではない。

DMPと潜在モデルの比較で教師付きの行動データを使うことは、「運動の言語ラベルを使わない」という条件と両立する。
ただし、自己教師ありの意味はラベルなしの経験から学習信号を作ることであり、データも目標も不要になるという意味ではない。
訓練データの取得・アクセス確認は別途必要で、この検討ではまだ行っていない。
