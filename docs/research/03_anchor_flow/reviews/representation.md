# 査読：スキル選択が当たらない原因と、表現学習からの改善案（2026-10-29）

観点：表現学習・スキル発見（option discovery、latent action、VQ/クラスタリング、対照学習）。
対象：architecture_v2.md（v2〜v3、V1〜V4）、anchor_flow_skill_memory.md、novelty_anchor_flow.md、memory-pilot の skill-v21 / skill-v22 / skill-v3c / skill-v3c2 / review-v2 / review-tests / interpret-units、実装 `skill_v2.py`。
コード・既存文書は変更していない。追加の数値は保存済み `skill-v21-20261029T060213Z-7493c4/per_row.npz` から再集計したもの（§1.2）。集計スクリプトは査読者のスクラッチ領域にあり、研究リポジトリには置いていない。

## 0. 結論（要約）

1. **「7〜14%」は、主に評価の定義から来ている。表現の問題は二次的。** 正解は「区間の実際の軌道（世界座標の向き・距離を含む）に最も近い単位 1 つ」で、ε による許容も「どの単位にも当たらない」という判定もない。この定義のもとでは、**既知タスクでも、タスク ID と何番目の区間かを完全に知る参照表でさえ、別エピソードでの正答率は 41〜62%**（§1.2）。7〜8 割は、今の正解の定義では原理的に届かない。
2. **D3 の低さの大部分はラベル分布のずれ（label shift）。** D3 で最も多い正解単位は行の 20〜36% を占めるが、学習側の最多単位は D3 では 2〜10% しかない。テスト側の多数派を答え続けるだけで 20〜36% になり、学習した選択器（2〜16%）はそれより低い。V3 の高い正答率（68〜79%）は、K=2〜3 での多数派の水準と同じで、選択ができている証拠ではない（v3c2 報告も同じ結論）。
3. **「正しいスキルを選べば大きく良い」という前提は、半分しか支えられていない。** D3 B の正解スキル（0.1745）は、取り出しの誤りを含むプリミティブ単位 P-a（0.1666）より悪い。S3 gripper＋bridge（0.141、review-v2）よりも悪い。しかも正解スキルは、区間の未来の行動を使って選んでいる（漏れ）。上限としても、汎化の主張の根拠としても弱い。
4. したがって、まず評価をやり直すべき（§4）。そのうえで、表現側の本当の課題は「**行動だけで作った分割は、観測から予測できる保証がない**」こと。表現の改善案は、スキルの形成に「観測から予測できること」を入れる方向に置く（§2 の手法 1〜3）。選択の側は、単位ごとの平均鍵ではなく、メンバー全体の集合として扱う（手法 4）。ラベル分布のずれは、勾配なしで補正する（手法 5）。

## 1. 診断：選択が当たらない本当の原因

### 1.1 実装から確認したこと（skill_v2.py）

| 項目 | 実装 | 含意 |
| --- | --- | --- |
| 区間の表現 | `_relative_commands`：開始点を原点にした**世界座標の軸**の xyz・回転の 32 点＋log 長さ（`trajectory_representation`, `_rep`） | 「右へ 50 mm」と「左へ 50 mm」は別の単位になる。向きと距離は、その場面の物体の配置で決まる |
| 単位の形成 | DP-means 型。ε = 0.1 × 学習区間の対の距離の中央値（`fit`） | 細かい粒度。Split あたり 20〜30 単位で、向き・距離ごとに分かれる |
| 正解の定義 | `_segment_truth_unit`：区間の軌道に最も近い単位の argmin。**ε による判定がなく、「該当なし」もない** | どの単位からも遠い D3 の区間にも、恣意的に正解が付く |
| 選択器の学習 | 多正例 InfoNCE。正例は ε 以内のすべての単位（平均 2.6〜4.0 個 / 20〜30 単位） | 研究者が挙げる「学習データで 93%」は、`training_top1_positive_rate`＝**多正例のどれかに当たれば正解**という値 |
| 選択器の評価 | `selection_metrics`：**argmin の 1 単位だけ**が正解 | 学習の 93% と、D1 の約 50%・D3 の 7〜14% は、**定義が違う数値**。93→50 の落ち込みの多くは、定義の違いによる |
| 鍵 | 単位の鍵 κ_k はメンバーの鍵の**平均**（`_refresh`） | 1 単位は 10〜70 タスクにまたがる（interpret-units）。多峰の集合の平均は、どのメンバーの場面も代表しない |
| 区間の境界 | 評価でも、正解の行動から作ったグリッパーの区切り（最短・最長の制約つき）を使う | 実際の運用では、境界はオンラインで決めなければならない。短い区間の結合には、未来の情報が使われている（軽度の漏れ） |

読み取り：
- **既知タスクの約 50% は、すでにこの正解の定義での上限に近い。** タスクと何番目の区間かを完全に知っていても、同じ場面の別のデモが別の単位に割り当てられる（デモの多峰性と、ε の細かさによる分割）。正答率 7〜8 割という目標は、この正解の定義とは両立しない。
- **D3 の 7〜14% は「上限が約 55〜60% の問題で、ラベル分布が大きくずれた」状態。** テスト側の多数派（20〜36%）にも負けるのは、学習側の事前分布（どの単位がよく出るか）を D3 にそのまま持ち込んでいるため。
- 注意：行単位の集計で、区間の番号は近似。上限は「タスクと区間の番号の関数」についてのもので、画像が物体の位置から向きを当てられれば、原理的には上回れる。ただし、学習した選択器は D1 でもこの参照表と同じ程度。

### 1.3 原因の切り分け：言えること／言えないこと

| 候補 | 判定 | 根拠 |
| --- | --- | --- |
| **評価の定義** | **主因（言える）** | 学習 93% は多正例で、D1/D3 は単一の正解。D1 の上限は約 50〜60%。多数派の基準が報告されていない（v3c2 のみ）。ε の判定がない |
| **ラベル分布のずれ** | **主因（言える）** | D3 の多数派 20〜36% に対して、学習側の最多単位は 2〜10%。選択器は多数派の基準を下回る |
| **表現（向き・距離を含む空間）** | **寄与はあるが、主因とまでは言えない** | 正解が向き・距離で決まるので、新しい配置では観測からの予測が難しい。ただし V4（向き・距離を除く）でも D3 top-1 は 0.11〜0.13 で、改善しなかった。V4 の正解も形状の argmin、鍵も平均で、評価の問題が残ったままなので、表現の効果を切り分けられていない |
| **クエリ側の情報不足** | **一部（言える）** | 区間の開始時の 1 フレームの凍結特徴だけを使う。D1 でも参照表と同じ程度なので、凍結特徴＋小さな MLP では、物体の位置から向きを読み取れていない可能性が高い。ただし言語の有無などの切り分けはしていない |
| **データ量** | **寄与の可能性（未検証）** | 学習区間は約 1,100〜1,300、単位は 20〜30。選択器は学習損失 0.15〜0.20 に対して検証損失 0.50〜0.94 で、過学習している。学習タスク数を変えた学習曲線がないので、言えない |
| **スキルとして選ぶ意味** | 前提が弱い | D3 B の正解スキル 0.1745 は P-a の 0.1666 より悪い。D1/D2 では正解スキル（A 0.077/0.195）が P-a（0.053/0.138）より悪い。正解スキルは、未来の行動から選んでいる |

**まとめ**：「エンコーダの空間が幾何で分かれている」という仮説は、それ自体は正しい観察だが、7〜14% の主な説明ではない。主な説明は (i) 正解を細かい幾何の argmin 1 個にしたこと、(ii) その結果ラベル分布が suite ごとに大きく変わること、(iii) **分割を行動だけで作っていて、観測から予測できるかを形成の基準に入れていない**こと。(iii) が表現学習としての本当の問題で、§2 はここを狙う。

## 2. 構想を守ったまま、選択が当たるための手法

前提として守ること：スキル＝行動空間の区間の集合。ラベルを使わず形成する。新しいスキルは勾配なしで追加できる。条件は画像・サブタスク・状態の埋め込みだけ。行動はいつもスキルの集合から始め、デノイズが場面に合わせる。

**中心の考え方**：「スキル＝場面からは決まらない運動の種類」「場面で決まる幾何＝デノイズが直す部分」という v3 の方向は正しい。足りないのは、**その境目をデータから決める基準**である。表現学習の言葉で言えば、スキルの変数 Z は、行動の区間 A についての情報を持ち（再構成・機能的距離）、**同時に観測 O から予測できる**ものであるべき（I(Z;O) が大きい）。Z で区別できても O から区別できない違い（左右の向きなど）は、Z から外して、集合の中のばらつき（デノイズが場面に合わせる部分）に回す。これは情報ボトルネック（Tishby, Pereira, Bialek, arXiv:physics/0004057 v1, 2000, https://arxiv.org/abs/physics/0004057 ）の形で、構想の「集合を出発点にし、デノイズが場面に合わせる」にそのまま対応する。

### 手法 1：観測から見分けられない単位を統合する（勾配なし、最優先）

先例：
- BUDS（Zhu, Stone, Zhu, arXiv:2109.13841 v2, https://arxiv.org/abs/2109.13841 ）：区切られていないデモから、区間をボトムアップに階層クラスタリングしてスキルを作る。
- LOTUS（Wan ら, arXiv:2311.02058 v4, https://arxiv.org/abs/2311.02058 ）：LIBERO で、ラベルなしのスキル発見と、継続的なスキルライブラリの更新を行う。

どちらも「行動・視覚の類似度」で集める。ここで加えるのは「**観測からの混同**」を統合の基準にすること。

```
入力：DP-means で作った細かい単位 {k}（今の v2.1 のまま、20〜30 個）
1. 学習 suite をエピソード単位で K 分割（交差検証）。選択器 p(k|o) を学習し、
   保留したエピソードで混同行列 C[i,j] = P(選ばれた j | 正解 i) を作る
2. 対称化した混同 S_ij = (C_ij + C_ji)/2 が閾値 θ を超え、かつ両単位の機能的距離が
   上限 δ_max 以下（運動の種類が近い）なら、i と j を 1 つのスキルに統合する
   → 統合したスキル K' = {i, j, …} は「行動空間の集合」のまま。代表 μ、ばらつき Σ はメンバー全体から
3. 統合をくり返し、保留での選択の正答率が目標（例：0.7）に届く、最も細かい分割で止める
   （θ は唯一の外部基準。個数は決めない）
4. 出発点：x = μ_K'(φ) + Σ_K'(φ) に応じたノイズ。集合の中の向き・距離の違いは
   デノイズ（場面の埋め込みを条件にしたアクションヘッド）が担う
5. 継続追加：新しい区間は、今までどおり DP-means で単位を作る。数エピソードたまったら、
   そのエピソードだけで混同を測り、手順 2 を局所的に適用する（勾配なし）
```

構想との対応：スキルは「行動空間で似た行動の集合」のまま。粒度は「場面から決められる運動の違い」まで、という基準がデータから決まる。

注意（査読で突かれる点）：統合すると、選択の正答率は自明に上がる（K→1 で 100%）。そのため、**正答率と同時に、正解スキルの MSE と、選んだスキルの MSE の両方**を報告し、MSE が悪化しない範囲での統合に限る（§3）。

### 手法 2：二つの見え方で互いの割り当てを予測するクラスタリング（SwAV / IIC 型）

先例：
- SwAV（Caron ら, arXiv:2006.09882 v5, https://arxiv.org/abs/2006.09882 ）：一方の見え方から作ったクラスタの割り当て（Sinkhorn で均等化）を、もう一方の見え方から予測する。
- IIC（Ji, Henriques, Vedaldi, arXiv:1807.06653 v4, https://arxiv.org/abs/1807.06653 ）：二つの見え方のクラスタの割り当ての相互情報量を最大化する。
- DeepCluster（Caron ら, arXiv:1807.05520 v2, https://arxiv.org/abs/1807.05520 ）。

ここでは「二つの見え方」を、**行動の区間 A** と**開始時の観測 O（画像・サブタスク・状態の埋め込み）**にする。

```
プロトタイプ C = {c_1..c_K}（K は上限。使われないものは捨て、DP-means の規則で増やす）
行動側   z_A = g(A の開始点相対の軌道)        p_A = softmax(z_A·C / T)
観測側   z_O = f(o)                           p_O = softmax(z_O·C / T)
割り当て q_A = Sinkhorn(z_A·C)、q_O = Sinkhorn(z_O·C)   （ミニバッチ内で均等化。1 クラスへの潰れを防ぐ）
損失 = CE(q_A, p_O) + λ_o·CE(q_O, p_A)      ← 交差予測。O から見分けられない分け方は残らない
     + λ_r·‖Dec(c_{argmax q_A}, o, φ) − A‖²   ← スキル＋場面で行動を再構成（運動の情報を保つ）
     + λ_g·L_機能的距離（同じプロトタイプの区間は機能的距離 ε 以内）
スキル k ＝ argmax q_A = k の区間の集合（行動空間の集合。μ_k, Σ_k は今の v2 と同じに作る）
選択 ＝ argmax p_O。信頼度 ＝ p_O の最大値または相互情報量の寄与
継続追加：新しい区間を g で埋め込み、最も近いプロトタイプとの距離が ε を超える区間が、
         支持数・エピソード数の条件を満たしたら、新しいプロトタイプを追加（勾配なし）。
         その f 側の鍵は、メンバーの z_O の集合（手法 4）で持つ
```

構想との対応：スキルはスキル ID として方策に入らない。f は選択のためだけに使い、アクションヘッドの条件は従来の埋め込みのまま。V3（競合）が 2〜3 単位に潰れた問題は、Sinkhorn の均等化で抑える。V2（対照）とは、「場面ごとの区別」ではなく「O から予測できる分け方」を直接目的にする点が違う。

### 手法 3：観測から予測する事前分布へ、スキルの事後分布を寄せる（V1 の改良：SPiRL / OPAL 型）

先例：
- SPiRL（Pertsch, Lee, Lim, arXiv:2010.11944 v1, https://arxiv.org/abs/2010.11944 ）：スキルの潜在 z の事前分布 p(z|s) を、状態から学習する。
- OPAL（Ajay ら, arXiv:2010.13611 v3, https://arxiv.org/abs/2010.13611 ）：オフラインのデータから潜在のプリミティブを学習し、初期状態に条件づけた事前分布を持つ。
- 離散化の先例：QueST（Mete ら, arXiv:2407.15840 v3, https://arxiv.org/abs/2407.15840 、LIBERO で FSQ によるスキルのトークン）、VQ-BeT（Lee ら, arXiv:2403.03181 v2, https://arxiv.org/abs/2403.03181 ）。
- KL の両方向の重みの釣り合い：DreamerV2（Hafner ら, arXiv:2010.02193 v4, https://arxiv.org/abs/2010.02193 ）の KL balancing。

今の V1 は KL を N(0,I) に向けている。これでは b が小さくなるだけで、O から予測できる方向に曲がる保証がない。

```
q(z | A)        行動の区間だけから（場面を見ない。V1 の Enc）
p(z | o)        開始時の観測から（選択器そのもの）
Dec(z, o, s, φ) 場面を見るデコーダ（V1 と同じ）
損失 = 再構成 + β·[ α·KL(sg q ‖ p) + (1−α)·KL(q ‖ sg p) ]
     （α 大：p が q を追う。1−α：q が p の予測できる領域へ寄る。DreamerV2 と同じ釣り合い）
     + デコーダが z を無視しないための項：同じ o で z を入れ替えると、行動が機能的距離 ε 以上に変わる（V2 の対照項）
スキルの形成：z の空間で DP-means（個数を決めない）→ 区間の集合
選択：p(z|o) の平均に最も近いスキル、または p のもとでの各スキルの確率
```

V1 との違いは、事前分布を観測の条件付きにし、q をそこへ寄せる 1 項だけ。実装の差分は小さい。

### 手法 4：単位の平均鍵をやめ、メンバー全体からの近傍投票で選ぶ（勾配なし）

先例：
- VINN（Pari ら, arXiv:2112.01511 v2, https://arxiv.org/abs/2112.01511 ）：表現学習した空間で、近傍のデモの行動を重みづけて使う。
- Behavior Retrieval（Du ら, arXiv:2304.08742 v2, https://arxiv.org/abs/2304.08742 ）：ラベルのないデータから、似た状態と行動を問い合わせて取り出す。

```
各スキル k は、メンバーの開始時の埋め込み集合 M_k = {e_m} を持つ（κ_k の平均は使わない）
選択スコア s_k(o) = log Σ_{m∈M_k の上位 r 近傍} exp(cos(E(o), e_m)/T)  − log |M_k|^γ
   （γ で、メンバーの多いスキルが有利になる分を調整）
エピソードの重複を避けるため、同じエピソード・同じ収録のメンバーは除く
継続追加：メンバーを足すだけ（勾配なし）
信頼度：上位 2 スキルのスコア差と、最近傍の絶対的な類似度（RTS 型）
```

1 単位が 10〜70 タスクにまたがるので、平均鍵は多峰の集合の平均になり、代表として意味をなさない。D1 のコサイン top-1（0.47〜0.52）と学習した選択器（0.49〜0.55）がほとんど同じことも、鍵が律速であることを示唆する。単独では §1.2 の上限を超えないので、**手法 1〜3 の選択部分として組み合わせる**。

### 手法 5：ラベル分布のずれを、テスト時に勾配なしで補正する

先例：BBSE（Lipton, Wang, Smola, arXiv:1802.03916 v3, https://arxiv.org/abs/1802.03916 ）。混同行列を使ってテスト側のクラスの事前分布を推定し、出力を補正する。

```
学習 suite の保留データで混同行列 C と選択器の出力 p(k|o) を用意
新しい suite のクエリ（ラベルなし）で、予測の分布 μ̂ を集計
テスト側の事前分布 π_test = C^{-1} μ̂（非負に射影）
補正：p'(k|o) ∝ p(k|o) · π_test(k) / π_train(k)
D2（追加あり）では、エピソードが進むごとに π_test を更新（勾配なし）
```

構想との対応：スキルも条件も変えない。「新しい場面では、どの運動がよく出るか」だけを推定する。§1.2 では、テスト側の多数派だけで 20〜36% あるので、効果が直接出るはず。ただしテストのクエリ（ラベルなし）を使うので、**テスト時適応として別に報告する**。

### 優先順位

1. §4 の評価のやり直し（実験なしで、保存済みの per_row から可能）
2. 手法 4＋手法 1（勾配なし。数時間で検証できる）
3. 手法 5（同上。テスト時適応として別に報告）
4. 手法 2 または手法 3（表現学習の本命。V1/V2 の結果を見てから、どちらかを選ぶ）

## 5. 一言での提言

「正しいスキルを当てれば良くなる、だから当てる精度を上げる」の順ではなく、「**観測から当てられる違いだけをスキルに残し、当てられない違い（場面の幾何）は集合の中のばらつきとしてデノイズに任せる**」ように、スキルの形成の基準を変えるべき。これは構想（スキル＝集合、デノイズ＝場面への最適化、条件は埋め込みだけ、勾配なしの追加）を一切崩さない。最初の一歩は、保存済みのデータでの評価のやり直し（E0）と、勾配なしの手法 4・1・5（E1〜E3）で、どれも 1 日以内で判定できる。
