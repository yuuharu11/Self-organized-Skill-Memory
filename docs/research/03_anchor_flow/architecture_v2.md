# スキルメモリ v2：発想の源泉に立ち返った改善案（2026-10-29）

**改訂の理由**：最初の版（同日）は「通常の方策が迷うときだけメモリを使う」という設計だった。これは、スキルを通常の方策の補助にしてしまい、発想の源泉から外れていたので撤回する。

## 0. 発想の源泉（山本さんの構想、2026-10-28）

- 適切な根本的な運動（スキル）がまずあり、それを状況に応じて最適化するのがデノイズの過程である。
- 行動空間で似た行動を集めると、自然に集合ができる。その集合をデノイズの出発点にすれば、集合を表現できる。
- プリミティブな運動は MoE のエキスパートが担う。スキルはそれを一段抽象化したもので、自己組織化し、継続して追加できる。
- 条件は、画像・サブタスク・ロボット状態の埋め込みだけ。スキルを外部の条件としては与えない。

つまり、**行動はいつもスキルから生まれ、デノイズはスキルを場面に合わせる役割に限られる**。「ノイズからの通常の方策」が主役ではない。

## 1. これまで、なぜスキルが効かなかったのか

構想が悪かったのではない。実装の中のスキルとデノイズが、構想のとおりになっていなかった。

| 構想 | これまでの実装 | 結果 |
| --- | --- | --- |
| スキル＝根本的な運動 | 0.5 秒の動きのかけらを、約 70 タスク分平均したもの | 運動の型ではあるが、スキルの粒度ではない。隣の区間で 79% 切り替わる（単位の解釈） |
| 集合を出発点にする | 集合の中心 1 点（平均）だけを使う | 細部が失われる（終端の位置が 18 → 45 mm ずれる、往復テスト） |
| デノイズ＝スキルを場面に合わせる | アクションヘッドは主にノイズから行動を作るよう学習（スキルからの経路は一部だけ） | ずれたアンカーを直す力が弱い。閉ループの既知タスクで成功率が下がった（95.5% → 86.5%） |
| ノイズの量はスキルと場面のずれに応じる | 取り出しの確信度から決める | 確信度がほぼ一様で、t0 が 1 に張り付いた／較正しても場面と合わない |

それでも、構想を支える兆しは出ている。似たデモがない場面では、単位が生の区間に勝つ（同じ件数の生の区間に対しても勝つ）。単位を別の場面で復号しても、運動の型は 78〜96% 保たれる。

## 2. v2：スキルを中心にした設計

```
スキルの形成（ラベルなし、勾配なしで追加できる）：
  デモをグリッパーの開閉などで区切る → 数秒の運動の区間
  区間を、区間の開始時の手先を原点にした座標で表す（場面に依存しない運動の形）
  機能的距離で集める → スキル k ＝ 区間の集合
  スキルが持つもの：
    代表の軌道 μ_k(φ)     φ ∈ [0, 1]：スキルの中の進み具合
    ばらつき   Σ_k(φ)     集合の広がり。場面によって変わる部分
    鍵         κ_k        区間の開始時の埋め込み（画像・サブタスク・状態）の平均

行動の生成（毎回スキルから始める）：
  1. スキルを選ぶ：q = E(画像, サブタスク, 状態) と κ_k を比べ、上位の候補から 1 つ選ぶ
     選んだスキルは終わるまで続ける（φ が 1 に達するか、グリッパーが切り替わるまで）
  2. 出発点：x = μ_k(φ のところの次のチャンク)  ＋ Σ_k(φ) に応じたノイズ
     ノイズの量はスキル自身のばらつきで決まる（集合の広がり＝場面に合わせる余地）
  3. デノイズ：スキルの集合の中から、いまの場面に合ったメンバーへ寄せる
     アクションヘッドは「スキルの代表＋ノイズ → 実際の行動」の経路だけで学習する
  4. φ を進める
  どのスキルにも当てはまらない場面：新しいスキルとして追加する（継続学習）
```

### デノイズの学習：誤ったスキルからでも元の行動に戻れるように（2026-10-29 ユーザーの指定）

スキルの選択はいつか誤る（取り出しの正答率は約 50%）。ノイズの大きさと反復回数は**信頼度**（クエリとそのスキルの鍵の一致の度合い）で決める。誤ったスキルは信頼度が低くなるので、強いノイズと多い反復回数で始まる。その状態からでも元の行動に戻れることを学習させる。

```
信頼度 c(q, k)：クエリ q と、出発点に使うスキル k の鍵 κ_k の一致の度合い
              （類似度、1 位との差など。推論と学習で同じ定義）
ノイズの大きさ τ = g(c)、反復回数 n = h(c)   g, h は単調（信頼度が高いほどノイズも反復も少ない）

学習のたびに出発点のスキル k を、次のどれかから選ぶ：
  (a) 正しいスキル、正しい進み具合
  (b) 正しいスキル、進み具合がずれている
  (c) 近いが違うスキル（2〜5 番目に近い）
  (d) 無関係なスキル（ランダム）
  (e) アンカーなし（純粋なノイズ、τ = 1）
そのスキルに対する信頼度 c(q, k) を推論と同じ方法で計算し、τ = g(c)
出発点 x_src = (1 − τ)·a_k + τ·ε
経路 x_t = (1 − t)·A + t·x_src、速度の目標 x_src − A、t = 1 から 0 へ n = h(c) ステップ
g, h は学習データの保留分で較正する（信頼度ごとに、戻れる誤差が最小になる τ と n）
```

推論でも同じ c → τ, n を使う。学習のときに正解とのずれを使ってノイズを決めることはしない（推論で使えない情報なので）。

確かめること：誤ったスキルを強制的に選ばせたとき、信頼度から決まるノイズで、通常の方策と同じくらいまで戻れるか。正しいスキルのときは、通常の方策より良くなるか。

### 各部品の理由

| 部品 | 構想との対応 | 根拠と、確かめること |
| --- | --- | --- |
| スキル＝数秒の区間の集合 | 「根本的な運動」「似た行動の集合」 | 0.5 秒の単位はかけらにすぎなかった。グリッパーで区切った上位スキルは時間的にまとまる（切り替わり 4〜6%） |
| 開始時の手先を原点にした座標 | 場面に依存しない運動の型 | いまの b は行動チャンクの圧縮で、場面の情報が混ざる。座標をそろえれば、同じ運動が場面をまたいで集まるはず（要確認） |
| 代表＋ばらつき | 「集合をデノイズの出発点にする」 | 平均の 1 点では細部が失われた。ばらつきを持てば、集合として表せる |
| ノイズの量＝スキルのばらつき | デノイズ＝場面への最適化 | 場面ごとに変わる余地の大きい部分ほど、デノイズで動かせるようにする。取り出しの確信度で決める方式（既存手法と同じ）より、構想に合う |
| アクションヘッドはスキルからの経路だけで学習 | デノイズはスキルを場面に合わせる | 補正の経路を明示的に学習すると良くなった（R7、Split B） |
| スキルは終わるまで続ける | スキル＝まとまった運動 | 毎回選び直すと、取り出しの誤り（約 50%）が毎回入る |
| プリミティブは MoE のまま | プリミティブはエキスパートが担う | SkillNet のアクションエキスパートの MoE はそのまま使う |
| 条件は埋め込みだけ | 外部の条件にしない | スキルは出発点として入るだけで、アクションヘッドに別の入力として渡さない |

### 2026-10-29 改訂：スキルの空間を「場面からは決まらない部分」にする（v3）

v2〜v2.2 で、スキルの選択の正答率は未学習の場面で 7〜14% だった。原因は、行動の復元だけで学習したエンコーダの空間が、場面で決まる幾何（方向・距離）まで含み、スキルが幾何ごとに分かれていたこと。そこで、場面への合わせ込みをデコーダ側に持たせ、スキルの空間には「何をするか」だけが残るようにする。

```
b = Enc(行動の区間)                         b は小さく、情報量に制限（KL の重み β）
行動 ≈ Dec(b, 場面の特徴, 状態, 進み具合)    場面から決まる部分はデコーダが担う
→ b の空間で、個数を決めずにスキルを形成（M6 の規則）
```

試す変種：
- V1：上の形で β を振る
- V2：V1 ＋ 同じ場面で違う運動の区間を区別させる対照の項（b が無視されないように）
- V3：競合による自己組織化。スキルごとに小さなデコーダを持ち、区間を最もよく説明できるスキルに割り当てる。どのスキルも説明できなければ新しいスキルを作る
- V4（比較用、人手の設計）：区間の動きを正味の移動方向と距離で正規化してから集める

確かめること：スキルの数と、運動の種類ごとのまとまり（事後の動詞の純度）。選択の正答率（目標 7〜8 割）。D3 の誤差。b が使われているか（b を入れ替えたときの行動の変化）。

## 3. 解釈できること

行動が毎回「スキルの代表 ＋ デノイズによる修正」に分かれるので、次のように説明できる。

- いまどのスキルの、どの進み具合（φ）にいるか。スキルは数秒の運動で、「近づいて掴む」「持ち上げて運ぶ」のように軌道として見せられる。
- デノイズがスキルの代表をどれだけ、どの方向に直したか（場面に合わせた部分）。
- スキルがどのデモから形成されたか。
