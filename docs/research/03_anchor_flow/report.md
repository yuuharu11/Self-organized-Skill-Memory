# 現状報告：スキル記憶つき VLA は、新しいタスクで効くのか（2026-10-31 15:20 UTC）

この文書は、前提知識のない読み手向けに、ここまでの経緯をまとめたものです。これだけで読めるように書いています。数値はすべて実測です。撤回した主張は、撤回したと明記しています。

---

## 0. 一言で

- ロボットの VLA に、ラベルなしで作った「スキル（運動の型）」の記憶を足し、**見たことのないタスクへの汎化**を上げたい。
- これまでの結論：
  - 記憶から取り出したスキルは、**既知のタスクでは効く。**
  - **新しいタスクでは、どの使い方でも方策そのもの（スキルなし）を上回らない。**
  - オフラインで確かに効いたのは、スキルと無関係な 2 点だけ。アクションヘッドの微調整と、少ないステップでのデノイズ。
- 今、閉ループの評価（LIBERO-Skill）を回している。
- **解決したいこと**：スキル記憶が、新しいタスクで方策の知らない情報を与えられる形があるか。あるなら、どう作るか。

---

## 1. 目標と、譲れない条件

- **最終目標**：LIBERO-Skill（skill_obj_02〜09、ゼロショット）で、SkillNet の論文値の成功率 44.5% を超える。論文の π0.5 は 28.5%。将来は RoboCasa365 と実機も使う。
- **ベースモデル**：公開されている SkillNet（π0.5 / openpi、LIBERO-90 で学習した MoE のアクションヘッド）。
- **研究の芯（著者の譲れない条件）**
  1. 目的は**汎化**。推論の速さは目的にしない。
  2. **行動は常にスキルから生まれる。** スキルを補助扱いする設計は避ける。
  3. スキルとは、**場面に依存しない運動の型**。人手のラベル（サブタスク名など）なしで創発させる。取り出しは上位候補の softmax ブレンドで、個数は固定しない。
  4. 取り出したスキル a からフローマッチングのデノイズを始め、場面に合わせる。**ノイズ量 t0 と反復回数は、取り出しの確信度で決める。**
     ```
     x_t0 = (1 − t0)·a_skill + t0·ε
     ヘッドで t0 → 0 まで、n ステップ積分する
     ```
     openpi の規約で t = 1 がノイズ。t0 = 1 は通常の方策と同じ。
- **関連研究**：BehaviorVLA（プロトタイプ記憶を、ガウス事前として flow matching に入れる。行動のラベルを使い、未知タスクでは評価していない）。

## 2. 仕組みと評価の設定

- **メモリ**：LIBERO-90 の 55,660 個の行動チャンク（10 ステップ × 7 次元。xyz 3、回転 3、グリッパー 1）。
  - 各チャンクは、キー（VLM の最終層をトークンで平均し、中心化したもの）、自己符号化器の潜在 b、生の行動を持つ。
  - b をクラスタリングした運動単位が 57 個ある。
- **取り出し V**：今の観測のキーとのコサイン類似度で上位 5 件を取り、softmax(sim / 0.05) でブレンドする。
- **オフライン評価**
  - 新しいタスク：LIBERO-90 の 10 タスクを、メモリと学習から丸ごと除外して評価に使った。最初は 160 行。のちに 1,500 行に増やした（グリッパーが切り替わる行 712 を含む）。
  - 既知タスク：保留したデモの 256 行。
  - 指標：デモの行動との正規化 MSE（有効な 7 次元）。対の差（同じ行・同じ ε）に、エピソード単位のブートストラップで 95% 区間を付ける。負の値が改善。
- **記号**
  | 記号 | 意味 |
  |---|---|
  | P1 | 方策の 1 サンプル |
  | P3 | 3 サンプルの平均 |
  | O | オラクル（正解に最も近い、別のエピソードのチャンク） |
  | FT | 微調整したヘッド |
  | n | 積分のステップ数 |

## 3. これまでにやったこと（時系列）

### 3.1 学習なしで、凍結ヘッドにスキルを入れる（〜10/30）

- **既知タスク**：誤差が 16〜21% 下がる。
- **新しいタスク**：改善がほぼ消える。
- **閉ループ**（LIBERO-Skill、37 組、凍結ヘッド）
  | 条件 | 成功数（基準 27 に対して） |
  |---|---:|
  | 類似度ゲートつき（低ければ t0 = 1 に戻す） | 25〜26 |
  | ゲートなし、t0 = 0.4 | **20**（悪化） |
  - ゲートつきは、LIBERO-Skill では類似度が閾値をほとんど超えず、90〜100% の問い合わせで通常の経路になった。**閾値で通常の経路へ戻す簡易 MoE は、このとき試している。**

### 3.2 新しいタスクでの改善の正体を分解した（10/30 夜）

| 新タスク、P3 との差 | 差 |
|---|---:|
| 方策 3 サンプルの平均（P3）対 1 サンプル | −.016（**以前の「改善」は、ノイズを減らした効果だった**） |
| V | +.014（悪化） |
| O | −.026 |
| O の「型」だけ（並進の残差の波形、回転、グリッパー） | −.022 |
| O の「空間」だけ（方向と距離） | −.005 |
| グリッパーだけ O に差し替え | −.013 |
| 回転だけ O に差し替え | −.008 |

方向と距離は、方策のほうが上手い。記憶の価値があるとすれば、「型」（グリッパーのタイミングと回転）。

### 3.3 型を選ぶ方法を 6 通り試した（すべて方策に負けた）

下書きは、並進を P3 の方向・距離に合わせ、型を候補から取ったもの。凍結ヘッドで t0 = .2、n = 2。

| 選び方 | 新タスク Δ vs P3 | 選んだ型の距離（**P3 自身は 0.032**） |
|---|---|---:|
| VLM 類似度ブレンド | +.008 | 0.045 |
| 平均キーと状態から学習した並べ替え器（4.3 万行） | +.019 | 0.056 |
| 凍結ヘッドの速度場の整合性 | +.004 | — |
| 平均前の画像・言語トークンに cross-attention | +.010 | 0.040 |
| 同上で、1 トークンに潰したもの | +.007 | 0.039 |
| 視覚を使わない選択器（状態の履歴、方策のサンプルのばらつき） | グリッパー MSE .44（P3 は .31） | — |
| （参考）VLM の上位 50 件の候補のうちのオラクル | −.019 | 0.014 |

- 選択器は、検証タスクでは学習できている。型の距離は、VLM の 1 位 0.079 → 0.046 に下がった。
- しかし新タスクでは、**方策 P3 自身の型のほうが正解に近い。**
- 外部レビューの指摘に同意している。「オラクルが強い」のは、5.5 万点で行動空間が密に覆われているだけで、記憶が新しいタスクの知識を持っている証拠にはならない。正解を見ずに選ぶのは、行動を直接予測するのと同じ難しさ。

### 3.4 アクションヘッドを、スキルの下書きから直すように微調整した（10/31）

- **学習**：
  - 公開 SkillNet から始め、action expert だけを学習した。
  - 通常の flow matching の行と、スキルの下書き（同じタスクを除いて取り出した V）の行を、半々にした。
  - 下書きの行の損失は `‖x_t − t·v_θ − a‖²`、`x_t = (1 − t)·A + t·ε`、t ～ U[0.1, 1]。
  - 学習率 1e-5、1,000 ステップ。
- 以前の失敗：
  - 目標を ε − A にすると、「ずれを直さない」方向に学習し、成功率が 31% に落ちた。
  - 目標を (x_t − a)/t にすると、t が小さいときに発散する。
  - 今回はどちらも使っていない。

| 新タスク 1,500 行、P3 | 総 MSE | グリッパー MSE | 符号の誤り | 切り替え時刻の誤差 |
|---|---:|---:|---:|---:|
| 公開、ノイズから n = 10 | .0675 | .313 | 10.1% | 3.88 ステップ |
| **FT、スキルなし、n = 2** | **.0547** | **.252** | **8.6%** | **3.20** |
| FT、自分自身の下書き、t0 = .4 | .0619 | .295 | 8.3% | 3.20 |
| FT、スキル V、t0 = .4、n = 2 | .0695 | .335 | 10.8% | 3.96 |
| 公開（凍結）、スキル V、t0 = .4、n = 2 | .0845 | .410 | 12.4% | 4.57 |
| FT、オラクルの下書き（160 行） | .0137 | .003 | 0% | — |

- **微調整と、少ないステップ（n = 2）は確かに効く。** 公開 .0675 → .0547。既知タスクでも悪化しない（step 1,000）。
- **スキルを入れると、どの形でも悪化する。** スキルなしとの差は、FT で +.012〜+.015、グリッパーで +.083 [+.068, +.099]。
- **撤回した主張**：160 行（切り替わる行 14）では「グリッパーにはスキルが効く」（.084 → .066）と見えた。しかし 1,500 行で逆転した。小標本の偶然だった。
- そのほかにも、効かなかったもの：
  - 腕は方策、グリッパーはスキルという事後の合成
  - 積分の途中でグリッパーだけをスキルに差し替える方法（τ = .4、.6）
- 実行系の確認：LIBERO のグリッパーは、出力の**符号**で開閉の方向だけを決める。「中間値で半開きになる」という説明は当たらない。

### 3.5 「ルーティングすれば勝てるか」の上限（1,500 行、行ごとに良いほうを選んだ場合）

| スキルなし FT と組み合わせる相手 | 勝つ行の割合 | オラクルの MSE（スキルなし比） |
|---|---:|---:|
| FT ＋ スキル V | 35% | 89% |
| FT ＋ 自分自身の下書き（スキルなし） | 38% | 93% |
| FT、ε = 0 のサンプル（スキルなし） | 45% | 91% |
| （グリッパーのみ）スキル V 対 **シャッフルした V** | 58% 対 21% | .231 対 .235 |

- 2 つの予測の良いほうを選べば、何を組み合わせても誤差は 1 割前後下がる。
- **スキルを入れたときの上限は、スキルを使わない対照と同じ。** でたらめなスキルでも同じだった。
- したがって、学習したルーターで「通常のエキスパート」と「スキルのエキスパート」を切り替えても、スキル固有の価値は取り出せない見込み。スキル専用のエキスパートを別に学習する案は、まだ試していない。

## 5. 課題

1. **新しいタスクで、記憶が方策の知らない情報を持っていない。** 少なくとも、10 ステップの行動チャンクを観測の類似度で引く今の形ではそう。方策 P3 の型は、取り出したどの型よりも正解に近い。
2. **選ぶための情報がない。** 候補の中に近いものはあるが、6 通りの選択器、ルーターの上限、どれもスキルを使わない対照と同じかそれ以下。
3. **効いた改善が、研究の芯と無関係。** 微調整と少ないステップは、スキルなしで効く。このままでは「スキル記憶の論文」にならない。
4. **オフラインの指標と閉ループの対応が未確認。** MSE は、平均的な予測（P3、少ないステップ）を有利に扱う。以前、凍結ヘッドにスキルを常に入れたときは、閉ループで悪化した。
5. **ハーネスでの基準が未確立。** 公開 SkillNet が、このハーネスで 44.5% を再現するかどうかが、まだわからない。

## 6. 解決したいこと・相談したいこと

1. **記憶の単位を変えるべきか。** 10 ステップの微視的なチャンクは、方策がすでに知っている。方策が単体では出せない情報に絞った記憶なら、新しいタスクで効く見込みがあるか。具体的に、どの単位が有望か。
   - 候補：タスク全体の手順（どの順で何をするか）、行き詰まったときだけ発動する立て直しの動き、物体どうしの関係にもとづく型。
2. **「行動は常にスキルから」と「汎化」を両立する定式化。** 今の結果では、スキルを強く入れるほど新しいタスクで悪化する。スキルを生成の主役にしたまま、場面への適合をフローに任せる、正しい分担の形は何か。
3. **ラベルなしで創発するスキルを、新しいタスクで正しく引く手がかり。** 観測の見た目は効かなかった。言語の構成、ここまでの軌跡、物体と手先の関係などのうち、何が有望か。
4. **閉ループの結果の読み方。** ②③ が ① を上回り、④ が負けた場合、論文の主軸をどう組み直すべきか（スキル記憶を残す前提で）。
5. **BehaviorVLA と比べて、新規性を主張できる切り口。** 特に、新しいタスクでの評価と、ラベルなしの創発。
