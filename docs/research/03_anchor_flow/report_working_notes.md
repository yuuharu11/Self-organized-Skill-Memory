# 報告：スキル記憶つき VLA の進捗と、次の一手の相談（2026-10-31）

前回の相談資料は [reviews/consultation_skill_retrieval.md](reviews/consultation_skill_retrieval.md)、細かい経緯と全表は [logs/night_log_s2_closed_loop.md](logs/night_log_s2_closed_loop.md) にあります。この報告だけで読めるように書いています。

## 0. 要約

- **構想**：VLA（π0.5 系の SkillNet）の行動を、ラベルなしで作ったスキルの記憶から取り出した運動の型から生み、フローマッチングのデノイズで場面に合わせる。ノイズ量 t0 と反復回数は、取り出しの確信度で決める。
- **わかったこと（3 点）**
  1. 新しいタスクで、**観測から候補の型を選ぶ方法は、方策そのものに勝てない。** 方策 P3 の型は、どの選択器が選んだ型よりも正解に近い。候補の中に正しい型はある（候補集合のオラクル −.019）。
  2. **アクションヘッドを x0 一貫性の損失で短く微調整すると、誤差は大きく下がる。** ただし、これはスキルの効果ではない。主に微調整そのものと、ステップ数を減らした効果。
  3. ~~スキルの中身が効いているのはグリッパーの開閉の型だけ~~ → **§8 で撤回。** 1,500 行（切り替わる行 712）で再評価すると、スキルのグリッパーは方策より有意に悪かった。160 行での傾向は、小標本の偶然だった。
- **相談したいこと**：§5。

## 1. 構想と、譲れない条件

- **目的は汎化**（新しいタスク・新しい場面）。速さは目的にしない。
- **行動は常にスキルから生まれる。** スキルを補助扱いする案は不可。
- **スキル**：場面に依存しない運動の型。ラベルなしで創発させ、サブタスク名などの人手ラベルは使わない。取り出しは上位候補の softmax ブレンドで、個数は固定しない。
- **生成**：openpi の規約で t = 1 がノイズ。
  ```
  x_t0 = (1 − t0)·a_skill + t0·ε
  ヘッドで t0 → 0 まで、n ステップ積分する
  ```
  t0 = 1 は通常の方策と同じ。
- **最終目標**：LIBERO-Skill（skill_obj_02〜09、ゼロショット）で、SkillNet の成功率 44.5% を超える。論文値は π0.5 が 28.5%。
- **ベース**：公開されている SkillNet（π0.5、LIBERO-90 で学習）。

  - 差は、同じ行・同じ ε どうしで取り、95% 区間はエピソード単位のブートストラップで出す。
  - 負の値が改善。

## 4. 現時点の解釈

1. 新しいタスクでは、**連続的な腕の動き（方向・距離・回転）は方策のほうが上手い。** 記憶から足せる情報はほとんどない。
2. 記憶が方策を上回りうるのは、**グリッパーの開閉という離散的な型とタイミング**。これは、凍結ヘッドでも微調整ヘッドでも同じ傾向。
3. 候補の中に正しい型はある（オラクル −.019 〜 −.026）。しかし、観測から選ぶと方策に勝てない。足りないのは、選ぶための情報。
4. オフラインの MSE は、平均を取る予測（P3、少ないステップ）を有利に扱う。閉ループの成功率との対応は、まだ確かめていない。以前の閉ループ（凍結ヘッド、ゲートなし t0 = .4）では、成功率が 27 → 20 / 37 に下がった。

## 5. 相談したいこと

1. **「型（特にグリッパー）はスキル、連続量はフロー」という分担を、手法の中心に据えてよいか。** スキルが離散的な構造（いつ掴むか・離すか、どの型の手首の回し方か）を決め、フローが場面に合わせる。これは「行動は常にスキルから」という条件と両立する、と考えている。
2. **成分ごとにノイズ量を変える方法。** 例えば、グリッパーは t0 を小さく、腕は t0 を大きくする。ヘッドは時刻を 1 つしか取らないので、次元ごとの t0 を学習で入れる方法はあるか。今は事後に合成しているだけ。
3. **新しいタスクで型を選ぶ情報源。** 観測（VLM のトークン）では方策を超えられなかった。言語の構成（新しい指示を既知の動詞の組み合わせとして分解する）、方策の不確かさ（サンプル間のばらつき）、ここまでの軌跡の文脈（グリッパーの状態の履歴）などのうち、どれが有望か。
4. **オフラインの指標と閉ループの乖離。** gripper-big で有意になった場合、閉ループで C3（学習なし）と C1 を、公開 SkillNet と比べるのが次の一手と考えている。順序や設計（試行数、タスク）について意見がほしい。
5. **BehaviorVLA**（プロトタイプ記憶と、ガウス事前の flow matching、ラベルあり）との差別化は、「ラベルなしで創発した型」「確信度で t0 と反復回数を決める」「新しいタスクで評価する」で足りるか。

- 新しいタスクで、スキルの下書き（V）は、どの成分でも方策を上回らない。
