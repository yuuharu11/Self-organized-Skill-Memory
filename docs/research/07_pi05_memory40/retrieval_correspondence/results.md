# π0.5 memory40 retrieval correspondence：統合結果

## 結果要約

VLM由来の12キーと非VLM由来の11キーを、同じ全件Oracle・共通評価関数で再評価した。全3,277クエリのうち、分割に従ったEvalは1,318行（80 episode）である。主条件は同一タスク除外、同一episode除外を副条件とした。正解行動は正規化されたactive-7の実演chunkで、τ=.01。VLMキーの全件Top-64は各3,277クエリで生成済み。現行 grouped-MaxSim の同一episode除外Top-1行は既存 `retrieved_row.npy` と3,277/3,277一致し、スコアも完全一致した。生成時のGPU peak allocatedは約18.1 GiBで上限35 GiB内だった。

主条件のVLMキーでは wrist-only が最良（Top-1 action MSE 0.0989、hit 5.84%）。カメラだけの平均も近い（0.1116、5.54%）。現在の grouped token MaxSim は0.2355、3.64%で、centered-current は改善しなかった（0.2391）。diagonal whitening は0.1591まで改善したが、対応の多くを拾えていない。

非VLMでは π0.5予測行動から検索するキーが最良で、task除外でもMSE 0.0280、hit 24.36%。ただし、これはπ0.5自身の予測誤差0.0068より大きい。

## 解釈と限界

「π0.5予測→メモリ」の強さは、ほぼ正しい予測に最も近いメモリを当てているだけで、この評価行（公開 pi05_libero が学習で見た可能性のある既知タスク）ではメモリが予測に情報を足していない。キーとしての良し悪しと、メモリが役に立つかは別の問い。後者は方策の予測が外れる場面（未見タスク・方策の誤差が大きい行）に絞った評価が必要。

高π0.5誤差部分集合はDev由来しきい値で切った診断であり、未見タスクを直接表すものではない。特にq90は118行なので順位差は不確実。公開pi05_liberoがこのデータとタスクを既に見ていた可能性があり、未見タスク汎化の主張には使えない。
