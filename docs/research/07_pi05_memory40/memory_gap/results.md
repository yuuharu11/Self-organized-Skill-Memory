# π0.5 memory-gap：段階2 オフライン A〜E 比較

## 判定

事前基準どおり、難しい行で best-noise の G(D) が0.5以上なので **段階4-B（検索側）へ進む判定**。D の oracle 選択候補はメモリに存在し、同タスクを除外しても大きく崩れない。

ただし、同じ oracle 候補の生行動 D-raw は、D（12次元 base を復元）より難しい行の t0=.2 で MSE .012305 改善した（95% CI [−.015876, −.008922]）。従って検索だけでなく圧縮にも大きな損失がある。D-raw は診断用であり、実行可能な性能ではない。

## 固定設定・検証

- 全1,318 Eval行（40 task・80 episode）、間引きなし。Devは保存済み校正データの240行・120 episodeを使用。Devのepisode平均通常誤差 q80 は **0.015494**。Evalで閾値以上となった難しい行は141（69 episode）、その上位5%は8行。
- 条件 A〜E と、D/D-raw の同一 episode 除外および同一 task 除外を実行。開始ノイズ .6/.4/.2、seed 4101/4102、10積分、同一epsilonを全条件で共有。MSEはactive7の10×7平均。
- A(normal)および C(VLM) の各Eval行の平均MSEは draft-sensitivity-01 と最大差 **0.0**。best_bridge は `bridge/001500`。oracle_action_mse の候補選択は許可候補内最小値と1,318行すべてで一致。
- D-raw は選ばれた `rows['actions']` の `[10,32]` 全次元を同じ形式で入力。E は正解行動を codec.encode した base と query の predicted residual で復元。D/E は oracle 診断で、実行可能な手法の性能とは扱わない。

判定に使った D の best G は t0=.6 で episode除外 **1.148**、task除外 **1.154**（G>1 は当該条件の誤差が E をわずかに下回ったため）。t0=.2でもそれぞれ .835 / .775。いずれも事前基準 .5 以上。

## Bとの差・追加診断

エピソード単位 bootstrap 5,000回。難しい行 t0=.2 では D-episode−B = −.017616 [−.021672, −.013453]、D-task−B = −.016349 [−.020380, −.012320]。D-raw-episode−B = −.029921 [−.034528, −.025024]。

同一タスク除外の差（D-task−D-episode）は、全行 t0=.2 で +.000384 [+.000175, +.000602]、難しい行では +.001267 [−.000342, +.002982]。難しい行では区間が0をまたぎ、大きな候補喪失を確認できない。

C−Bは全行 t0=.6 で −.000124 [−.000382, +.000117]、t0=.4 で −.000015 [−.000430, +.000395] と区間が0をまたぐ。t0=.2 は +.007321 [+.004084, +.010844] でCが悪い。難しい行でもt0=.6/.4は区間が0をまたぎ、t0=.2は +.032488 [+.021851, +.043832]。

これはオフライン行動誤差の診断であり、「統計的な差がない」ことを「同等」とは解釈しない。シミュレーションでの閉ループ評価は本段階では実施していない。
