# Local-key 検索の訂正版評価

## 初回のバグと訂正

初回 local-key-01 の Top-1 / Top-5 / Recall / Spearman は無効。`_retrieve` でTop-K内の位置 `ix` をデータセット行IDとして `actions[ix]` に渡していたため、別の行動を比較していた。訂正版は `actions[mids[ix]]` に直し、プール位置と行IDが異なる回帰テストを追加した。保存済みlocal-key-01のTop-1候補行IDと訂正版の候補順位は G / W / wrist_lowerhalf / invariant_projected_local の4条件ですべて一致し、正しいTop-1 MSEはそれぞれ 0.244 / 0.219 / 0.185 / 0.121。初回レポートのL1/L2判定は撤回し、本結果で置き換える。

local-key-02 の初回集計にも指標バグがあった。Top-64候補全体から正例を数えていたため、`Recall@8` が実際には Recall@64 になっていた。上位8件だけを分子に数えるよう修正し、保存済み候補行IDと正解行動から全候補の指標を再計算した。以下のRecall値は再計算後の値である。

## 条件・選択

メモリはLong以外30タスク・3,857区間（raw正規化行動）、評価はLong Eval 548行 / hard 63行。π0.5本体はLong学習済みだが、Longはキー学習・射影・Dev選択に使っていない。Hard閾値は固定Dev q80 = 0.01549410422449。Devの領域・状態/履歴ブロック重み・直接回帰入力は同一タスク除外で選択し、Evalと揃えた。

ブロックキーはLong以外の非memory訓練行で各ブロックを標準化し、個別L2正規化後に重み付き（平方根係数）連結して再度L2正規化した。重み候補は visual:state:history = visualのみ、(0.75,0.25,0)/(0.50,0.50,0)/(0.25,0.75,0)、(0.75,0,0.25)/(0.50,0,0.50)/(0.25,0,0.75)、(0.60,0.20,0.20)/(0.40,0.30,0.30)/(0.20,0.40,0.40)。Devで選ばれた局所キーは `wrist_lowerhalf+prev`、重みは visual=.75 / state=0 / history=.25。直接回帰も同じキー入力を使った。

## 基準・判定

| 条件 | 全Long MSE | hard MSE |

L1 (局所キー−G、選択条件 `wrist_lowerhalf+prev`): 全Long -0.125 [-0.157, -0.093]、hard -0.111 [-0.152, -0.070]。episode bootstrap 5,000回の95%区間上端はいずれも0未満で **L1合格**。

L2 (局所キー−同一入力の直接回帰): 全Long 0.095 [0.078, 0.112]、hard 0.149 [0.118, 0.180]。差は正で、直接回帰の誤差が低く **L2不合格**。したがって局所検索は全体キーより改善したが、今回の判定基準では同じ観測情報からの直接回帰を上回らず、「検索が未知タスクに効く」核心的根拠には至らない。差なし・同等とは解釈しない。
