# π0.5 LIBERO-40：運動メモリと修正Expertの学習

## 今回の比較

通常・フォールバックは公式 `pi05_libero`。元の重みを変更せず、独立した修正用Action Expertを追加学習する。公開SkillNetとBehaviorVLAの数値は他論文の参考値として扱い、同一条件の再現結果とは呼ばない。主たる効果の判定は、同じπ0.5の通常生成と提案方式を同じ評価初期状態で比較して行う。

公開参考値：π0.5のLong 92.4%、SkillNet LIBERO-40のLong 98.4%。98.4%超えは検証する目標であり、学習だけで達成したとは扱わない。LIBERO-40＝Spatial/Object/Goal/Long各10タスク。今回のモデルは対象タスク学習済みであり、未知タスクへの転移実験ではない。

## 重みとデータ

- `data/VLA/pi05/openpi/vla_base_source.json` にある既存重みは `gs://openpi-assets/checkpoints/pi05_base`。LIBERO適応済みではない。
- 通常・フォールバック用には公式 `gs://openpi-assets/checkpoints/pi05_libero` を取得した。保存先は `.skillnet-state/checkpoints/openpi-assets/checkpoints/pi05_libero/`。
- 使用する実演は `.skillnet-state/data/lerobot/emergent/libero_40_unsegmented/` の40タスク・1,693実演。skill注釈は読まない。
- 追加の圧縮器・修正Expert学習からは各タスク5実演を保留する。公開π0.5本体はそれらを既に学習した可能性があるため、基盤モデルまで未見の検証集合とはしない。
- メモリは各タスクの学習側10実演から構築する。10ステップの完全な行動区間をstride 10で抽出し、26,581区間を前処理する。fpsは元データの10を記録し、20 Hzと仮定しない。

## 実装する方式

1. VLMは固定。最終層の画像2カメラ・指示の有効トークンを個別に保存する。パディング・不在カメラ・特殊テキストトークンは検索から除く。
2. コサイン類似度によるMaxSimを同じカメラ・指示の種類内で計算し、種類内平均・種類間等重み平均で候補を順位付けする。キーの場面間平均やグループ代表への置換はしない。
3. 運動圧縮器は既存M1（b=12、r=4、MLP幅128）を学習する。bをメモリに保存し、現在の入力から予測したrと現在の状態で行動列へ戻す。VLMの平均特徴はr予測の補助入力にのみ使用し、トークン検索キーを置き換えない。
4. Top-1の運動を使う。学習・検証クエリと同じ実演は検索対象から除外する。取得候補を混ぜず、検索・復元と修正の誤差を切り分ける。
5. 通常Expertをコピーした修正Expertを追加学習する。VLMだけ共有・固定し、修正Expertのアテンション、FFN、時刻MLP、入出力射影は更新する。
6. (B=(1-t_0)a_m+t_0\epsilon\)、(X_u=(1-u)a^*+uB\)、時刻 (t=t_0u\)、教師速度 ((B-a^*)/t_0\)。(t_0\) は0.2〜0.6、(u\) は0.01〜1から標本化する。通常の教師速度 `epsilon-action` を異なる下書きの経路へそのまま流用しない。
7. 損失は正規化行動列の有効7次元に対する速度MSE。保存する学習損失と、最終行動列MSE・閉ループ成功率は区別する。

## 後から変えられるもの

- フォールバック閾値・ノイズ割当ては学習後の検証実演で決める。現時点では未校正。
- 学習した0.2〜0.6の範囲内で開始ノイズ量を変更できる。範囲外への変更は別途検証・追加学習が必要。
- 検索方式・保存表現・候補数を変えると下書きの分布も変わるため、既存の修正Expertがそのまま適用できるとは仮定しない。
- 信頼度は正解確率と同一視しない。校正前の実験を「信頼度適応済みの提案」として報告しない。

## 実行と成果物

実行先：`.skillnet-state/outputs/memory-pilot/pi05-memory40-20261104/run-01/`。

`run.py pipeline` は前処理→VLMトークン抽出→圧縮器学習→実演間検索→修正Expert学習を順に実行する。各段階を別プロセスにしてGPUメモリを解放する。進捗は `status.json` と各段階の `.log`。完了マーカーのある段階は再実行時に省略する。

初回修正学習はbatch 8、AdamW学習率2.5e-5、最大4,000更新または4時間。500更新ごとに修正側の重みだけ保存する。元の通常Expertは上書きしない。学習不足の可能性を残し、損失の低下だけで収束と呼ばない。

初期実装はメモリ構築と学習までだったが、以下の追記で校正・閉ループ評価まで接続した。基礎検証には経路の端点・教師速度・モダリティ別トークン検索・同一実演除外を含む。

## 自動継続と評価（追記）

GPUサーバの独立tmuxセッション `pi05-memory40` が現在の処理を監視する。接続切断時の自動復旧は実際に動作した。トークン抽出はフラッシュ済み区間から再開できる。通常の学習失敗は成功扱いせず、失敗段階を記録する。

後続は `run.py` による学習・校正、`finish.py` による閉ループ評価まで接続済み。修正Expertの保存重みは、各500更新時の固定40区間の保留速度損失で選ぶ。この重み選択と信頼度校正にはDev実演のみを使い、別のEval実演を残す。校正では通常π0.5と各開始時刻で同じ初期ノイズを使い、修正側の重みを読み込んでもフォールバック出力が変わらないことを検証する。

評価はまず4suite×各10タスク×5初期状態×通常/提案の2条件。残り時間でLongのみ50初期状態/タスクまで拡張する。固定順序で回し、途中の成功率に応じてタスクを選ばない。24時間の予算上限を設け、予算内の完了組と未完了を分ける。50初期状態をすべて完了できるとは未確認。公開98.4%はLongの参考値であり、4suite平均の目標値とはしない。

`evaluation_protocol.json`、`rollouts.jsonl`、`closedloop_summary.json`、`report.md` にプロトコル・全試行・集計・人間向けの結果を保存する。元の状態での環境/通信エラーのみ同一条件で1回再試行し、元エラーも保持する。完了した失敗は再試行しない。繰り返す実行基盤エラーは明示して停止し、不足分を成功率の分母から隠さない。

実環境経路の確認としてLong task 0 / init 0を通常π0.5で実行し、277環境ステップ・56問い合わせで成功、約38秒で正常完了。これは動作確認の1試行であり、主評価の成功率とはしない。`baseline_rollout_smoke.json` に保存。修正側の2回の勾配試験も通過し、サンプルしたVLM重みの不変と修正出力層の更新を確認済み。純粋関数の検証は9テスト通過。検索GPU実装は小規模なNumPy参照計算と候補順位・スコアが一致した。

## 定期監視と圧縮器の診断

独立したtmuxウィンドウ `health` が毎分、進捗・最終ログ・損失の非有限値・GPU使用量・15分以上の進捗停止を監視し、`health.json` と `health.jsonl` に記録する。監視プロセスは評価結果から設定を変更せず、他ジョブを停止しない。実装上の変更と実験設定の変更を区別する。

圧縮器の学習は28 epochで完了した。保留全区間の再構成MSEは0.004237、予測rに置換した場合も0.004237。保留410区間の疎な追加診断では、元b＋元r 0.004329、元b＋r=0 0.004328、b=0＋予測r 0.250968だった。bは行動再構成に使われているが、rの寄与はほぼなく、状況への適応がbとrに分離されたという根拠にはしない。運動表現を途中で差し替えず、今回の学習・閉ループ比較は継続する。診断は `codec_latent_diagnostic.json` に保存。
