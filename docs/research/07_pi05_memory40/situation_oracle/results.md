# Situation oracle: results

LIBERO-40 の no-op 除去済み RLDS 行を元HDF5へ行動列で対応づけ、MuJoCo状態から特徴を復元した。評価は CPU のみ（GPU利用なし）、学習・方策 rollout なし。対応した 510 エピソード、8,279 行すべてで、10-step active7 の生指令列が HDF5 と一致（raw tolerance 1e-6）、同じ量子点正規化後のキャッシュ値とも一致（1e-5）。各状態を該当タスクの `ControlEnv` に復元してから測定した。

Long query は 548 行、hard subset は 63 行（固定閾値 0.01549410422449）。主メモリは Long を含まない `raw-rows-noLong` 3,857 行。参照は Long のメモリ行 2,726 件から、同じタスク・別エピソードだけを毎回許可した。クエリ行とクエリエピソードはどちらの候補にも含めていない。ブロックの標準化統計は主メモリだけから計算し、重みは非Long Dev 1,148 行（task 10–39）で選択した。Long の行動・特徴は重み選択に使っていない。

## 事前判定と所見

- **S1: 不通過。** 主メモリのDev選択キーHは、wrist_lowerhalf+prevよりLong/hardとも誤差が大きく、paired CIも改善側にない。
- **S2: 不通過。** 主メモリHはhold-lastをLong/hardのどちらでも上回らない。hardのCIも改善を確定しない。同タスク参照でもLongではhold-lastより悪い。
- 成分の寄与はHが支配的。E/R単独は行動をほぼ特定せず、G単独はグリッパー符号一致 .872 と高い一方、行動MSEは .482。R+G+H / E+R+G+H はH単独を改善しなかった。
- 選択Hキーの近傍候補間の行動 pairwise MSE は k=8 で .204 [.190,.217]、k=32 で .247 [.228,.264]（hard .286 / .314）。この有限メモリ近傍で運動が割れており、状態の近さだけでは次の行動が一意に決まらない。これは条件付きばらつきの経験的指標で、理論的な下限そのものではない。
- メモリ全体の行動オラクルは .029/.035 と低い一方、検索結果は大幅に悪い。候補内に近い行動があることと、シミュレータ状況キーで選べることは別問題である。
