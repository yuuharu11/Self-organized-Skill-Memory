# 段階3：失敗状態からの分岐検証の事前設定

日付：2026-11-04。状態：拡張版44/44条件の確認完了。本番開始前に以下を固定。

## 問いと対象

シミュレーションでの閉ループ評価により、通常π0.5が失敗する状態から、現在のメモリの候補で成功まで進めるかを調べる。Longは学習40タスクに含まれる既知タスク。未知タスクへの汎化を検証する実験ではない。

段階2は事前基準で「検索が障害」の判定だったが、圧縮にも大きな損失がある。D-rawは評価と同じ行動距離で選んだ診断上限であり、実行時に選べる性能ではない。本段階の候補集合は実行時に使える情報だけで作る。成功した候補を事後に特定する集計も、候補を実行時に正しく選べた性能とは区別する。

## 分岐元と条件

paired-breakdown-01の通常π0.5の失敗試行から最大10件。タスク6・8を優先し、公開初期状態0–49から選ぶ。選択リスト・seed・初期状態ハッシュは本番前に固定し、分岐結果で選び直さない。各試行の20/40/60%の3点を保存し、元の続きと同じ乱数の行動列が一致することを確認する。確認済み実装の復元方式は、初期状態から保存行動を再生し、シミュレータ状態と観測の一致をassertする方式。flatten状態だけの復元は使わない。

|---|---:|
| 通常π0.5、別乱数8回 | 8 |
| ゼロ下書き、t0=0.6 / 0.2 | 2 |
| 現行VLM検索、t0=0.6 / 0.2（固定） | 2 |
| 8候補 × 圧縮bの復元/生の行動列 × t0=0.4/0.2 | 32 |

最大30分岐点・1,320本の続き実行（分岐元の再生・一致確認は別枠）。旧READMEの780本は今回の行列ではない。

8候補は、現行VLM・手首カメラのみ・codec prior b̂・π0.5予測行動の4キーから上位2個ずつ。重複は次点で埋め、各候補の出どころのキーと順位を保存する。検索は、VLM全モダリティのgrouped MaxSim、手首group1だけのMaxSim、メモリ統計で標準化したprior b̂ cosine、通常π0.5の予測行動と記録行動の正規化active7 MSEの負値。同点は行ID昇順。キー順はVLM→手首→prior b̂→予測行動で、各キーが新規の2行を採用するまで重複を飛ばす。採用元と全4キーでの順位・スコアを保存する。未実装の経路を別の検索方法で代用しない。

## 事前の主集計

各分岐点で、通常π0.5の別乱数8回がすべて通常の失敗であり、かつ32本のメモリ候補分岐のどれかが成功したかを判定する。その分岐点数と、完全に判定可能な分岐点に対する割合を報告する。予定分岐点数・完了数・未判定数も必ず併記し、技術エラーを通常失敗として「通常8回全失敗」の根拠にしない。

候補の形式（圧縮/生）、t0、候補のキーと順位別に内訳を示す。同一分岐点が複数の内訳に入る場合は重複を明記する。ゼロ下書きでも救える点を別に示し、候補成功だけからメモリ固有の効果と断定しない。追加の通過閾値は設けず、上記の記述的割合を使う。

通常失敗リストからタスク6・8を交互に選んだ10試行を固定した。task6の初期状態は0,20,23,30,33、task8は0,2,4,8,12。環境seed=7+初期状態、問い合わせseed=(7+初期状態)×100000+問い合わせ番号。別乱数の通常π0.5は1009×1…8を問い合わせseedへ加算。全条件で積分10回、replan5、待機10、制御上限520、分岐点は105/210/310制御ステップ。
