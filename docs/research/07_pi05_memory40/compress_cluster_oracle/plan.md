# 圧縮・クラスタリング上限の事前計画

## 問い

検索を評価せず、各場面の正解行動を含む行プールから正解を見て代表候補を選ぶ。圧縮とメドイド化が失う情報、およびその下書きを修正 Expert がデノイズした後に残る差を記述する。これは正解選択を許す上限診断であり、検索性能や未学習タスクへの汎化を評価しない。

## 固定データと表現

入力は `pi05-memory40-20261104/run-01` の行ID付きデータ。行プールは fair-expert 学習行、`raw-rows-all40` のメモリ行、保留6タスクDev行、Long Eval 548行の和集合とする。各Long/Dev行の行動IDがプールに含まれることを検査する。Long Evalはクラスタ形成に含めるが、距離尺度の較正・κ選択・Expert学習・ノイズ選択には使わない。

表現は raw active7 の10×7行動と、既存の `b12m`/`b24`/`b48`/`b96` codec の潜在ベース。codec重みは読み取り専用で、新規fitしない。M6の `CodecFunctional` 64行probe距離を使い、probeは非Long行に限定する。クラスタ代表は実在行のメドイド。

## 方式と選択

各表現で none / fine / mid / coarse / m6default を比較する。fine/mid/coarseは非Long行だけでM6距離のランダム組中央値を求め、κ候補から登録数が概ね3000/300/30に近い値を選び、そのεを固定してLongを含む全プールをM6に流す。登録数は閾値の帰結として報告する。m6defaultはκ=.1、support=10、episode=3。未割当クエリは最寄り単位へ割り当て、元の未割当率も記録する。

保存量は、メドイド表現の実値、メドイド行ID、プール行ID、行から単位へのID対応を別々に数える。fit時に保持する全プール表現値は、メモリ本体の保存量と分ける。

各クエリの主候補は全代表をクエリ条件で復元した後、正解active7行動MSEが最小の1本。副候補は自分が属する単位のメドイド。正解行動を使う選択は診断上限に限る。Top-32事前絞り込みを使う場合は全件探索との一致を抜き取り確認する。

## Expertと評価

Expert学習は fair-expert の既存レシピを固定して再利用する。初期値は公開通常Expert、共通の訓練行・mini-batch列・seed 20261104・batch 8・AdamW・4000更新・500更新ごとの保存を揃え、下書きだけ各方式の主候補に置換する。Longを学習・checkpoint選択に使わない。保留6タスクDevの生成MSEでt0=.2/.4/.6とcheckpointを選ぶ。

Long全548行とhard 63行で、同じnoise seed 4101をrow IDでfold-inし10積分する。各方式のprimary/secondary、primaryの別タスクshuffle、zeroを評価する。episode単位5000回bootstrapで、圧縮・クラスタリング・両者の各損失、およびshuffle/E-zero/通常との差を出す。差のCIが0をまたぐ場合は同等とせず、検出された優劣なしと記述する。

## 解釈上の限界

正解行動を見た候補選択、評価行自身を含むプール、既知タスク、Longを含む事前学習済みcodec、単一seed、オフライン生成である。結果を実行可能な検索性能や閉ループ性能として主張しない。
