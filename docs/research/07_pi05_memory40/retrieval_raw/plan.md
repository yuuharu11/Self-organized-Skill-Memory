# 段階4-B：生行動候補の検索

## 問い

π0.5 の通常予測が難しい行で、保存済みメモリにある「生の実演行動が近い候補」を、推論時に利用可能な観測だけから検索できるかを調べる。段階2では正解行動距離で選んだ候補の生行動が有効だったが、それはオラクル上限であり、検索可能性は未確認だった。

## 固定データと分割

- 読み取り専用入力：`pi05-memory40-20261104/run-01/` と `score-audit-01/`。
- query は既存の validation 3,277 行。split は `run.calibration_episodes` 由来の `query_meta.npz` をそのまま使い、Dev/Eval を混ぜない。
- メモリは既存の 6,583 行。正解距離は `oracle_action_mse.npy`（正規化 active-7、10×7 の生行動 MSE）を再利用する。
- 主条件は同一 task を候補から除外、副条件は同一 episode のみ除外。
- 閾値 τ は .005/.01/.02。検索キーや学習キーに未来の行動を入れない。
- learned key の特徴標準化・対照学習は `memory=False, validation=False` の行のみ。正例は行動 MSE が閾値以下かつ別 task のペア。3閾値の選択は Dev episode の task-excluded Top-1 生行動 MSEだけで行う。Eval は最後まで選択に使わない。
- 「難しい行」は既存 `memory_gap` と同じく、校正データで決めた通常π0.5のエピソード平均誤差 q80 を Eval に適用する。

## 比較するキー

1. VLM：score-audit の保存済み Top-64 を再利用する。現行 grouped MaxSim、centered current、wrist-only、camera-only、pooled、top-token 集約などを含める。
2. 手首＋状態：手首画像トークンの平均特徴と `state[:8]`。メモリ外 train 行の平均・標準偏差で標準化した後の cosine と負の標準化二乗距離。
3. 手首＋状態＋短い履歴：現在の上記特徴に、同一 episode の直前 stride の手首特徴・状態・実行済み行動チャンク（10×7）と履歴有無 flag を追加。同じ2つの固定距離と、別 task の行動近傍ペアで学習する対照キーを比較する。実運用では履歴行動は実際に実行した指令で置き換える必要がある。
4. 参考キー：π0.5予測行動→メモリ実演行動、codec prior の b̂。前者は方策予測依存、後者はVLM/状態依存であり、通常の画像・状態キーと区別して報告する。

## 指標と保存物

- τごとの oracle 存在率、Top-1 hit、Recall@1/@8/@64（oracle候補がある query を分母）。
- Eval query ごとに選択したメモリの生行動を下書きにし、`memory_gap/run.py` と同じ修正 Expert、固定noise、積分回数で t0=.2/.4 の最終MSEを評価。全Eval行と難しい行を報告し、ゼロ下書きより最終誤差が小さい割合も出す。
- 各方式の Top-8 query/candidate row ID、score、候補の実行行動チャンクを NPZ 保存し、段階3から利用できるようにする。
- 学習・Evalの選択履歴と、最終予測を新規出力ディレクトリに保存する。既存キャッシュは変更しない。

## 判定・限界

主に τ=.01、task exclusion、Eval の Recall@8 と生行動下書きの最終MSEを読む。学習キーが固定キーより良いかは同じ分割・候補・評価器で比較する。全手法で候補 recall が低ければ、再ランキングでは埋められない候補生成の制約として扱う。行動距離は実演の正解を使う評価ラベルであり、キー入力には使わない。結果の主張は本キャッシュ内の Eval query と保存メモリに限り、シミュレーションでの閉ループ成功率への改善とは解釈しない。
