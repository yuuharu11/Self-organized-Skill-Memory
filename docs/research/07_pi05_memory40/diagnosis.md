# π0.5＋運動メモリ：うまくいかない原因の診断

この文書は、07の実験全体から「何が原因でメモリが成功率を上げないのか」をまとめたもの。個々の数値と設定は各 results.md にあり、ここではそれらをつないだ結論と根拠だけを書く。

## 一言でいうと

- **メモリの中には、π0.5が誤る場面を救える動きが入っている。**
- **それを実行時に選べていない。** 原因の中心は検索で、見た目（VLM特徴）を手がかりに探しているため、動きの近さを捉えられない。
- 圧縮（12次元のb）による損失は二番目の原因。開始ノイズの量は原因ではなく、検索の悪さを埋め合わせるために上げざるを得なかった結果。
- これまで見えていた改善の大半は、**下書きの中身ではなく、修正Expertの追加学習の効果**だった。

すべて学習済みタスク（`pi05_libero` は Long を含む40タスクで学習済み）での結果であり、未学習タスクでの検証（OOD）はまだしていない。

## 構成のおさらい

```
現在の観測 ──VLM特徴──> メモリ6,583区間（10ステップの行動）からTop-1を検索
                          │
                          ▼
              保存されたスキル b（12次元）＋ 予測した r̂ → 10ステップの下書き
                          │
                          ▼
   下書きにノイズを混ぜた点（開始ノイズ t0）から、修正Expertでデノイズ → 行動
```

障害がありうる場所は、①何を保存するか（表現）、②どう選ぶか（検索）、③下書きをどう使うか（ノイズ量・修正Expert）の3つ。これを安い順に切り分けた。

## 根拠

### 1. 救える動きはメモリにある

難しい行（Devで決めた「通常π0.5の誤差の上位20%」の閾値以上のEval行、141行）での、生成後の行動誤差（正規化した7次元のMSE）。出典：[memory_gap/results.md](memory_gap/results.md)

| 下書き | t0=.6 | t0=.4 | t0=.2 |
|---|---:|---:|---:|
| 通常π0.5（下書きなし） | .0513 | .0513 | .0513 |
| ゼロの下書き | .0277 | .0289 | .0345 |
| 現行VLM検索 | .0270 | .0293 | .0670 |
| メモリ内の最良候補（12次元bで復元） | .0246 | .0212 | .0169 |
| 同じ候補の生の行動列（圧縮なし） | .0206 | .0126 | **.0046** |

同じタスクを候補から除外しても、最良候補の誤差はほとんど変わらない（t0=.2で .0169→.0182、生の行動列は .0046→.0051）。事前に決めた判定基準（G≥0.5）により、障害は検索側と判定した。

注意：「最良候補」は正解の行動に最も近いものを後から選んだ上限値で、実行可能な性能ではない。

### 2. 検索が選べていない（一番の原因）

Eval 1,318行、同じタスクを候補から除外した場合。Spearmanは、クエリ内での「検索スコア」と「行動の誤差」の順位相関の平均（マイナスが大きいほど、スコア上位ほど動きが近い）。出典：[retrieval_correspondence/results.md](retrieval_correspondence/results.md)、`score-audit-01/report_nonvlm.md`、[retrieval_raw/results.md](retrieval_raw/results.md)

| 検索の手がかり | Spearman | 1位が正しい動き（τ=.01） | 難しい行・t0=.2の生成後誤差 |
|---|---:|---:|---:|
| 現行VLM（正面＋手首カメラ＋指示文、MaxSim） | −0.16 | 3.6% | .081 |
| 手首カメラ＋状態の学習キー | −0.23 | 5.5% | .066 |
| 写像b̂（場面からbを予測し、bの近さで探す） | −0.41 | 11.2% | .056 |
| （参考）π0.5の予測行動とメモリの行動を比較 | −0.85 | 24.4% | .033 |
| （比較）ゼロの下書き | — | — | .035 |

- VLM特徴の類似度は、動きの近さとほとんど対応しない。集約や重み付けを変えた版（平均、IDF、白色化、上位トークン）も改善しなかった。
- 動きの空間で比べる（b̂、行動）と、急に選べるようになる。ただし、実行時に使える手がかりのうち最良の b̂ でも、選んだ下書きはゼロの下書きより悪い。
- π0.5の予測を手がかりにする方法は最もよく当たるが、メモリが方策の予測に寄せるだけになる。π0.5が誤る場面や未学習タスクでは手がかり自体が外れるため、研究の主張には使わず、参考値として扱う。

### 3. 圧縮による損失は二番目の原因

同じ最良候補を、表現だけ変えて比べた（難しい行、t0=.2、同一エピソード除外）。出典：[representation/results.md](representation/results.md)

| 保存の仕方 | 1区間の保存値 | 生成後誤差 |
|---|---:|---:|
| 生の行動列 | 70 | .0046 |
| 状態から推定できる成分を引いた差分 | 70 | .0071 |
| 現行 b12 | 12 | .0169 |
| b24 / b48 | 24 / 48 | .0197 / .0242 |
| 手先相対座標の b12 | 12 | .0181 |

bの次元を増やしても改善しなかった。ただし修正Expertは現行b12の下書きで学習しているため、その入力分布の差も混ざっている。また、正しい候補を選べない限り、この損失は表に出ない。

### 4. 開始ノイズは原因ではなく結果

- t0=.6では下書きの中身がほぼ消える。通常π0.5からの改善のうち約85%は、ゼロの下書きでも得られる。出典：[draft_sensitivity/results.md](draft_sensitivity/results.md)
- t0=.2では外れた下書きにそのまま従ってしまい、現行検索は通常π0.5より悪くなる（難しい行で .067）。
- 良い下書きを選べない限り、どのノイズ量でも勝てない構造になっている。

### 5. 修正Expertは「下書きを信用しない」ように学習されている

修正Expertは、現行VLM検索のTop-1を復元した下書き（`drafts.npy`、正解との誤差の平均 .092）で学習した。ほとんど当たらない下書きから正解に直すことを学んだため、下書きを当てにせず、画像と状態から作り直すように育った可能性が高い。上の「ゼロの下書きで85%」や、正しい下書きでの伸びの小ささと整合する。良い下書きを活かす訓練はまだしていない。

### 6. 閉ループでも、メモリの中身による改善は見えない

- LIBERO-Long、初期状態0〜9の各100試行：通常95、メモリ（t0=.6固定）93、b̂を直接下書きに91、b̂で検索93、信頼度でノイズを変える91、それに通常への切り替えを足すと94。いずれも通常π0.5との差の95%区間は0を含む。出典：[paired_breakdown/results.md](paired_breakdown/results.md)
- 初期状態0〜49の500試行でも、通常459、メモリ459（救済29・悪化29）。
- 失敗した場面から途中で分岐させる実験（[rescue_branching/results.md](rescue_branching/results.md)、実行中）では、途中経過（10試行中2試行）で次のことが見えている。
  - π0.5を乱数だけ変えても成功することが多い。
  - 救えた場面ではゼロの下書きも成功している。
  - t0=.2で1つの候補を使い続けるとほぼ全滅する。
  - 「π0.5では救えず、メモリの動きなら救える」という分岐点はまだない。最終結果はこのファイルに追記する。

## 原因ではないと分かったこと

| 疑い | 判断 | 根拠 |
|---|---|---|
| メモリに良い動きが入っていない | 否定 | 最良候補で難しい行の誤差が約10分の1 |
| 同じタスク内にしか良い候補がない | 否定（既知タスクでは） | 同じタスクを除外しても最良候補の誤差はほぼ同じ |
| bの次元が足りない | 否定 | b24/b48で改善しない |
| ノイズ量の選び方が悪い | 主因ではない | 検索の質が悪い限り、どの量でも勝てない |
| VLM特徴の集約方法が悪い | 否定 | 平均・IDF・白色化・上位トークンで改善しない |

## まだ分かっていないこと

- **未学習タスクでの振る舞い。** 写像b̂、学習キー、修正Expertは、評価に使ったタスクも学習している。b̂の当たり率などは楽観的な値。
- **10ステップ単位の保存そのものの是非。** 短い断片は、どのタスクにも似た動きがあって区別しにくく、検索の失敗の一因と考えられる（仮説）。以前の実験（[03_anchor_flow/proposal_rerank69.md](../03_anchor_flow/proposal_rerank69.md)）では、正しい動きを含むまとまりには上位20件で90〜98%到達できたが、まとまりの中の正しい位置を当てられたのは2〜14%だった。
- **良い下書きで学習し直した修正Expertが、どこまで下書きを活かせるか。**

## 次の方向

1. **検索を動きの空間で行う。** π0.5の予測に頼らずに、観測から動きの空間へ写す写像（b̂の改良）を本筋にする。
2. **まとまり単位の保存を検討する。** 意味のある運動のまとまりで保存し、まとまりを選ぶ検索と、まとまりの中の進み具合の推定を分けて評価する。
3. **未学習タスクで確かめる。** 圧縮器・写像・検索キーをLIBERO-90だけで学習し、Longで当たり率と生成後の誤差を測る。閉ループの本検証は [08_heldout_memory_addition](../08_heldout_memory_addition/README.md)。
4. 修正Expertの学習し直しとノイズ量の調整は、検索が改善してから行う。
