# スキルの作り方の比較（軽量版）

2026-10-26 開始。軽量版 go/no-go（[emergent_skill_verification.md](emergent_skill_verification.md) §4.1）の特徴キャッシュの上で、スキル表現の作り方を比べる。
ユーザーの要望：スキルの基本部分と残差を独立させる。無駄のない（冗長でない）スキルを作る。追加できる。スキルどうしが完全に別物である必要はない（部分的に共有してよい）。ARTなどの先行研究を参考にしてよい。

> 訂正（2026-10-26）：特徴抽出が goal と spatial の suite 名を逆にしていた（データセットでは task 10–19 が goal、30–39 が spatial）。
> この文書の「学習は object/goal、新しい suite は spatial」は、実際には「学習 = object＋spatial、新しい suite = goal」だった。
> 以後は2つの分割で測る。Split A：学習 = object＋spatial、新しい suite = goal（既知の運動6タスクと新しい運動4タスクが混ざる）。Split B：学習 = object＋goal、新しい suite = spatial（新しい場面×既知の運動）。
> パイロットで「spatial では新しいスキル単位を足さなかった」とした結果は、実際には「引き出し・コンロ・押す動作を含む goal で単位を足さなかった」であり、新しい運動を検出できていないことを示す。

## 背景

軽量版では、学習していない suite（spatial）に対して、object/goal のメモリの中に使える値はある（未来の運動で引くと 0.162）が、
観測からのキーでは引けなかった（最良でも 0.197、今のキー 0.227、ランダム 0.230）。
z 全体に場面ごとの細かい情報が混ざっていると考え、z を「どんな運動か（base）」と「この場面での調整（residual）」に分ける。
base だけをメモリで引き、residual は観測から決める。運動制御のスキーマ理論（一般化運動プログラム＋パラメータ）や DMP の形と目標の分け方に対応する。

## 共通の条件

- 特徴キャッシュ：`/work/.skillnet-state/outputs/memory-pilot/emergent-light-20261026T050453Z-0cb536/feature-cache`（言語なしのカメラ別特徴は `emergent-light-keys-20261026T074213Z-9e39c3/camera_features`）。再抽出しない。
- 学習：object/goal の20タスクだけ。spatial は学習・正規化・PCA・プロトタイプの初期化に使わない。H=25 を本命、H=10 を比較。乱数シード3つ。
- 追加：spatial の store 分を流し、パラメータを勾配で更新せずに追加する（プロトタイプの移動平均の更新など、勾配でない更新は方式ごとに明記する）。
- 評価：spatial の query 分。評価用の運動の特徴（環境の手先の軌道）は学習・追加の判断に使わない。

## 方式のインターフェース

各方式は `skill_moe/skillnet/examples/emergent/light/methods/<name>.py` に置き、次を実装する。

```
fit(train)                      -> None        # object/goal で学習
encode(A, s)                    -> (b, r)      # base（離散ならコード番号と埋め込み）、residual
decode(b, r, f, s)              -> Â           # 行動チャンク
prior(f, s)                     -> (b_dist, r) # 観測から base の分布と residual を予測
memory_add(k, b, meta)          -> 追加したか、理由   # 勾配なし
memory_query(k)                 -> 上位の base と重み
describe()                      -> 方式・容量・更新規則の説明
```

追加の圧力（最良の方式に重ねて比べる）:

- S：入れ替え再構成。近い base どうしを入れ替えても再構成できるように学習する（共有の圧力）。
- C：手先基準の正規化。行動チャンクから開始位置・向き・大きさを外して base を作り、外したものは residual が担当する（幾何で決まる不変性）。

## 評価指標

| 観点 | 指標 |
| --- | --- |
| suite をまたいだ再利用（主） | object/goal だけのメモリから base をキーで引き、residual は Prior で予測したときの spatial の再構成誤差（基準：今のキー 0.197〜0.227、上限 0.162、ランダム 0.230） |
| 追加の効果 | spatial を追加した後の誤差、追加率、追加後の object/goal の誤差（忘れていないか） |
| 創発 | base と運動の特徴の相互情報量（シャッフル補正）、I(タスク; base \| 運動) |
| 無駄のなさ | 使われている単位の数とパープレキシティ。冗長性（同じ residual で復号したときに行動がほぼ同じになる単位の組の割合）。レート・歪み（1窓あたりのビット数 vs 再構成誤差） |
| 独立性 | base と residual の HSIC。residual だけを変えたときに運動の型（base の最近傍）が変わらない割合 |

方式ごとに、学習・追加・評価の設定と、勾配でない更新の有無を報告する。結果は誇張しない。

## ユーザーの4つの要件と判定（2026-10-26）

| 要件 | 指標 | 目標の状態 |
| --- | --- | --- |
| R1 継続的に追加できる | suite を順番に流す（object→goal→spatial→LIBERO-10、順序を3通り）。各段階の後に、これまでの全 suite の再構成誤差と単位数 | 段階を経ても以前の suite の誤差が悪化しない。単位数はデータ量に対して頭打ちに向かう |
| R2 スキルを区別できる | 同じ residual で復号したときの単位間の行動の距離（機能的な区別）。冗長な単位の割合（単位を除いても誤差がほぼ変わらない）。運動の特徴から単位を当てる精度 | 冗長な単位が少なく、単位ごとに運動が区別できる |
| R3 入力を表現できる | 自分の区間の再構成誤差（既知の suite と新しい suite）。どの単位からも遠い区間の割合（被覆）。レート・歪み | 少ない情報量で誤差が小さい。被覆の外の区間が少ない |
| R4 新しい入力に適切に追加する | 追加の判断の点数で「新しい suite の区間か」を当てる AUROC。既知の区間での誤った追加の率。追加した単位あたりの新しい suite の誤差の改善。追加した単位が新しい suite の中で再利用される率。追加した単位が既存と重複していないか | 新しいものだけを追加し、追加した単位は役に立ち、再利用され、重複しない |

### パイロットで見つかった問題と直し方（2026-10-26、`skill-formation-20261026T174759Z-cedc45`）

- P1：離散の base を持つ方式（FSQ、M2〜M5）で、base を 0 やランダムにしても誤差が変わらない。デコーダが観測特徴 f と residual だけで行動を出し、base を無視していた。
  → D1：デコーダは f を見ない（Â = Dec(b, r, s)）。観測はスキルの選択と residual の予測にだけ使う。D2：residual に KL をかけて容量を絞る。
- P2：追加の判断がキーの新しさだけで、スキルの新しさを見ていない。M3〜M5 は追加率 100%、M4 の統合と M5 の原子追加は起きていなかった。
  → D3：新しさを2段に分ける。キーが新しい → メモリに項目を追加（新しい場面）。base が既存の単位から遠い → スキル単位を追加（新しい運動）。R4 は後者で測る。
- P3：レートの推定と冗長性の判定が、方式を区別できていなかった。→ 計算方法を直す。
- 参考（P1 の影響が小さい連続の方式）：M1（独立化の重み 0.01）は、object/goal のメモリから spatial を引く誤差が 0.205 で、M0 の 0.235 より良かった。

LIBERO-10（長い複合タスク）は既知の運動の組み合わせなので、R4 では「追加が少なく再利用が多い」ことが期待される。spatial（新しい場面）との対比に使う。
LIBERO-10 の特徴も、同じ凍結 VLM で抽出してキャッシュに加える。

## スキルの定義（2026-10-27 ユーザー確認）

スキルは、場面に依存しない運動の型（ベース空間の領域）とする。場面との対応は、メモリの項目（キー = 観測、値 = ベース）が受け持つ。
個数は事前に決めない（K を固定する k-means は、初期化にも評価にも使わない）。取り出すときは、ソフトマックスの重みで複数のスキルをブレンドする。

```
機能的距離： D(b, b') = 固定標本 (r, s) での ||Dec(b,r,s) − Dec(b',r,s)||² の平均
尺度：       ε = κ · （学習のランダムなベースの組の D の中央値）
割り当て：   min_j D(b, c_j) ≤ ε なら単位 j に入れる。そうでなければ保留の場所に入れる
登録：       保留の中で D ≤ ε でつながるまとまりが m 区間以上、かつ別々のエピソード e 個以上なら新しい単位にする
             既存の単位と D ≤ ε なら、登録せずに統合する
取り出し：   キーで上位 k 件の項目を取り、α_i = softmax(−dist_i / T)
             項目ブレンド b̄ = Σ α_i b_i、またはスキルブレンド b̄ = Σ_j (Σ_{i∈j} α_i) c_j
```

この手順は M6 として実装する。前回の判断では、学習データの最近傍距離の q95 を閾値にしていたため、既知のデータでも約5%を必ず新規と判定していた（Split A と B で単位の追加率がほとんど変わらない）。M6 は、これを繰り返し現れることという条件で抑える。
