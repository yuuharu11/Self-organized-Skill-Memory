# 検索メモリを追加する初期実験

この文書は実装前のモデル・評価方針。メモリモデルの学習や性能検証はまだ行っていない。
ラベルなしの創発スキルに向けた次の段階の方針は [emergent_skill_plan.md](emergent_skill_plan.md) にまとめている。

## 土台にするモデル

- 公開SkillNet-LIBERO-40。
- 設定: `pi05_libero_moe_skill_4_40`。
- 重み: `jsw19/SkillNet-LIBERO-40`、revision `2505898fbf65d06994711ca69a2141f904c9368f`。
- 初期実験では既存の視覚・言語モデル、action生成器、MoEを固定する。
- 既存モデルの出力を比較対象として残し、別の大規模モデルは一から学習しない。

## 段階と追加部分

1. 既存方策の実行から、開始時の観測、ロボット状態、実行行動、区間ID、初期状態ID、内部特徴を記録する。
2. 検索キーには現在までの観測・目的の特徴、値には運動生成側の区間特徴を候補として保存する。
3. 検索した複数の値をsoftmax重みで合成し、通常の観測に追加する情報として使う。
4. 小さなアダプタで既存のスキル条件付けを補足する。学習は追加部分から開始する。

運動生成側の特徴は、既存モデルのaction側隠れ状態などを候補とする。
最初の暫定特徴を、獲得済みのアクション概念とは呼ばない。
生成したaction chunkと実際に実行した短い区間は区別して記録し、未実行の予測を成功経験として登録しない。

接続の候補は、検索合成値を小さな投影でskill embeddingの次元へ変換し、
既存の条件付けに残差として加える形。
アダプタの出力をゼロに初期化し、メモリを無効にすれば元の推論と同じになる設計にする。
ゼロ出力の初期化と、学習時に勾配が流れることは別々に確認する。

この段階では既存SkillNetのskill IDと注釈も残る。
言語ラベルなしで運動スキルを発見したという主張には使わない。
メモリが実際に役立つことを確認してから、連続運動表現の学習やID条件への依存を減らす実験へ進む。

## タスクと分割

- シミュレータはLIBEROを継続使用する。
- 初期の動作確認は `libero_spatial` の10タスクで行う。
- メモリ作成・追加モジュールの学習・評価は、エピソードと初期状態IDを分離する。
- 同じエピソードの隣接窓を訓練・評価にまたがって使わない。
- 公開LIBERO-40重みは対象タスクを学習済みなので、これはメモリ追加の寄与を測る実験。
  メモリに含めないタスクを作っただけで、モデルにとって未知タスクだとは主張しない。
- Spatialの各1試行10/10成功は既存環境の疎通確認。メモリの効果を示す結果ではない。
  本実験では複数初期状態、データ量、実行時間、検索の有無をそろえて比較する。

## 最初の比較

| 条件 | 検証する点 |
| --- | --- |
| 既存モデルのみ | 学習済みベースライン |
| メモリ経路を追加するが無効 | 元モデルとの出力一致 |
| ランダムなメモリ | 追加パラメータだけの効果を区別 |
| top-1検索 | 単一記憶による条件付け |
| 複数検索の重み付き和 | 合成が単一検索より役立つか |

重み・検索候補・区間IDをログへ残し、正解区間そのものの検索による評価漏洩を防ぐ。
現在の成果はモデルと実験方針の具体化までであり、これらの比較は未実装・未実施。
