# 相談：新しいタスクで「正しいスキル」を取り出す方法（2026-10-30）

## 0. 一言で

π0.5 系の VLA（SkillNet）に、ラベルなしで作ったスキルの記憶を足しています。行動は記憶から取り出したスキルから生み、フローマッチングのデノイズで今の場面に合わせる、という構想です。

- 既知のタスクでは効きます。
- 新しいタスクでは、**正しいスキルを取り出せない**ために効きません。
- 正しいスキルを入れれば、新しいタスクでも誤差は 40〜75% 下がります。つまり伸びる余地はあり、壁は取り出しにあります。

**相談したいこと**：新しいタスクで、場面に依存しない運動の型としてのスキルを、どう取り出せばよいか。

## 1. 研究の構想と、譲れない条件

- **目的は汎化**（新しいタスク・新しい場面）。速さは目的にしない。
- **行動は常にスキルから生まれる。** スキルを補助扱いする案は避けたい。ただし、確信度が低いときに通常のデノイズへ戻す簡易な MoE（ゲート）は、安全装置として検討中。
- **スキルの定義**：場面に依存しない運動の型。ラベルなしで創発させる。サブタスク名などの人手ラベルは使わない。取り出しは、上位候補の softmax ブレンド。スキルの個数は固定しない。
- **デノイズの仕方**：取り出したスキル a からデノイズを始める。ノイズ量 t0 と反復回数を、取り出しの確信度で決める。
  ```
  x_t0 = (1 − t0)·a + t0·ε
  凍結した行動ヘッドで t0 → 0 まで積分（n = max(2, round(10·t0)) ステップ）
  ```
  openpi の規約で t = 1 がノイズ、t = 0 が行動。t0 = 1 は通常の方策と同じ。
- **ベースモデル**：公開されている SkillNet（π0.5 / openpi）。SkillNet のスキル埋め込みは、MoE のルーターにしか入らない。
- **評価**：
  - 本番は LIBERO-Skill（skill_obj_02〜09、ゼロショット）。論文値は SkillNet 44.5%、π0.5 28.5%。
  - 将来は RoboCasa365（atomic → Composite-Unseen）と実機。

- 同じ初期ノイズを全条件で共有した。
- 95% 区間は、エピソード単位のブートストラップで出した。

### 3.5 ステップ 1：場面に合わせる変換器 F（行動ヘッドは凍結、F だけ学習）

```
Â = a_ret + ΔF(a_ret, q, s)     # 残差型。ΔF の最終層は 0 で初期化
Â を下書きにして、凍結したヘッドで t0 = 0.2 からデノイズ
```

新しいタスク（160 行、20 エピソード）での結果：

| F | t0 = 1 との差 | スキルなしの F(q, s) との差 |
|---|---:|---:|
| 残差型 | −.009（有意） | −.009（有意） |
| 直接回帰型 | −.010（有意） | −.009（有意） |
| 幾何変換型（平行移動・スケール・回転） | −.004 | −.003 |

- 合格基準（−0.02）には届かなかった。
- 改善はスキルから来ている。スキルなしの F は通常の方策と変わらなかった。また、q を別の行のものに入れ替えると悪化した。
- 正しい下書きを入れれば、同じ変換器で誤差が約 75% 下がる。**壁は検索。**

## 4. 課題の整理

1. **キーと目的がずれている（と考えている）。** VLM の特徴は主に「どんな場面で、どんなタスクか」を表す。これは新しいタスクで変わる部分そのものだ。一方、欲しいスキルは場面に依存しない運動の型である。そのため、場面の近さで探すと、新しいタスクでは外れる。
2. **確信度が当てにならない。** 類似度が表すのは「似た場面があったか」で、「取り出したスキルが正しいか」ではない。このため、ゲート（簡易 MoE）を作っても、開くべき場面を選べない。
3. **凍結したヘッドは、ずれた下書きを直せない。** 小さな変換器 F で、ある程度は直せた。ヘッドの fine-tune（後述の案 C）は、まだ試していない。
4. **関連研究とのかぶり。** BehaviorVLA（arXiv 2605.22671、ICML 2026）が近い。内容は次の通り。
   - 過去の画像と行動から行動のプロトタイプを作り、メモリに保存する。
   - エピソードの最初に一度、(最初の画像, 指示) で上位 K 件を取り出す。
   - それをガウス事前分布にして、π0.5 のフローマッチングに足す。ヘッドも一緒に学習する。
   - 学習に「behavior label」を使う。
   - 新しいタスクへの汎化は評価しておらず、限界の節で弱いと認めている。
   
   私たちが差を付けられるのは、ラベルなしで創発するスキル、確信度で t0 と反復回数を変える仕組み、新しいタスクへの汎化の 3 点だと考えている。

## 5. 今考えている案

| 案 | 中身 | 学習 |
|---|---|---|
| A1 方策の予測をキーにする | 通常の方策が出した行動 a_pol に近いチャンクを、行動空間で検索する | なし |
| A2 運動の文脈をキーにする | 直前の行動チャンクとロボット状態から、「この動きの続き」を検索する | なし |
| A3 二段階 | VLM で候補を絞り、A1 か A2 で並べ替える | なし |
| B 確信度を変える | a_ret と a_pol の一致度を確信度にして、ゲートと t0 を決める | なし |
| C ヘッドの fine-tune | 行動ヘッドを、スキルの下書きから場面に合わせて直すように学習する。誤ったスキルからでも戻れるようにする（正しい・位相違い・近い・ランダム・なし を混ぜる） | あり |
| D スキル空間の分離 | スキルの潜在から場面で決まる部分（位置・距離）を除き、場面への合わせ込みはデコーダに持たせる | あり |

懸念：
- A1 は循環的ではないか。方策の予測の近くを探して、方策より良いものが出てくるのか。
- A2 は、タスクの切り替わり（次の運動に移る瞬間）で外れそう。

1. 新しいタスクで「場面に依存しない運動の型」を取り出すには、何をキーにすべきか。上の A1〜A3 以外に有望な設計はあるか。
2. 取り出しの確信度として、「取り出したスキルが今の場面で正しいか」を表す、学習なしで作れる量はあるか。
3. A1（方策の予測で検索）に意味はあるか。循環の問題をどう考えるか。
4. 取り出し（どの型か）と、合わせ込み（どこへ・どれだけ）を分ける設計（案 D）は筋が良いか。分けるなら、スキルの表現をどう作ればよいか。
5. 学習なしの制約を外すなら、A〜D のどれを、どの順で試すべきか。それぞれ、短時間で go / no-go を決められるオフラインの判定基準は何か。
6. BehaviorVLA との差を研究として主張できる形にするには、どの実験が要るか。
7. この方向全体を見て、筋が悪いと思う点があれば率直に指摘してほしい。

## 7. 回答の要旨と判断（2026-10-30 追記）

外部モデルから 3 本の回答を受け取った。要点と、こちらの判断を記録する。

### 7.1 回答 1：キー・確信度・案 D について

**採用するもの**
- **t0 = 0.2 での反復回数 n = 2 は少なすぎる。** 速さは目的にしないので、n = 10 と比べて切り分ける。
- **ブレンドは、同じ運動単位の中だけにする。** 上位 5 件に別の単位が混ざると、その平均はどちらでもない軌道になる。
- **案 D の具体化。** チャンクを次の 2 つに分ける。
  - 型：単位長・正面向きにした軌道と、グリッパー
  - 方向と距離
  
  スキルは型だけを供給し、方向と距離は今の方策と場面から取る。これはスキルの定義（場面に依存しない運動の型）とも一致する。

**保留するもの**
- 行動ヘッドの中間表現や MoE ルーターの表現をキーにする案。
- 速度場の整合性を確信度に使う案。
- 方策の予測で検索する案（A1）が、多様体への射影として働くという主張。

### 7.2 回答 2：これまでの改善はノイズ削減の効果ではないか

**数値は確認できていない。** この回答は、「方策の出力 3 回の平均（P）」の追試結果があるという前提で書かれている（新しいタスクで V が +.020、P が −.011 など）。しかし、こちらにはそのような実験の出力がない。そのため、数値は検証済みの事実として扱わない。

**主張の中身は重要なので、検証する。**
- t0 = 0.2 では、確定的な下書きを入れるので、初期ノイズの分散が大きく減る。
- これだけで MSE が下がるなら、これまでの改善はスキルの効果とは言えない。対象は、既知タスクの −.016 と、変換器 F の −.009。

### 7.3 回答 3：確認実験の仕様

確認 1 と確認 2 の仕様を受け取り、そのまま採用した。
- P1・P3 を作る乱数は、評価用の乱数と分ける。
- P0（ε = 0）は、直接出力した場合と、下書きにした場合の両方を測る。
- V_same（同じ運動単位の中だけでブレンド）も測る。
- 分解は並進 3 次元だけで行い、距離が小さいチャンクにはガードを入れる。
- 乗法版と加法版の両方で分解する。

### 7.4 実施中の確認（出力：variance-decomp-<UTC>）

**確認 1：ノイズ削減だけでどこまで下がるか。** 次の下書きを、t0 = 0.2（n = 2 と n = 10）で比べる。
- P1、P3、P0（下書きにした場合と、直接出力した場合）
- V、V_same、F、O

**確認 2：オラクルの改善は型と空間のどちらから来るか。**
- 型オラクル：O の型に、P3 の方向と距離を合わせる。
- 空間オラクル：P3 の型に、O の方向と距離を合わせる。

**結果による分岐**

| 結果 | 次の一手 |
|---|---|
| 型オラクルが P3 を有意に上回る | 案 D、必要なら案 C を加える |
| 空間オラクルだけが効く | 型のスキルでは勝てない。方針を見直す |
| V と F が P3 に勝てない | 今後の合格基準を「P3 に勝つこと」に変える |
