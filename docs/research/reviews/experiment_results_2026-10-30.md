# 実験結果のまとめ：スキルメモリを出発点にするデノイズ（2026-10-30 時点）

この文書だけで読めるように、手法の定義と結果の数値をまとめた。

## 1. 手法と評価の設定

```
方策：公開 SkillNet（π0.5 系、LIBERO-90 で学習済み）。重みは凍結（学習なし）
フロー：t = 1 がノイズ、t = 0 が行動。x_t = (1 − t)·A + t·ε

スキルメモリ（LIBERO-90 のデモから、勾配なしで構築）：
  各時刻の行動チャンク A（10 ステップ ≒ 0.5 秒）
  キー k = π0.5 の VLM（画像・指示文・状態）の最終層を、トークンで平均したもの
  b = Enc(A, s) ∈ R^12（小さな自己符号化器）、生のチャンク A も保存
  b を機能的距離でまとめた単位：57 個。エントリ数：55,660

行動の生成（5 ステップごと）：
  q = 今の観測の VLM 平均（キーと同じ作り方）
  上位 5 件を検索 → 下書き a を作る
  t0 = 信頼度から決める。n = max(2, round(10·t0))
  x = (1 − t0)·a + t0·ε から、凍結したアクションヘッドで t0 → 0 までデノイズ
  t0 = 1 は通常の方策と同じ
```

- **本番の課題**：LIBERO-Skill の skill_obj_02〜09（8 タスク）。LIBERO-90 にはない新しいタスクで、指示文は固定、初期配置だけが試行ごとに変わる。各タスク 20 試行（論文は 50 試行）。
- **論文の値（8 タスク平均）**：SkillNet 44.5%、π0.5 28.5%。
- **オフライン評価**：LIBERO-90 の保留分 256 行（64 エピソード、メモリには入っていない）。デノイズ後の行動と、デモの本当の行動との誤差（正規化 MSE と、チャンクの終点のずれ mm）。各行で同じ初期ノイズ 3 本を全条件で共有し、t0 = 1 との対応差を出す。95% 区間はエピソード単位のブートストラップ。

## 2. 最初の版（無効・失敗）

| 版 | 内容 | 結果 |
| --- | --- | --- |
| 追加学習版 | アクションヘッドを、アンカーから始める経路で追加学習 | 学習の目標に不具合があり、結果は無効。追加学習した重みは、スキルなしでも 31.2% で、論文の SkillNet より低かった |
| 学習なし・旧アンカー | 単位の中心のまわりから b をサンプルし、エントロピーで信頼度 | 37 組の対応比較で、提案だけ成功 6、通常の方策だけ成功 6。差なし |

## 3. 旧アンカーが効かなかった原因（オフラインの診断）

- **キーの縮退**：上位 1 件の類似度の平均は 0.997（0.984〜0.9995）。上位 5 件の重みのエントロピーはほぼ一様（正規化して平均 0.97）。そのため t0 が 0.6〜1.0 に張り付き、スキルがノイズに埋もれていた。
- **ただし順位には情報があった**：正しい単位の top-1 は約 25%（多数派の単位を答える基準は 4.7%）。
- **下書きの精度**（終点のずれ）：

| 下書きの作り方 | 終点のずれ |
| --- | ---: |
| ゼロの行動 | 61.2 mm |
| 旧アンカー（単位の中心のまわりからサンプル） | 59.3 mm |
| 単位の中心 | 45.2 mm |
| 上位 5 件の b を平均して復号 | 37.7 mm |
| 正しい単位の中心 | 31.7 mm |
| 別のデモで最も近い b（検索が完璧な場合） | 15.9 mm |
| 自分の b を復号（圧縮器の限界） | 2.1 mm |

- **キーの作り方の比較**（512 件の部分メモリ）：全トークン平均、画像トークン平均、指示文トークン平均、最後のトークン、平均を引いた版、状態との結合を比べた。正しい単位の top-1 は、どれも 17〜26% の範囲。最良は全トークン平均（または画像平均）を、メモリの平均を引いて正規化したもの。状態との結合は改善しなかった。

## 4. 改良版（anchor_v2）のオフライン結果：既知のタスク

改良点：キーはメモリの平均を引いて正規化。下書きはサンプルせず、上位 5 件の重み付き平均。メモリは全件。正しい単位の hit@1 は 0.42、hit@5 は 0.72。

正規化 MSE の t0 = 1 との差（τ は半分のエピソードで選び、残り半分で報告）。t0 = 1 の MSE は 0.093、終点のずれは 27.7 mm。太字は 95% 区間が 0 をまたがないもの。

| 下書き | t0 | 全体 | 通常の方策が苦手な 30% | 類似度の上位 30% |
| --- | --- | ---: | ---: | ---: |
| 各 b を復号してから平均（τ = 0.05） | 0.2 | **−.017** | **−.055** | −.008 |
| | 0.4 | −.007 | −.020 | **−.005** |
| | 0.6 | −.005 | −.023 | **−.004** |
| 生の行動チャンクの平均（τ = 0.1） | 0.2 | **−.016** | **−.054** | −.011 |
| | 0.4 | −.006 | −.017 | **−.008** |
| 潜在空間で平均してから復号（τ = 0.03） | 0.2 | **−.012** | **−.042** | −.005 |

- t0 を小さくする（スキルを強く使う）ほど誤差が下がり、単調だった。終点のずれの差は約 −1 mm で、有意ではない。
- 圧縮器を通しても、生のチャンクでも、ほぼ同じ。
- 「苦手な 30%」を別のノイズで選び直しても、t0 = 0.2 の改善は残った（−0.038〜−0.041、有意）。

LIBERO-90 の 10 タスクをメモリから除き、その 10 タスクの行で評価した。LIBERO-Skill に近い条件。t0 = 0.2 での、MSE の t0 = 1 との差：

| キー | 既知のタスク | 新しいタスク |
| --- | ---: | ---: |
| 平均を引いた VLM 平均（学習なし） | −.016（有意） | **−.002（有意でない）** |
| キーの小さな射影を LIBERO-90 で学習（方策は凍結） | −.021（有意） | −.008（有意でない） |
| 検索が完璧な場合（本当の行動に最も近い別のデモ） | −.077〜−.084 | −.039 |

新しいタスクでは、t0 = 0.6 のほうが少しだけ良い（0.5 秒のかけらで −.006、有意）。

## 6. 数秒の区間スキル（オフライン）

LIBERO-90 のデモを、グリッパーの開閉で区切った。3,959 エピソードから 11,017 区間ができ、長さは中央値 2.6 秒（10〜90% 点で 0.45〜4.5 秒）。区間の軌跡を k-means でまとめると、シルエットは k = 5 で最大 0.35。

| 下書き | 新しいタスクで t0 = 0.6 のときの差 | t0 = 0.2 のときの差 |
| --- | ---: | ---: |
| 0.5 秒のかけらを毎回検索 | −.006（有意） | −.002 |
| 区間を開始時に選び、進み具合で揃えて最後まで使う | +.011 | +.064（有意に悪化） |
| 区間を毎回選び直す | +.001 | +.017（有意に悪化） |
| 区間のクラスタの代表軌跡 | +.030（有意に悪化） | +.103（有意に悪化） |

検索した区間の動詞は、新しいタスクで 64%、既知のタスクで 87% 一致した。運動の種類は合っているが、別の場面の軌跡をそのまま使うと、位置や距離が合わない。

## 7. 閉ループ：LIBERO-Skill（改良版、学習なし）

段階 0 で先に終わった 37 組（タスクと初期配置の組）を、4 つの条件で、同じ初期状態・同じ乱数で回した。① は同じ回で回し直した通常の方策。

| 条件 | ①だけ成功 | この条件だけ成功 | 両方成功 | 両方失敗 | 正確符号検定 p | 成功数 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| ② 動的な t0（類似度の中央値以下は t0 = 1、上は 0.6 / 0.4 / 0.2） | 3 | 1 | 24 | 9 | 0.63 | 27 vs 25 |
| ③ 固定の t0（中央値以下は 1、上は 0.4） | 3 | 2 | 24 | 8 | 1.00 | 27 vs 26 |
| ④ ゲートなし、常に t0 = 0.4 | **11** | 4 | 16 | 6 | 0.12 | 27 vs **20** |

- ゲートの閾値（LIBERO-90 保留分での中央値 0.944）を、LIBERO-Skill ではほとんど超えない。タスクごとの類似度の中央値は 0.80〜0.92。②③ は、問い合わせの 90〜100% で t0 = 1 になった。
- ④ はタスク 02 で 6 対 0（p = 0.031）。スキルを強く使うと、新しいタスクでは成功率が下がる。
- 37 組は、短く成功しやすい試行に偏った部分集合。8 タスクの平均の推定には使わない。通常の方策を 8 タスク × 20 試行まで埋める測定が、続いている。

**停止（2026-10-30 01:30 UTC、ユーザーの指示）**：通常の方策を 8 タスク × 20 試行まで埋める測定は、途中で止めた。止めた時点の記録は、① 通常の方策 81 試行（成功 48）、② 37、③ 37、④ 41。① は試行数がタスクごとに 8〜17 とばらつき、短く成功しやすい試行に偏っているので、8 タスクの平均は算出しない。記録は出力ディレクトリにそのまま残してある。


## 8. 軽量版（オフラインの小さなモデル）での補足

- 似たデモがない場面での行動の誤差（MSE）：通常の方策 0.281 / 0.235（Split A / B）に対して、スキル系の最良は 0.211 / 0.163。既知の場面での悪化は 0〜1%。
- 正しいスキルを選べる割合は低い。新しい場面で、学習したスキルのどれかに機能的に合う区間は 21〜26% しかない。選び方の工夫（近傍の投票、統合、出やすさの補正、観測から条件づけた事前分布、2 つの見え方の相互予測）は、どれも目標（正答率 0.7）に届かなかった。

## 9. わかったこと

1. **学習なしで、凍結した方策の出発点にスキルを入れる方式は、新しいタスクでは効かない。** 既知のタスクでは誤差が 16〜21% 下がるが、新しいタスクでは改善がほぼ消える。閉ループでも、ゲートありは通常の方策と同じで、ゲートなしは悪化した。
2. **伸びる余地はある。** 検索が完璧なら、新しいタスクでも誤差は 39% 下がる。
3. **足りないのは 2 つ。** 新しいタスクで正しいスキルを引くことと、引いたスキルを場面（位置や距離）に合わせることである。運動の種類は 6 割以上合っているが、凍結したアクションヘッドは、ずれた下書きを場面に合わせて直せない。
4. **次の候補**：アクションヘッドを、スキルの下書きから場面に合わせて直すように学習する。誤ったスキルからでも戻れるようにして、ノイズの量と反復回数は信頼度で決める。また、スキルの空間から場面で決まる部分を除き、場面への合わせ込みをデコーダに持たせる。どちらも、方策を学習しないという制約を外すことになる。
