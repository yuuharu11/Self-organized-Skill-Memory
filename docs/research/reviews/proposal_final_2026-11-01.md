# 運動片の選択を学習すれば、記憶からの生成は有効になるか

2026-11-01 UTC。外部レビューを受けた本日の提案。**次は、69タスクの経験で検索の再順位付けを学習し、固定した生成器で効果を判定する。** 作業仮説は「現在の性能を制限している有力な要因は、運動片の選択である」。選択だけが原因だとは確定しない。

研究の経路は一貫して、**運動記憶から下書きを取り出し、flow matchingのbridgeで現在の場面へ合わせる**ものとする。通常方策へのゲートは設けない。サブタスクの教師ラベルは使わない。メモリなしのR0は対照である。以前の[R012設計書](proposal_R012_2026-11-01.md)は変更せず、本書で今日の結果と次の判断を整理する。69タスク実験の結果欄は空欄のまま残す。

## 3. 決着実験：69タスクで選択だけを学習する

### 3.1 問い・データ・固定範囲

問いは、**「既存のR1生成器を固定したまま、69タスクで学習した選択器が、正解を見ない検索でもメモリなし対照と対応を壊した記憶を上回るか」**とする。今回はR2、単位の再設計、t0調整、生成器の再学習を同時に入れない。

- [既存の分割manifest](/work/.skillnet-state/outputs/memory-pilot/research-proposal-r012-20261101T003453Z/proposed_split_final.json)の**Train 69／Dev 10／Diag 10**を維持する。task名は分割と監査にのみ用いる。メモリ項目、検索器への勾配、特徴統計はTrainから作る。episode・同一初期状態単位で分け、訓練query自身と同じ実演・初期状態の未来区間を候補から除く。
- 69は**検索器の訓練タスク数**である。R0/R1生成器は今回の10タスク診断の重みを凍結する。公開SkillNetは全89タスクを既習として扱う。既存の運動codecにも全89由来の学習があれば明記し、「すべてを69タスクだけで学習した」とは書かない。単位統計・新しい正規化へのDiag流入は許さない。
- 現在までの画像・全体指示・robot state・関係履歴Φを使う。Φは`t,t−5,t−10,t−15`の4時点。R0にも同じΦを与える。未来のquery行動・未来物体状態・進捗正解・subtask labelを検索入力へ渡さない。**教師行動を使うのはTrainの検索損失だけ**。保存済み候補の行動列を読むことは、現在queryの未来を見ることとは区別する。
- Diagは各タスク5実演、計50実演を固定する。[準備側の選定manifest](/work/.skillnet-state/outputs/memory-pilot/r012-20261101T004734Z/rerank69-v1/diag_selection.json)に従い、画像・action・物理状態の厳密対応が確認できる実演だけを使う。除外した未対応実演の数と偏りも報告する。
- Diag 10のうち4タスクは既に今日のR012診断で見ている。全10タスクの結果を主表に残し、**R012既見4／R012追加6**も分けて出す。追加6も過去解析・cacheの利用履歴を監査し、完全に未使用の検証集合とは仮定しない。新しく選んだ実演にしても4タスクの既見は消えない。公開基盤の既習も含め、厳密な未見タスク検定とは呼ばない。

公開済み特徴の再利用では、行の対応、skill／object annotation入力の有無、codecの学習範囲をmanifestで確認する。確認できない場合は準備未成立として扱い、ラベルなし・Train-onlyという記述を推測で埋めない。

### 3.2 アルゴリズム

```text
bank = Train 69の経験のみから作る固定10×7 actionチャンクと因果的key
       単位membership・key変換・codecの来歴を保存し、Diagでfitしない

各Train query q:
    単位keyのcosine top-20 → メンバーを展開 → 項目keyのcosine top-64
    反対episode-foldの候補だけを使い、同一episode・初期状態を除外
    d_j = MSE(candidate_action_j, queryの教師action)  # 訓練時だけ
    teacher_j = softmax(-d_j / .01)
    score_j = MLP(現在までのquery特徴, 候補特徴・候補action, cosine・順位)
    teacherとのcross entropyで、rerankerだけを更新

推論:
    同じ規則の64候補をrerank → 上位5を固定温度のsoftmaxでブレンド
    A = Σ_j w_j action_j
    B = .6 A + .4 ε
    R1の既存S-all bridgeを、Aと現在文脈で条件付けして積分
```

bridgeの既存訓練定義は`X_s=(1−s)a*+sB`、`t=.4s`、速度教師`(B−a*)/.4`である。今回はその生成器へ新しいAを渡す。**H=10、replan=5、t0=.4、Euler 2回**を固定する。低確信でも通常方策へ切り替えず、適応積分・候補数変更・可変長・グラフ探索を加えない。

rerankerは[10タスク版の実装](/work/.skillnet-state/outputs/memory-pilot/r012-20261101T004734Z/rerank-v1/run_rerank.py)と同じ小MLPを用いる。AdamW、LR `5e−4`、weight decay `1e−4`、batch16、最大80 epoch、patience8、seed `20261102`を基準に固定する。episodeで分けたTrain内部validationの候補選択誤差でepochを選び、ブレンド温度は既存grid`.01,.025,.05,.1,.2,.5,1`から同validationだけで決める。10タスク版の選択値1.0を、69タスクでの選択済み値として流用したとは書かない。Devは入力・整合の確認に使い、Diagの誤差で設定を選び直さない。

### 3.3 比較と事前の通過条件

同じquery・同じ3本のnoiseで、次の条件を一度に評価する。

| 条件 | 役割 |
| --- | --- |
| R0固定 | 同じ現在・履歴情報を持つメモリなし対照 |
| R1固定＋69-bank cosine | 同じ69-bank、同じ64候補からcosine top-5をブレンド。bank拡大と選択学習の効果を分離する |
| R1固定＋69-bank rerank | 提案する選択器。変えるのは候補のスコアだけ |
| 同rerankの下書きをshuffle | 生成器・下書き分布を保ち、queryとの対応を壊す。旧版と同じ固定の行循環shuffleを用い、shuffle乱数を成績で選ばない |
| 全bank／64候補内のオラクル | 評価時だけ教師行動で選ぶ上限。通過条件には使わない |

**10タスク版で不通過とした基準を維持する。** 正規化active 7次元×10ステップの生成後MSEを、各noiseについて計算して平均する。3予測を平均してからMSEを取るP3集計に置き換えない。比較ごとに同じ評価行とnoiseを使う。

`Δ0 = MSE(rerank) − MSE(R0)`、`Δshuffle = MSE(rerank) − MSE(shuffle)`とする。**両方のepisode単位対応bootstrap 95% CIの上端が0未満のときだけ通過。** 10,000再標本化、bootstrap seed713を維持する。片方のみ、点推定のみ、下書き誤差のみの改善は不通過とする。データ対応・漏洩・train/serve整合に問題があれば、性能の不通過と混同せず「実験不成立」と記録する。

cosineとの差は、**学習した選択の寄与を説明するために必ず併記**する。上の通過基準を満たしてもcosineを超えなければ、bank拡大の効果を選択学習の効果と主張しない。候補内オラクル誤差、exact-item coverage@64、hit@5、下書き誤差、生成後の位置・回転・gripper別誤差、clip率、task別差も出す。評価後に都合のよい指標へ主判定を変更しない。

CIはこの診断集合のepisode変動を扱う。訓練seed間や新しいタスク分布への確実性は表さない。query窓を独立試行として数えない。

### 3.4 この実験の公平性と射程

**これは選択を調べる限定実験であり、69タスクで同予算学習したメモリなし方策に勝つ実験ではない。** R0/R1の生成器容量・元の10タスク訓練予算は揃っているが、今回のrerankerだけに69タスク分の追加学習を与える。追加データ・更新数・計算時間を明記する。同一69-bankのcosine／rerank／shuffle比較は、この固定生成器内での選択の寄与を測る。

手法全体の主比較へ進む場合は、同じ69タスクのデータ、共通入力、生成器容量、更新予算、推論NFEでR0とmemory bridgeを学習し直す。rerankerの追加計算も計上する。特権Φの成績と、公式の画像・指示・robot stateだけの成績を別表にし、LIBERO-Skillの実演や物体軌跡を開発へ流さない。

**読み方**

2. **正しい下書きなら、公開 SkillNet を大きく上回る。** オラクル下書きで .0178。P3 .0274 より 35% 低い。Diag は SkillNet の既習タスクであり、SkillNet に有利な比較でもこの差が出る。

4. §4 の表では「下書きだけ改善し、生成後は不通過」に近いが、生成後も方向は改善している。事前の約束どおり、閾値・候補数・t0 の調整で救済はしない。

**判断**：この形（cosine 候補 → 学習 rerank → 上位 5 のブレンド → bridge 生成）では、事前に固定した基準でメモリの利得を確認できなかった。確立できたのは「メモリへの依存と、選択が正しいときの大きな上限」まで。次に投資するなら、第一段の候補到達（33%）を、行動教師で学習した第一段検索（RA-VLA 型の対照を含む）で上げられるかであり、これは新しい事前登録の実験として扱う。
