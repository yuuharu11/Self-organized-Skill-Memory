# 運動の型から始めるデノイズ：スキルメモリの主張と検証計画（2026-10-28）

研究の主張（山本さんの構想）を整理し、批判的に検討した点、実装と検証の計画、判定の基準をまとめる。
これまでの軽量検証の結果は [skill_memory_findings.md](skill_memory_findings.md)、評価の手順は [libero_lifelong_protocol.md](libero_lifelong_protocol.md) にある。
新規性の調査結果は §6、先行研究と比較対象の一覧は [prior_work_and_baselines.md](prior_work_and_baselines.md) にある。

## 1. 主張

1. **プリミティブな運動は MoE のエキスパートが担い、それを一段抽象化したものを「スキル」と呼ぶ。** スキルは場面に依存しない運動の型で、ラベルなしに運動経験から自己組織化する。
2. **スキルメモリは継続学習に対応する。** 新しい運動は、勾配による更新なしにメモリへ単位として追加される。
3. **スキルを外部の条件としては与えない。** 条件は従来の VLM の出力トークンと同じく、画像・サブタスク・ロボット状態の埋め込み空間だけである（サブタスクはスキルの上位概念で、スキルのラベルではない）。
4. **デノイズは「根本的な運動を状況に合わせて最適化する過程」である。** そのため、メモリから取り出したコアの行動を、デノイズの開始点にする。
5. **似た行動を集めると集合ができ、その集合をデノイズの出発点として表せる。**

目的は、未学習の場面・タスクへの汎化である（推論の速さは主張しない）。

## 2. 手法（アルゴリズム）

```
運動の符号化（学習済みで、追加時は固定）：
    b = Enc(A, s)                      A：行動チャンク、s：ロボット状態。b：運動のコード

メモリ（単位 k ごとに、登録時に同じ区間から鍵と値を同時に作る）：
    値   (c_k, σ_k)                    b 空間での中心と、単位内のばらつき
    鍵   κ_k = mean E(画像, サブタスク, 状態)   入力空間の埋め込みの平均
    単位の追加・統合は skill_memory_findings.md §1 の M6（機能的距離 D と閾値 ε）

取り出し：
    w_k(o) = softmax_k( cos(E(o), κ_k) / τ )
    t0(o)  = g( H(w) )                 H：w のエントロピー。確信が高いほど小さい t0

デノイズ（フローマッチング。openpi の規約で t = 1 がノイズ、t = 0 が行動）：
    k ~ Categorical(w)                     成分を1つ選ぶ（平均はとらない）
    b' ~ N(c_k, σ_k² I)、 a_k = Dec(b', s)   ばらつきは b 空間で与えて復号する（行動空間の σ と混同しない）
    x_{t0} = (1 − t0) · a_k + t0 · ε,  ε ~ N(0, I)                     … (★)
    x_{t0} から t = 0 までアクションヘッドで仕上げる。反復回数 n = max(1, round(N · t0))（N = 10。刻み幅は通常と同じ）
    t0 と n は確信度で決める（2026-10-28 ユーザーの指定：信頼度に応じてノイズの量と反復回数を変える）
    t0 = 1 では a_k の係数が 0 になり、純粋なノイズから始める通常の方策と完全に一致する

アクションヘッドの学習：
    通常の経路 x_t = t · ε + (1 − t) · A をそのまま使う（中間状態は通常の学習経路の上にある）
    加えて、アンカーと正解のずれに慣らすため、x_t = (1 − t) · a + t · ε, a ∈ {取り出したアンカー（同じエピソードと近い収録を除く）, 正解の b から作ったアンカー}
    で A を目標にする項を混ぜる。主に使うのは「取り出したアンカー」で、正解の b は少量にする（取り出しの誤りへの耐性を過大評価しないため）
```

当初は混合分布 Σ w_k N(Dec(c_k), σ_k²) を時刻 t0 の状態として直接置く式を書いていた。調査（[novelty_anchor_flow.md](novelty_anchor_flow.md) §7）の指摘で、これは時刻 t0 で学習経路が作る分布と一致せず、t0 → 1 でも通常のノイズに戻らないことが分かったので、上の (★) に改めた（2026-10-28）。
成分を1つサンプルする方式を主とし、比較として、近い単位のブレンド、複数の取り出しから平均と分散を合わせた1つのガウス（OptimusVLA 型）を置く（§3 の2）。

## 3. 批判的な検討：主張が依存している仮定

| # | 仮定 | 問題 | 対応 |
| --- | --- | --- | --- |
| 1 | 似た行動が自然に集まる | 「似ている」は距離の定義で決まる。§6 の所見では残差 r が使われず、b は行動チャンクを丸ごと圧縮したコードになっていた。粒度 κ は、データだけからは一意に決まらない（§7） | 「ラベルなしに、ひとつの外部基準（許容する誤追加率 α）から単位が創発する」と主張する。b の場面への非依存性は別に検証する |
| 2 | 集合の中心をデノイズすれば集合を表せる | 多峰の集合（左から回る／右から回る）の平均は、無効な運動になる。行動空間で別のスキルをブレンドしても同じ | 点ではなく分布（★）を開始点にする。ブレンドは近傍の単位に限るか、成分をサンプルする |
| 3 | 外部でコンディショニングしない | 開始点も、情報を注入する経路の一つである。「条件付けしない」は査読で崩れる | 差は「スキルのラベルも外部モジュールも使わず、単位が創発し、勾配なしで追加され、条件の経路はクエリの埋め込み1本だけ」と言い換える |
| 4 | デノイズが状況への最適化を担う | 弱いノイズから始めると、デノイザは近くの修正しかできず、どの運動を選ぶかは取り出しで決まる。多峰性の選択が取り出しに集中する | 取り出しの確信度で t0 を変え、外れたときは通常の方策に戻す。取り出しの精度を主要な指標にする。ただし softmax のエントロピーは絶対的な確信度ではない（どの鍵からも遠いクエリでも尖る。同じ運動の単位が重複すると上がる）。絶対的な類似度や RTS 型の値と比べる |
| 5 | 継続学習ができる | 新しい単位をメモリに追加しても、アクションヘッドが既知の運動に引き戻すかもしれない | アクションヘッドを固定したまま、新しい運動で効果があるかを測る（§4 の S1） |

既存の結果のうち、主張を支えるもの：取り出した b から始める (iii) は RAGDP 型に H=25 の全条件で勝ち、取り出した値をシャッフルすると大きく悪化する（[skill_memory_findings.md](skill_memory_findings.md) §4）。
弱いところ：正解の b を渡した上限との差が大きく、ボトルネックは取り出し（§4、§5）。また、これまでの比較は既知の運動のクラスだけである。

## 4. 検証計画

段階ごとに go/no-go を判定する。実装は S1 と S2 を並行して進め、S2 の閉ループ評価の本番は S1 の判定後に行う。

### S1：軽量版での決定的な確認（オフライン、凍結した VLM 特徴＋小さな MLP）

```
Split A：学習 = object＋spatial、新しい suite = goal（新しい運動の4タスクを含む）
Split B：学習 = object＋goal、新しい suite = spatial
アクションヘッドは学習データだけで学習し、以後は固定。新しい suite の区間はメモリへの追加だけ
比較：通常（ノイズから）／RAGDP 型／RTS 型（生の区間の記憶＋確信度 t0）／OptimusVLA 型（取り出しの平均と分散の1つのガウス）／(iii) top-1／
      (★) 成分サンプル＋確信度 t0（エントロピー、絶対類似度、固定 t0、t0 をクエリ間でシャッフル）／アンカーのシャッフル／正解の b（上限）
      すべて同じアクションヘッドの学習データ・更新量・ステップ数で揃える
seed 0, 1, 2
```

判定（すべて新しい suite で、とくに Split A の新しい運動4タスク）：
- **S1-a**：(★) の行動誤差が、通常より 10% 以上小さく、RAGDP 型以下。シャッフルでは通常より悪化する（アンカーが使われている）。
- **S1-b**：新しい運動の区間で、追加後に登録された単位が top-1 に選ばれる割合が 50% 以上。
- **S1-c**：二乗誤差は平均的な行動を有利にするため、多峰性も測る。同じ観測から8本サンプルし、最良の1本の誤差とグリッパー開閉のタイミングの分布が、通常の方策より悪くない。
- エントロピーで t0 を決めることの効果は、t0 を固定した場合と比べて報告する。

#### S1 本番の結果（2026-10-28、サブタスクは gold、3 seed）

[report.md](../../.skillnet-state/outputs/memory-pilot/s1-production-20261028T065924Z/report.md)。行動の MSE（平均 ± seed 間 SD）：

| 対象 | 通常 | RAGDP 型（生の区間） | 提案（成分サンプル＋エントロピー t0） | アンカーのシャッフル |
| --- | ---: | ---: | ---: | ---: |
| A 全体 | 0.337 ± 0.017 | **0.087 ± 0.002** | 0.189 ± 0.007 | 0.246 ± 0.017 |
| A 新しい運動 | 0.480 ± 0.072 | **0.080 ± 0.007** | 0.237 ± 0.028 | 0.312 ± 0.042 |
| B 全体 | 0.240 ± 0.010 | **0.081 ± 0.001** | 0.175 ± 0.002 | 0.221 ± 0.006 |

- S1-a 不合格：通常より 27〜50% 良いが、生の区間の記憶に大きく負ける。
- S1-b 合格：新しい運動の区間で、追加された単位が top-1 になる率は 82 ± 5%（4タスクとも 50% 以上）。
- S1-c 合格（task 15 は seed 間で不安定）：8本の最良と開閉タイミングは通常より良い。
- エントロピーで t0 を決める利点は一貫しない。成分サンプルは top-1 より平均 MSE が悪く、best-of-8 は良い。
- 解釈：新しい suite の同じタスクの別デモがメモリに入るので、生の区間の記憶はほぼ同じ場面の行動をそのまま引ける。単位の中心は平均化されて細部を失う。「通常」は混合で学習した F をノイズから動かしたもので弱く、比較が不公平（ノイズだけで学習した F を追加する）。
- 次に確かめること：同じタスクのほぼ同じデモがメモリにない条件（場面・物体が違う、追加デモが少ない）で、単位が生の区間に勝つか。単位を選んでからその単位の中の最も近い区間を使う2段の取り出し。

#### 単位の解釈（2026-10-28、S2 メモリ 57 単位、事後の解釈）

[summary.md](../../.skillnet-state/outputs/memory-pilot/interpret-units-20261028T171143Z/summary.md)、図鑑：https://claude.ai/artifact/8AKkqV5zurMmp9aNKmyfU7
- 57 単位中 42 単位（74%）は、場面を変えても方向・回転・グリッパーが一貫する運動として記述できる（例：右へグリッパーを開いたまま 50 mm）。
- 1 単位は中央値で約 70 タスクにまたがる。39 単位（68%）は「方向×グリッパー×回転」の記述が他の単位と重なる。
- 同じ単位が続く長さは中央値 0.5 秒（区間 1 つ）、隣の区間で単位が切り替わる率は 79%（区間は重なりなし）。
- 解釈：いまの単位は 0.5 秒の動きのかけらで、構想の「プリミティブを一段抽象化したスキル」にはなっていない。区間を長くする、単位の列をまとめる、境界をデータから決める、のどれかが要る。

### S3：プリミティブの列をまとめた上位の単位（スキル）（2026-10-28 設計）

解釈の結果、いまの単位は 0.5〜1.25 秒の動きのかけら（プリミティブ）だった。構想の 2 層（プリミティブ → スキル）に合わせ、プリミティブの単位の列を上位の単位にまとめる。ラベルは使わない。

```
1. 区切り：エピソードをプリミティブの単位の列 u_1..u_T にし、境界をデータから決める
   候補：グリッパーの開閉の切り替わり、b の変化点（隣の区間との機能的距離が閾値超え）、両方
2. 区間の表現：区切った区間（可変長、0.5〜数秒）を、プリミティブの列と b の列から固定長に
   （例：時間で正規化した b の列を K 点に再標本化して連結、または小さな系列エンコーダ）
3. スキルの形成：区間の表現に M6 と同じ規則（機能的距離 + 閾値、個数を決めない、勾配なしで追加）
4. 取り出しと使い方：クエリ → スキル → スキルの中の位置（何番目のチャンクか）→ そのチャンクのアンカー
   → §2 と同じく確信度で t0・n を決めてデノイズ
評価：
  解釈：スキルの長さ、またがるタスク数、事後の動詞の純度、列としての一貫性
  効果：公平比較と同じ条件（D1/D2/D3、F_normal 基準、同じノイズ）で、プリミティブ単位・生の区間と比べる
        本命は D3（メモリにほぼ同じデモがない）
```

この環境で行うのは、上の判定ができる規模の閉ループ評価までとする。多数の設定や長時間の学習を伴う本番の実験は、インターンが行う。

## 5. 決まっていないこと（判断が必要）

1. 混合分布から成分を1つサンプルするか、近い単位をブレンドするか（S1 の結果を見て判断する）。
2. b を「場面に依存しない運動の型」と呼べるか。r が使われないままなら、b は「運動のコード」と呼び、b と r の分解は主張しない（[skill_memory_findings.md](skill_memory_findings.md) §6）。
3. プリミティブな運動を担う MoE のエキスパートと、スキルメモリの関係。今回の S2 では MoE はそのまま使い、スキルは開始分布の経路だけから入れる。

## 6. 新規性の調査

詳細は [novelty_anchor_flow.md](novelty_anchor_flow.md)（2026-10-28）。主張ごとの先行研究と、実行する比較対象（B0〜B11）は [prior_work_and_baselines.md](prior_work_and_baselines.md)。要点：

| 要素 | 判定 | 最も近い先行研究 |
| --- | --- | --- |
| 観測に依存した開始分布からフローを始める | 既存 | PriorGrad、BRIDGeR、データ依存のカップリング、LAFM |
| ラベルなしの運動の潜在コードで開始分布を選ぶ | 既存に近い | LAFM（動画からの潜在行動、固定 512 個の学習済み事前分布）、SL-FM |
| スキルのトークンを入れず、開始分布だけで行動を誘導する | 既存 | SL-FM、MOSS |
| 勾配なしで経験を追加し、取り出した行動から確信度に応じた t0 で始める | 既存 | Retrieve-then-Steer（arXiv:2605.10094。LIBERO-10 で π0.5 が 92.4→94.4%） |
| 複数の取り出しの平均とばらつきから始め、類似度でノイズ量を変える | 既存 | OptimusVLA（CVPR 2026） |
| 個数を決めずに形成した運動単位を、固定した方策のまま追加し、未見の運動へ転用する | **貢献の候補（未検証）** | 一体として行った先例は見つかっていない |
| 場面に依存しない運動の型が自己組織化する | **貢献の候補（未検証）** | |

したがって、主張は「開始点にする」「外部で条件付けしない」「確信度で t0 を変える」ではなく、**運動経験から自己組織化した単位を、方策を固定したまま追加し続けることで、生の区間の記憶（RTS 型）より未見の運動・場面への汎化が良くなる**ことに置く。
LIBERO 閉ループでこの系統（取り出した行動から始める）が成功率を上げた報告は複数あり（RTS、OptimusVLA、LAFM）、実現性は肯定的である。

査読で突かれる点と対応：
- RTS・OptimusVLA との差が「生の区間を単位にまとめただけ」にならないよう、同じ経験・同じアクションヘッドで生の記憶と比べ、単位の寄与（値のシャッフル、同じ容量の生の記憶）を示す（S1・S2 の対照に追加済み）。
- 「外部で条件付けしない」は「スキル ID・スキルトークンを速度場へ別に入力しない」まで限定する。
- エントロピーによる t0 は小さな設計差にすぎないので、主張の芯にしない。
