## 0. 要点

1. arXiv 2603.03818 で扱われたモデルは **π0（3B）と GR00T N1.5** で、**π0.5 は含まれない**。系列は LIBERO の各 suite 内の10タスク。リプレイが1タスク1000サンプル（約20%）ならNBTはほぼ0だが、**2%（100サンプル）ではNBTが約0.1〜0.2残る**。方針の引用「少量のリプレイでほぼ忘れない」は、少なくとも「少量」と「π0.5」の部分で言い過ぎになっている。
2. この報告と食い違う結果もある。Stellar VLA v5では、**π0.5を1%リプレイで逐次学習した場合のNBTが38.4（Goal）と34.8（Long）**。Memory Anchorsでは、π0.5を全パラメータ微調整したLIBERO-GoalでNBTが0.45。2605.26820は実機で逐次微調整のBWTが−81と−69になったと報告し、シミュレーションでの耐忘却の一部はベンチマークと事前学習データの重なりや正規化統計の漏洩によるものだと指摘している。結論として、「忘れない」を主張の軸から外す方針は妥当。ただし根拠は「条件次第で忘却はリプレイで抑えられ、すでに主要な比較軸ではない」と書くのが正確。
3. LIBERO公式の生涯学習の設定：各タスク50デモ・50エポック、5エポックごとに20試行で評価、3シード、指標はFWT/NBT/AUC、比較は SeqL/ER/EWC/PackNet/MTL。勾配で学習することを前提に作られているため、勾配なしの追加ではFWTの定義を読み替える必要がある（§4.4）。
4. 提案：**LIBERO-90で導入学習した凍結ベース**に対し、**LIBERO-10とLIBERO-Skill（同じシーン群で既知の運動を組み合わせたタスク）を(a)の主系列**にする。**新しいシーンの系列としてSpatial/Object/Goal**を与える。(b)は既知の運動の幾何を変えたbddl変種で作る。LIBERO-40で学習した公開チェックポイントは、これら全suiteを学習済みなので、主評価には使えない。

**主な結果**（SR / NBT）：

- 回復：π0は元の学習ステップの約6〜11%でピークの成功率に戻る（表4）。BC-Tは33〜187%。
- 付録：スクラッチ学習ではモデルが大きいほどNBTが下がる（表10）。

**方針の引用の判定**：部分的に正確だが、そのままでは不正確。

- 正確な部分：事前学習済みVLAでは、ERを使うとスクラッチのBCよりはるかに忘れにくい。リプレイが十分（約20%）ならNBTはほぼ0。
- 不正確な部分：(i) 対象はπ0とGR00Tで、π0.5ではない。(ii)「少量」の2%ではNBTが0.1〜0.2、0.2%では0.58残る。アブストラクトの「sometimes … zero forgetting even with a small replay buffer」と導入の2%の例は、本文の表6と整合しない。(iii) リプレイなしの逐次学習ではVLAも大きく忘れる（表2）。
- 修正文案：「事前学習済みVLA（π0、GR00T N1.5）は、LIBEROのsuite内10タスクの逐次学習で、1タスク約20%のリプレイを使うとほぼ忘れないと報告されている（arXiv 2603.03818）。ただし2%以下のリプレイでは忘却が残り、π0.5で1%リプレイの場合にNBTが約35〜38という報告もある（Stellar VLA v5）。そのため忘却の抑制は既存手法で達成可能な比較軸とみなし、本研究の主張にはしない。」

## 2. LIBERO公式の生涯学習プロトコル

Liu et al., "LIBERO: Benchmarking Knowledge Transfer for Lifelong Robot Learning", NeurIPS 2023 Datasets and Benchmarks。[arXiv](https://arxiv.org/abs/2306.03310)、[HTML](https://arxiv.org/html/2306.03310)。会議名はarXivページに書かれておらず、既知の情報として記した。

| 項目 | 内容 |
| --- | --- |
| suite | LIBERO-Spatial／-Object／-Goal（各10タスク）、LIBERO-100（LIBERO-90は事前学習用、LIBERO-10（Long）は下流の生涯学習用）。合計130タスク |
| データ | 1タスク50本の人手テレオペデモ |
| 学習 | 1タスク50エポック、バッチサイズ32、Adam、学習率は1e-4から1e-5へcosine。BCでGMMヘッド。言語はBERT（CLIP、GPT-2、タスクIDに替えても有意差なし） |
| 評価 | 5エポックごとに20試行（最大600ステップ）で評価し、最良のチェックポイントを残す。各タスクの学習後に、既習の全タスクをそれぞれ20試行で評価する |
| シード | 100、200、300の3つ |
| 順序 | 主実験は固定順。別実験として**5通りの順序**をER/PackNet（ResNet-T）で比較し、順序の影響は有意（特にPackNet） |
| 指標 | c_{i,j,e}：i−1個のタスクを学習した後、タスクiをeエポック学習した時点でのタスクjの成功率。c_{i,i}はタスクiの最良成功率。**FWT_k = (1/11)Σ_{e∈{0,5,…,50}} c_{k,k,e}**、**NBT_k = (1/(K−k))Σ_{τ>k}(c_{k,k} − c_{τ,k})**、**AUC_k = (1/(K−k+1))(FWT_k + Σ_{τ>k} c_{τ,k})**。それぞれkで平均する |
| 比較 | SeqL（下限）、MTL（上限）、ER（1タスクあたり最大1000軌道を保存し、各イテレーションで32軌道を混ぜる、と要約された。「1タスクあたり」かは要確認）、EWC（λ=5·10⁴、γ=0.9）、PackNet（25%を剪定して50エポック再学習）。アーキテクチャはResNet-RNN、ResNet-T、ViT-T |
| 主な知見 | FWTはSeqLが最も高い。EWCはSeqLより悪い。PackNetはSpatial/Object/Goalで最強だが、LongではERが上回る。**LIBERO-90で単純な教師あり事前学習をすると下流の生涯学習が悪化することがある** |

**読み取れること**

- VLAの継続学習は二つの流派に分かれる。**suite内10タスクを公式またはランダムの順序で学習する**流派（2603.03818、Stellar、SCE、Optimus-R G.5、Memory Anchors）と、**LIBERO-90で事前学習してから下流の系列を学習する**流派（LIBERO公式のLIBERO-100、TAIL、CLARE、DMPEL、Stellar LIBERO-30\*）。本研究は導入学習が別にあるので、後者の形が自然。
- 少量データの追加はLOTUS系が標準で、**追加タスクは10デモ、リプレイは5デモ/タスク**。VLA系では1タスク数千〜1万ステップの勾配学習が普通で、**追加にかかる時間やデータ量を主要指標にした研究は見当たらない**（網羅的な検索ではない）。
- **タスク横断のスキル再利用を直接測る指標は、どの研究にも見当たらない**。FWTか、Optimus-R G.4のような特定の動作の成功率で間接的に示しているだけ。Simple Recipe WorksのZSが「未学習タスクへの効果」として最も近い。
- 試行数はLIBERO公式が20、Stellar/CLAREが100、SCEが50、Memory Anchorsが初期状態50個。論文ごとにばらつきがあり、同じ手法でも報告値が一致しない（π0.5のNBTは研究によって0.01から0.45まで開く）。**比較対象は自前で同じ条件で走らせる必要がある**。

## 4. 本研究の評価プロトコル案

### 4.1 前提：公開チェックポイントと漏洩

ローカルの文書とメタデータで確認した事実：

- `pi05_libero_moe_skill_4_40` は `jsw19/libero_40_v1` で学習されている。これは**Spatial、Object、Goal、10の4 suite・40タスク全部**にあたる（[libero_data_processing.md](../libero_data_processing.md)、`modified_libero_rlds` の4つのbuilder）。**このチェックポイントでは、どのLIBERO標準suiteも「新しい経験」にならない。** 使えるのは上限の参考値としてだけ。
- `pi05_libero_moe_skill_4_90` は `jsw19/libero_90_v1` で学習されている。LIBERO-90の言語指示は重複を除くと73種類で、学習用のスキル分割もこの73種類に対応する。LIBERO-10/Spatial/Object/Goalのタスクは含まない。
- LIBERO-Skillの9タスク（`public_task_manifest.json`）はLIBERO-90のシーンで2つの動作を組み合わせたタスク。ただし **`skill_obj_01`（LIVING_ROOM_SCENE2 put both the alphabet soup and the tomato sauce in the basket）はLIBERO-10のタスクと同じ**。LIBERO-40の重みはこのタスクを学習済み。
- `pi05_base` の事前学習データは「10k+ hours of robot data」としか公開されておらず、LIBEROを含むかは**未確認**（[openpi README](https://github.com/Physical-Intelligence/openpi)）。2605.26820はシミュレーションでの結果に事前学習データとの重なりがあると指摘している。

漏洩への対策：

1. ラベルなしで学習し直すベースは、**LIBERO-90だけ**で学習する（これを導入データと呼ぶ）。系列に使うsuiteのデモは、導入学習、PCAの当てはめ、追加のしきい値の分布推定、**行動・状態の正規化統計**のどれにも使わない。正規化統計は導入データで固定する（2605.26820が、将来のデータを含めた統計は漏洩になると指摘）。
2. 追加の前に、各系列タスクでのゼロショット成功率を、凍結ベース、メモリなし、`pi05_base` を直接使った場合のそれぞれで測る。ここが高いタスクは「新しい経験」とは呼ばず、別に集計する。
3. 評価に使う初期状態は、追加に使うデモの初期状態と重ならないようにする。LIBEROの初期状態50個と、RLDS（OpenVLAの再生成版）のデモの初期状態が重なっていないかは**未確認**なので確認が要る。重なる場合は、bddlのregionの範囲内で新しい初期状態を生成し、独立に評価する。
4. 評価用のラベルを分けて扱う。`instruct2plan_*.json` の運動クラス（pick、place、open drawerなど）は**評価・分析にだけ使い**、学習・キー・追加の判断には使わない。

### 4.2 系列（何をどの順で「新しい経験」にするか）

| 段階 | 内容 | 獲得の種類 |
| --- | --- | --- |
| 導入 | LIBERO-90（73指示、全シーン）でラベルなしのベースを学習し、メモリを初期化して凍結する | — |
| 系列A（主評価） | **LIBERO-10を公式順序で**追加し、続けて**LIBERO-Skillの`skill_obj_02`〜`09`**（`01`はLIBERO-10と重なるため除く）を追加する。LIBERO-90と同じシーン群で、既知の運動を組み合わせたタスク | 主に(a) |
| 系列B | **Spatial → Object → Goal**（各suite内は公式順序）。導入データにないシーンや配置。Objectは新しい物体の把持、Goalは同じシーンで目的だけが違う | (a)が中心で、一部は(b)と(c) |
| 系列C | 既知の運動の変種（§4.3で作る） | (b) |
| 対照 | 表現範囲外と予想される運動（Goalの "push the plate to the front of the stove" など。LIBERO-90に押す動作がないかは要確認） | (c)の負の対照。追加しても上がらないのが正しい結果 |

- 順序は、公式順序のほかに**ランダムな順序を2通り**加え、合計3通りで平均する（LIBERO公式とMemory Anchorsに合わせる）。suiteの順序も、A→Bの代わりにB→Aでも1回行う。
- 追加に使うデータは**1タスクあたり1、5、10デモ**の3水準（LOTUS系の10デモに合わせ、より少ない側にも広げる）。加えて、**ロボット自身が実行して成功した軌道だけを追加する**モードも用意する（方針の「実行された軌道だけを登録」に合わせる）。このモードでは成功判定を使っている点を明記する。
- 各タスクの追加は「デモ（または実行軌道）を凍結したEnc／キー関数に通して追記する」だけにする。追加の処理とパラメータのハッシュをログに残し、追加の前後で重みが変わっていないことを示す。

**言語なしのキーの弱点**：Goal（同じシーンで目的が違う）、Object（同じ配置で対象物を言語で指定）、LIBERO-10のLIVING_ROOM_SCENE2（2タスクが同じシーン）では、キーに言語を入れないと**同じ見た目から違う目的のzを取り出してブレンドしてしまう**恐れがある。この3つは言語なしのキーにとって困難な場面として分けて報告し、言語を入れたキーとの差をここで見る。言語はVLA本体には入力され続けるので、キーが運動の「やり方」だけを担えば破綻しないはず、という仮説を検証する場にする。

### 4.3 (a) と (b) の作り方

**(a) 新しい場面×既知の運動**：系列Aがそのまま該当する（LIBERO-90のシーンでの新しい組合せ）。系列BのSpatialは新しい配置、Objectは新しい物体の把持、と場面の変化の種類を分けて集計する。評価用の運動クラスで、各タスクの部分目標が導入データの運動クラスに含まれているかを事前に一覧にし、「既知の運動だけからなるタスク」を(a)の正式な集合とする。

**(b) 既知の運動の変種**：LIBEROのbddlを編集して、運動の幾何だけを変えたタスクを作る。

- 目標位置をずらす：put on plate → plateの位置を学習時の範囲外に置く。to the left/right of → 新しい相対位置。
- 高さを変える：top/middle/bottomの引き出しや、置き場所の棚の高さを変える。
- 把持対象の形を変える：同じpick-placeで、マグからボウルへ、など既知の物体の範囲内で変える。

範囲の判定は**評価用の運動特徴**（終点の変位、持ち上げ高さ、軌道長など。学習の特徴とは分ける）で行う。導入データの分布に対して、最近傍距離が上位5〜20パーセンタイルに入るものを(b)、それを超えるものを(c)寄りとして、**追加の前に固定**する。あわせて、凍結したEnc/Decでその変種のデモを再構成した誤差が導入データの範囲内であることを確かめ、「デコーダの表現範囲内」を操作的に確認する。

確認すること：(a)ではキーだけが追加され、新しいzはほぼ追加されないこと。(b)では新しいzが追加されること。この期待と実際の追加ログの一致率を報告する。

### 4.4 指標

LIBEROの成功率行列 c_{i,j}（i個目の追加後、タスクjの成功率）を、追加ごとに**既習タスク、まだ追加していない将来タスク、導入データ（LIBERO-90）から選んだ保持確認用の10タスク**で測る。

| 指標 | 定義 | 役割 |
| --- | --- | --- |
| 追加直後の成功率 | c_{k,k}。勾配なしなのでエポックの軸はなく、LIBEROのFWT_kの代わりにこの値を使う。勾配ありの比較対象では「同じ壁時計時間・同じデータ量のときのc_{k,k}」を対応させる | 主張1（その場で使える） |
| 追加による上昇 | Δ_k = c_{k,k} − c_{k−1,k}（追加前のゼロショットとの差） | 漏洩とベースの汎化を差し引く |
| データ効率 | 1/5/10デモでのc_{k,k}の曲線 | |
| 追加コスト | 1タスクあたりの壁時計時間、GPU秒、追加された項目数、保存バイト数、使ったデモ数。勾配ありの比較対象には**time-to-match**（凍結＋メモリのc_{k,k}に到達するまでのステップ数と時間）を測る | 主張1 |
| 旧タスクの保持 | LIBERO定義のNBT、導入データの保持確認タスクでの成功率 | 副次指標。「忘れない」とは主張せず、保持できていることだけを確認する |
| AUC | LIBEROのAUCで、FWT_kをc_{k,k}に置き換えたもの | 先行研究と並べるため |
| **タスク横断の再利用率** | (i) 重みの割合：成功したエピソードで、取り出した項目の重みαのうち、**現タスク以外から追加された項目**が占める割合。(ii) 因果的な効果：タスクsから追加された項目をマスクしたときのタスクtの成功率の低下 R_{s→t}。(iii) 将来タスクへの効果：c_{k,j}（j>k）がc_{0,j}より上がった量 | 主張2。(i)だけでは見かけの検索も数えてしまうので、(ii)を主指標にする |
| メモリの成長 | 1タスクあたりの追加件数、キーだけの追加とzの追加の比率、(a)(b)の期待との一致率 | 機構の検証 |

評価用の運動クラスごとに再利用の行列R（例：pickしてplaceする動作がタスクAからタスクBで使われたか）を集計すると、「運動として再利用された」ことを示しやすい。

### 4.5 比較対象（すべて同じ導入済みベース、同じ追加データ、同じ評価用初期状態で実行する）

| 比較対象 | 内容 | 何と切り分けるか |
| --- | --- | --- |
| メモリなし | 凍結ベースだけ | 下限 |
| 初期メモリのみ | 導入時のメモリを使い、追加しない | 追加の効果 |
| ランダムメモリ | 同じ件数で、キーとzの対応をシャッフルしたもの、またはzを導入データの分布からランダムに取ったもの | 検索の中身の効果 |
| 生の行動の検索（VINN/kNN型） | 取り出したデモの行動チャンクをそのまま実行する、またはブレンドする | zとデコーダを使う意味 |
| 逐次の全パラメータFT＋ER | 2603.03818の条件（1タスク約20%）とStellarの条件（1%）。学習量は1タスク1k/3k/10kステップの3点 | 勾配ありの上限と、時間・データの比較 |
| 逐次LoRA（±ER） | rankは16程度 | 軽量な勾配ありの比較 |
| MTL | 系列全体をまとめて学習 | 上限 |
| Optimus-R型 | key/valueのバンク。(i) 原著のStage C（残差、A_mem、温度を勾配で更新）、(ii) **全部固定して追記だけ**の版。(ii)は原著にないので、原著のablationとは呼ばない | 最も近い競合との差 |
| SkillMemo型 | 値をMoEゲート系列にしたメモリ | 運動の潜在を値にする意味 |
| 言語をキーに入れた版、ルーターだけにzを入れた版 | 方針で決めた比較 | 設計の検証 |

RICL、RA-VLA、Retrieval-VLAのような文脈内適応の比較は、[related_work_retrieval_memory.md](related_work_retrieval_memory.md) §9.1の判断に従い、余力に応じて加える。公式コードの有無（Optimus-R、SkillMemo）は今回**確認していない**。再実装する場合は、再実装であることを明記する。

### 4.6 試行数と統計

- 本評価：**1タスクにつき初期状態50個×1試行**、3通りの順序（またはシード）。1 suite・1条件で500試行になり、平均成功率の95%信頼区間はおよそ±4pp（成功率70%前後の場合）。
- 予備評価：1タスク20試行（LIBERO公式と同じ）。差が10pp未満の比較は本評価に回す。
- 手法間の比較では初期状態を揃え、対応のある比較（初期状態ごとの成功/失敗のMcNemar検定、またはタスク単位のブートストラップ）を行う。比較の数が多いので、主張に関わる主要な比較（凍結＋メモリと、ランダムメモリ／メモリなし／逐次LoRAの同時間比較）を事前に登録する。
- 時間の比較は、同じGPU・同じバッチ条件で、追加の処理（エンコードと索引の更新）と学習（勾配ステップ）の壁時計時間を測る。勾配ありの比較対象では、評価にかかる時間を含めない。

### 4.7 まだ決まっていないこと

- (b)の変種タスクの具体的な数値（ずらし幅など）と、範囲を判定するパーセンタイル。
- 系列Bを導入データから完全に切り離すかどうか。LIBERO-90とObjectには同じ物体（alphabet soup、ketchupなど）が出てくるので、「新しい場面」の程度は物体単位で記録する。
- 実行軌道を追加するモードでの成功判定の扱い（環境の報酬を使うか、自己判定にするか）。
