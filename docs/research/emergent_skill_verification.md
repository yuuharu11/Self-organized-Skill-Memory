# 創発スキルの最初の検証：アルゴリズムと判定基準

[emergent_skill_plan.md](emergent_skill_plan.md) の方針に従う最初の検証の具体化。
判定に使う z、合格の基準、最初の学習の範囲は、ユーザーの委任を受けて決めた（2026-10-25）。
実装・学習はまだ行っていない。

## 記号

- 観測 o_t（画像と言語指示）、固有感覚 s_t、行動チャンク A_t = a_{t:t+H}。H = 25（約1.25秒、本命）。比較として H = 10（SkillNetと同じ、約0.5秒）。replan_steps = 5。
- h_t：VLM（PaliGemma）の出力トークン。
- z_t：チャンクごとに1つの連続潜在（スキル表現）。

## 1. 学習（最小構成）

初期値は π0.5 の基本重み（skill ID を見ていない）。PaliGemma は凍結する。
action expert、Enc、Prior、z の注入部だけを学習する。データは LIBERO-90 のデモ。skill ID 列は入力に使わない。
正規化統計と、メモリのキーの PCA も LIBERO-90 で固定する。

LIBERO-40 で学習しない理由：LIBERO-40 は LIBERO の4 suite をすべて含む。
後から「新しい経験」として追加する LIBERO-10 と LIBERO-Skill を、学習から外しておく必要がある。
LIBERO-Skill の `skill_obj_01` は LIBERO-10 のタスクと同じなので、評価で重複させない。
評価の手順は [libero_lifelong_protocol.md](libero_lifelong_protocol.md) を参照。

```
各サンプル (o_t, s_t, A_t) について:
  h_t      = VLM(o_t)                         # 凍結
  q(z)     = Enc(A_t, s_t)                    # 事後分布。きれいな行動チャンクを見る
  p(z)     = Prior(pool(h_t), s_t)            # 事前分布。観測だけを見る
  z        ~ q(z)
  L_fm     = flow matching の損失( A_t | h_t, s_t, z )
             # z はルーターと、action expert の追加トークン1つに入れる
  L        = L_fm + β · KL( q(z) || p(z) )
```

KL によって、Enc の z が運べる情報を絞る。同時に、Prior が観測から同じ z を予測するよう学習させる。

## 2. 推論

```
h_t = VLM(o_t)
z_t = Prior(pool(h_t), s_t) の平均             # メモリなし
   または  z_t = メモリから検索・ブレンドした z   # メモリあり（§3）
A_t = action expert で h_t, s_t, z_t を条件に flow matching のサンプリング
先頭の replan_steps = 5 ステップだけ実行する
```

## 3. メモリ（勾配なしの追加と検索）

```
キー:  k_t = PCA( pool(VLM(o_t, 言語なし) の画像トークン), s_t )
       # PCA は基準データで一度当てはめて固定する
       # 画像と言語は双方向に注意し合うので、言語なしのキーには言語を空にした別の前向き計算が要る
値:    z_t = Enc(実際に実行した A_t, s_t) の平均    # 実行されなかった予測は登録しない

追加:  d   = k_t からメモリ内の最近傍までの距離
       τ   = メモリ内の項目どうしの最近傍距離の分布の分位点
       d > τ なら (k_t, z_t, メタ情報) を追加する      # パラメータは更新しない

検索:  上位 k 件 {(k_i, z_i)} をキーの距離で取る
       w_i = softmax( −距離_i / 温度 )
       z̄   = Σ w_i z_i  → 推論の z_t として使う
```

## 4. 最初の go/no-go

判定には、推論時に実際に使う z（Prior の z と、メモリから検索・ブレンドした z）を使う。
Enc の z は行動を見て作るので、運動と対応するのは自明に近い。参考値として出すだけにする。
運動の特徴（方向・回転・グリッパー）は、環境で実際に起きた手先の軌道から作る。
z の作成に使った入力とは別の情報にする。

| # | 指標 | 合格の目安 |
| --- | --- | --- |
| i | Prior の z と運動の特徴の相互情報量 | シャッフル基準の p95 と未学習モデルを明確に超え、かつタスクとの相互情報量を上回る |
| ii | 違うタスクの区間からの検索 | ランダムと正解の差の50%以上を埋める（参考：既存の内部特徴は約78%、固有感覚は約32%） |
| iii | 交差再構成 | 検索・ブレンドした z の誤差が、Prior の z の誤差より小さい |

3つとも満たせば、自己教師の項を1つずつ足す段階に進む。
満たさなければ、まず区間の長さ（H=25 と H=10 の比較）と β を疑う。

## 4.1 軽量版の go/no-go（先に行う）

本番の学習（§1、4設定×3万ステップ）は規模が大きいので、go/no-go はまず軽量版で判定する（2026-10-26 決定）。
凍結した π0.5 基本重みの PaliGemma から特徴を1回だけ抽出してキャッシュし、その上で小さな Enc・Prior・Dec を学習する。
データは LIBERO-40 の unsegmented 版から LIBERO-10 を除いた30タスク。判定基準は §4 と同じ。

```
f_t = pool(VLM(o_t) の画像トークン)        # 言語あり、凍結。Prior 用
k_t = pool(VLM(o_t, 言語なし) の画像トークン)  # メモリのキー用
q(z) = Enc(A_t, s_t)    p(z) = Prior(f_t, s_t)    Â_t = Dec(z, f_t, s_t)
L = ||Â_t − A_t||² + β · KL(q || p)        # β を3点振る。H=25 本命、H=10 比較
```

分からないこと：本物の action expert に入れたときに z が効くか、エキスパートの使い分け。
合格したら、本命設定だけを数千ステップ学習して確かめる。

**結果（2026-10-26、`emergent-light-20261026T054800Z-85a58f`）：全6設定で no-go。**
H=25・β=0.01 で i 合格（運動との相互情報量 1.19 bit、タスク 0.42 bit）、ii 合格（差の 59% を埋めた）、
iii 不合格（memory blend の誤差 0.041 が Prior の 0.036 より悪い）。β=0.1 は z が縮退（有効次元 0）。
評価は学習と同じ30タスクの別エピソードで、Prior が既に知っている条件だった。
メモリの役割を測るため、Prior に見せていない suite（spatial）で iii を測る追加評価（iii'）を行う。元の iii の不合格は撤回しない。
