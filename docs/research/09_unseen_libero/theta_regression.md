# θ回帰と型選択

## 結論

LoRAで学習し直した追試は、Devでcheckpoint・経路を選び、checkerも**合格**。正式に採用した `L-vlm` は θ_src からの誤差を下げ、定数θよりも低誤差だったが、事前基準のギャップ回収率50%には届かず**no-go**。回収率は `C_vm_none` で23.8% `[21.1,26.5]`、`C_vm_08` で36.9% `[30.0,42.7]`。この構成・データ・学習量では不足という判定であり、θ回帰一般の可能性を否定する結果ではない。

先行MLPの数字は数値照合済みだが、訓練内holdoutでモデル設定を選んでおり、指定Dev選択によるgo判定には使えない。この手順上の不備は今回のLoRA追試では解消した。LoRAの入力表現・集約・ヘッドはMLPと完全には揃っていないため、両者の差をLoRA更新だけの効果とは解釈しない。

型選択の代理評価では C_vm_08 のπ0.5由来姿勢がrandomより低誤差だったが、oracleとの差の区間は0を含み、候補集合も学習キャッシュ由来の部分集合である。完全な全メモリ検索の評価ではない。

## 条件

- 学習はLIBERO-40 `~validation` 23,304行。Dev 113行、Eval 619行（hard 134行）。凍結π0.5のthird-person画像・wrist画像・言語のprefix特徴、状態、型のDCT・長さ・窓位置を入力にした小型MLPを比較した。
- データ条件は `C_vm_none` と `C_vm_08`。予測対象は角軸θ、6Dθ、またはaction空間出力。`nowrist` / `wristonly` は視覚トークン群を除く入力対照。
- θ*は評価正解から作る上限診断。π姿勢はπ0.5出力を使った姿勢。正解はθ回帰モデルの学習や特徴生成に入れない。
- 実験2では窓ごとに型候補を選び、姿勢を分けて比較した。`pi05_shape` はπ0.5出力から型を選びπ由来姿勢で戻す。`oracle_shape_pi05_pose` は正解で型だけを選ぶ上限。`random5_pi05_pose` はランダム5候補を個別評価した誤差の平均で、行動をブレンドしない。

## 結果

### 実験1：θ回帰

| C_vm_none / R-6d-theta | .2116 / .3063 | .1793 / .2999 | .2142 / .3391 | .0030 / .0050 | −18.3% / −2.2% |
| C_vm_none / R-6d-act | .1862 / .3188 | .1793 / .2999 | .2142 / .3391 | .0030 / .0050 | −3.9% / −6.4% |
| C_vm_none / R-6d-act-nowrist | .2009 / .3484 | .1793 / .2999 | .2142 / .3391 | .0030 / .0050 | −12.2% / −16.5% |

### 実験2：型選択と復元姿勢

Evalのactive7正規化MSE（全 / hard）。同じπ姿勢での差はepisode bootstrap 95%区間。

| メモリ条件 | π0.5型選択 | random候補平均 | oracle型選択 | π選択−random（全Eval） | π選択−oracle（全Eval） |
|---|---:|---:|---:|---:|---:|
| C_vm_none | .5283 / .6916 | .5310 / .6286 | .4804 / .6176 | −.0027 `[−.0258,+.0216]` | +.0479 `[+.0219,+.0723]` |
| C_vm_08 | .4776 / .5655 | .5980 / .6662 | .4575 / .5140 | −.1204 `[−.1472,−.0920]` | +.0201 `[−.0050,+.0464]` |

ここでoracle型選択は正解で型を選ぶ。π選択のC_vm_08はrandomより良かったが、oracleとの差の95%区間は0を含む。C_vm_noneではπ選択とrandomの区間が0を含む。通常π0.5は .3639 / .4494。

### 実験3：LoRAでθ回帰を学習し直す

初期値は公開 `pi05_libero`。rank 16、固定seed、batch 8、AdamW（学習率 .0001、weight decay .00001）、global norm clip 1、最大4,000 updates。`L-vlm` はPaliGemma後半の層6/18のAttention・MLPにLoRAとθヘッドを付け、先頭12層は勾配・optimizer更新をマスク。`L-expert` はaction expert側のLoRAとθヘッドを学習。500 updatesごとに保存し、Dev 113行の復元後行動MSEで選んだ。

| メモリ | Devで選択 | Dev MSE | Eval MSE 全 / hard | θ_srcからの回収率 全 / hard | 定数θとの差（全Eval） | 判定 |
|---|---|---:|---:|---:|---:|---|
| C_vm_none | L-vlm、2,500 updates | .141813 | .137296 / .240154 | 23.8% `[21.1,26.5]` / 20.3% `[16.6,24.2]` | −.123685 `[−.146754,−.103833]` | no-go |
| C_vm_08 | L-vlm、4,000 updates | .138108 | .153342 / .280458 | 36.9% `[30.0,42.7]` / 23.9% `[7.7,37.3]` | −.107064 `[−.134460,−.084208]` | no-go |

両条件で、選ばれたLoRAはθ_src、π0.5姿勢、従来MLPより低いEval MSEだった。しかし「θ_src–θ*ギャップの50%以上を回収し、訓練平均の定数θよりも低誤差」という事前基準を満たさなかった。checkerは4条件のMSE・区間・回収率を独立再計算して一致を確認し、Dev選択経路でのno-goを妥当と判定した。未学習正解の学習漏洩・Evalによる再選択は確認されていない。

## 読むときの注意

- **先行MLPの選択手順**：checkerは、指定Devではなく訓練内holdoutでモデルを選んだと指摘した。先行10条件の数値は独立再計算に一致するが、Dev選択による正式なgo判定としては使わない。LoRA追試はDevで選択し直しており、その事前基準でno-go。
- 未学習Evalの正解漏洩は確認されなかった。θ*は上限であり、実行時に利用できる姿勢ではない。
- 実験2の候補はキャッシュにある学習由来のsource unitを重複除去した部分集合。全メモリを単位境界を越えて復元した候補集合の評価ではない。
- θ回帰のEval結果は行動誤差で、閉ループの成功率ではない。差が有意でない条件を同等とは解釈しない。
- LoRAとMLPは特徴集約・観測マスク・ヘッドが異なる。LoRAの優位を重み更新方式だけに帰属しない。
- reviewerは実験2のrandomが候補出力を平均していた問題を修正し、候補を混ぜずに個別採点するよう変更。予測θと正解θによる姿勢診断も分けた。
