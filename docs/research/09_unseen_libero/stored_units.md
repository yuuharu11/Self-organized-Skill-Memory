# 保存した単位だけで戻す

## 結論

メモリに保存した単位をそのまま当てると、未学習タスクでは**固定10窓が可変長より良い**。同じくらいの単位数で比べると、固定 τ=.16（81単位）は .0850 / .1523、可変 ε=.005 τ=.16（64単位）は .1319 / .1956。

まとめ方では、誤差基準が M6 より良い。固定10窓で、誤差基準の81単位は難しい行で .1523、M6 の41単位は .2008（全行は同程度）。ただし単位数は誤差基準のほうが2倍ある。

圧縮そのものの損失は小さい。固定10窓のまとめない場合で、生 .0340 / .0816、DCT 3 .0379 / .0858。

## 条件

- 問い合わせ側の正解は、単位の選択と採点だけに使う。切れ目にも、向きと大きさにも使わない。検索とデノイズはなし。
- 単位は向きと大きさを含めて保存し、保存された長さのまま当てる。伸縮しない。単位が終わると次を選ぶ。
- 選び方：次のフレームを正解で見て、誤差 τ 以内で最も長い単位。なければ誤差が最小の単位。τ はまとめと同じ値で、まとめない場合は .04、M6 は .08。
- 未学習の評価619行（難しい134行）、LIBERO-40の400デモ。表現は DCT 3個。

## 読むときの注意

- 選択は正解を見た上限で、実際の検索の性能ではない。
- 可変の選び方は長い単位を優先するので、誤差を最小にしているわけではない。規則は1通りで調整していない。
- 単位数と1回で進むフレームが揃っていない。比較は近いものどうし。
- 難しい行は固定の生の最良距離で決めているので、固定の生に不利に選ばれている。
- Long は未実施。
