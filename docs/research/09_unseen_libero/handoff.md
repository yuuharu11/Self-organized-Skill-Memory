# 引き継ぎ：未学習タスクでの運動単位とデノイズ

## 目的と方針

π0.5（`pi05_libero`）の運動スキルメモリを、LIBERO-40 で作り、公開微調整データに含まれない LIBERO-90 の10タスクで評価する。デモから可変長の運動の核を切り出して保存し、向きや大きさはデノイズで場面に合わせる、というのがユーザーの考え。

守ること（ユーザーの指示）：

- **未学習デモの正解は、単位の選択と採点だけに使う。** 切れ目、向きと大きさ、圧縮には使わない。
- **検索はしない。** 検索の影響を除き、正解に一番近い単位を選んだ上限を見る。
- 可変長は確定方針。圧縮は容量ではなく特徴抽出のため。
- 報告は日本語。文書のファイル名と本文に日付を書かない。

## データ

- メモリ：LIBERO-40 の400デモ（各タスク10本、6,583窓）。`run-01` の `memory` 行。
- 評価：未学習10タスクの100デモ、619行（難しい行134。メモリの生の行動で一番近いものでも遠い行）。開発用は別の2タスク20デモ（113行）。
- Expert の学習行：LIBERO-40 の `~validation` 23,304行。
- 指標：正規化した行動の active7 MSE。「全行 / 難しい行」で書く。
- 通常 π0.5 の閉ループ成功率は 32/100（[baseline_results.md](baseline_results.md)）。

## デノイズ前に分かったこと

正解で単位を選んだ上限。数字は全行 / 難しい行。

1. **誤差の大部分は、未学習の動きがメモリにないことによる。** 生の行動をまとめずに借りても .0340 / .0816。各動きを自分自身の値で戻すときの圧縮の損失は .003〜.01 で、ごく一部（[variable_length_error.md](variable_length_error.md)）。
2. **圧縮法の差は小さい。** DCT、PCA、M1 codec、キーフレームは、同じまとめ方ならほぼ同じ。DCT の個数を増やしても変わらない（[compression_compare.md](compression_compare.md)、[dct_coefficients.md](dct_coefficients.md)）。
3. **まとめるほど悪化する。** 誤差は τ（まとめの許容誤差）でほぼ決まる。誤差基準のまとめは M6 より難しい行で良いが、単位数は多い（[stored_units.md](stored_units.md)）。
4. **可変長は、切り方次第。** 再構成誤差で切ると固定10窓より悪い。**速度の極小点とグリッパーの切替で切ると、初めて固定より良い**（まとめない4,516単位 .0344 / .0685、固定6,583単位 .0379 / .0858。τ=.08 で247単位 .0614 / .1069、固定329単位 .0633 / .1278）（[motion_core.md](motion_core.md)）。
5. **手先座標は強くまとめたときだけ効く。グリッパーを動きから分けると、動きの誤差が約15%下がる**（分けたグリッパーの当て方は未実装）。
6. **向きと大きさを除くと誤差は大きく下がるが、当てる方法がない。** 正解から与えると .0461 / .0901、通常 π0.5 の出力から取ると .2016 / .3320（[skill_draft.md](skill_draft.md)）。この形の結果は診断扱い。

## デノイズ後に分かったこと（最重要）

既存の Expert（action head のコピー、LIBERO-40 で学習、`t0∈U[.2,.6]`）17本の評価。17条件すべて完了（結果は `oracle-01/predictions/<条件>/result.json`、まとめの文書はまだない）。正解で選んだ下書きを `x=(1−t0)·下書き+t0·ε` からデノイズした出力の MSE：

| 下書き | 下書き | t0=.05 | t0=.2 | t0=.4 | t0=.6 | t0=1 |
|---|---:|---:|---:|---:|---:|---:|
| 生、まとめない | .0340 / .0816 | .0345 / .0822 | .0484 / .1009 | .1066 / .1699 | .1895 / .2771 | .3499 / .4244 |
| PCA 24、まとめない | .0338 / .0811 | .0342 / .0817 | .0485 / .1012 | .1063 / .1717 | .1885 / .2769 | .3482 / .4260 |
| 生、M6（42単位） | .0826 / .1986 | .0830 / .1989 | .1000 / .2148 | .1621 / .2751 | .2258 / .3361 | .3400 / .4119 |
| ゼロの下書き | .2874 / — | .3091 / .3763 | .3476 / .4506 | .3727 / .4552 | .3634 / .4439 | .3507 / .4220 |

通常 π0.5 は .3639 / .4494。

**未学習タスクでは、デノイズで下書きより良くなる t0 がない。** ノイズを増やすほど、Expert 自身の出力（t0=1、通常 π0.5 とほぼ同じ）へ近づいて悪化する。Long（既知タスク）では下書きの距離が .04 程度までなら t0=.2 で大きく改善したが、これは Expert が正解を知っているタスクでの話だった。今の Expert は「下書きを直す」のではなく「自分の答えへ引き戻す」働きをしている。

レビューの判定は「要修正」。b12 のシャッフル対照だけ、候補行の特徴と状態で復元されていて不公平。主な MSE は独立に再計算して一致している。

## 寝ている間にやりたいこと

### 今回の結果

- 圧縮下書き＋デノイズの開発選択条件では、白色ノイズ `A-vm-none` が全Eval .03349 / hard .06939、下書き .03506 / .07172。最終値は下書きよりわずかに低い（全Eval差 −.00156、95%区間 [−.00208,−.00104]）。低周波DCTノイズは同じ下書きの白色条件より悪く、k=3で全Eval差 +.00112 [+.00097,+.00129]、hard +.00233 [+.00190,+.00279]。低周波条件は Claude が実装し、Checker は「合格」、reviewer は「妥当」。詳細は [圧縮表現から始めるデノイズ](compressed_denoise.md)。
+- 正解を見て選ぶ17条件の比較では、最良の未統合下書きは生 .04842 / .10093、PCA24 .04847 / .10122（全 / hard）で、通常π0.5は .36387 / .44941。どの条件も選択t0=.2で生成後誤差が下書きより大きく、デノイズで悪化した。これは検索器の性能ではなく、候補選択の上限。b12 M6のシャッフル対照は単位長が揃わず不公平とレビューされたため、比較の結論には使わない。詳細は [表現ごとのoracle下書き](oracle_results.md)。
+- **次の一手**：Expertやノイズ基底を先に増やさず、実行時に利用可能なキーで、別タスクの候補から生または低損失圧縮下書きを選ぶ検索を改善する。評価はoracleと分け、Dev固定・自タスク除外を保ち、生成後MSEが下書きMSEを下げるかを確認する。現状の値は閉ループ成功率を示さない。
