# 引き継ぎ：未学習タスクでの運動単位メモリ

この流れを引き継ぐ人向けに、目的、守ること、分かったこと、未解決の点、次の一手をまとめます。
結果を作り直す手順は [再現手順](reproduce.md) にあります。

## 目的と方針

π0.5（`pi05_libero`）の運動スキルメモリを LIBERO-40 で作り、公開微調整データに含まれない LIBERO-90 の10タスクで評価する。デモから可変長の運動の核を切り出して保存し、向きや大きさは場面に合わせる。

守ること：

- **未学習デモの正解は、単位の選択（上限の診断）と採点だけに使う。** 切れ目、向きと大きさ、圧縮、モデル選択には使わない。
- **行動は常にスキル（メモリの型）から作る。** スキルを補助入力にする案は採らない。
- 可変長は確定方針。圧縮は容量ではなく特徴抽出のため。
- 比較には必ず「直前の行動を保つ」などの自明な基準を入れる。π0.5 との差だけで判断しない。
- 文書のファイル名と本文に日付を書かない。

## データと指標

- メモリ：LIBERO-40 の400デモ（各タスク10本）。速度の極小点とグリッパーの切替で切ると 4,516 単位。
- 学習行：LIBERO-40 の `~validation` 23,304 行。保留8タスク [2, 7, 12, 17, 22, 27, 32, 37] は選択用で、候補からも除く。
- 評価：未学習10タスクの100デモ、619窓（難しい行134）。Dev は別の2タスク20デモ（113窓）。
- 指標：正規化した行動の MSE（active7、または6軸＋グリッパー）。「全行 / 難しい行」で書く。閉ループは10タスク×初期状態0〜9の成功数。
- 通常 π0.5 の閉ループは 32/100（[baseline_results.md](baseline_results.md)）。

## 分かったこと

順に読むと流れが分かります。詳細は各文書。

1. **誤差の大部分は、未学習の動きがメモリにないこと。** 正解で選んでも生の行動で .034 / .082。圧縮の損失は .003〜.01（[variable_length_error.md](variable_length_error.md)）。圧縮法の差は小さい（[compression_compare.md](compression_compare.md)）。速度の極小点で切ると可変長が固定窓より良い（[motion_core.md](motion_core.md)）。
2. **デノイズは下書きを直さない。** 既存 Expert、白色ノイズ、低周波ノイズで学習した Expert のどれも、未学習タスクで下書きより良くならない。ノイズを増やすほど π0.5 自身の答えへ近づく（[oracle_results.md](oracle_results.md)、[compressed_denoise.md](compressed_denoise.md)）。
3. **型は十分で、律速は θ と型の選び方。** 正解の θ と正解の型なら .003 まで下がる。θ を観測から回帰しても、LoRA で学習しても、型の出どころの θ から大きくは良くならない（[theta_regression.md](theta_regression.md)）。
4. **型を選ぶ入力は「直前の実行行動＋状態」が一番効く。** 差の 57〜63% を埋める。VLM の特徴は保留タスクでは効くが、未学習では効かない（[motion_query.md](motion_query.md)）。
5. **θ のデノイズも Expert での仕上げも、未学習では効かない。** LoRA θ の見かけの良さは、ほぼ動かない予測による（[theta_flow.md](theta_flow.md)）。
6. **閉ループで初めて π0.5 を上回った。** τ=.04〜.08 でまとめた単位メモリの型を π0.5 の出力に合わせると、未学習 LIBERO-90 で 43/100（π0.5 32、対で +14 / −3）。ただし学習済みの LIBERO-10 では 11〜19/50（π0.5 46）。下書きを公開 Expert でデノイズすると、LIBERO-10 は 47/50 に戻るが LIBERO-90 は 33〜35/100 に戻る（[closed_loop_unit_memory.md](closed_loop_unit_memory.md)）。

## 未解決の点

- **τ はテストで選んだ。** 43/100 は同じ100試行で4条件を比べた最良値。τ を保留タスクか Dev で決めてから1回だけ評価し直す必要がある。
- **得意な場面で壊れる。** LIBERO-10 で型が足を引っ張る理由（型の選び方か、θ の合わせ方か）は切り分けていない。メモリを使うか π0.5 のままにするかを決める仕組みがない。選択の確信度は当たり外れを見分けない。
- **グリッパーの切替時刻（G2）** は未着手。切替のある19%の行で誤差の大半が出る。
- 新しいコード（K1〜K4、`theta_flow.py`、`expert_refine.py`、`unit_retrieval.py`、`cluster_pools.py`、`memory_closed_loop.py`）は、K1 と K2 を除いてテストとレビューが済んでいない。
- 主評価は RoboCasa365 に移る予定（[10_robocasa365](../10_robocasa365/README.md)）。

2. LIBERO-10 で、メモリを使う・使わないの切り替え（π0.5 との一致度など、正解を使わない指標）を試す。
