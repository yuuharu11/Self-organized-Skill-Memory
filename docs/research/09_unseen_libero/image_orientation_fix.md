# 未学習行の画像の向きの修正

オフラインで使ってきた未学習 LIBERO-90 の行（Dev 113 窓、Eval 619 窓）の画像が、180度回っていた。
直した行を新しい場所に作り、画像から作る入力を取り直して、軽い比較（π0.5 そのまま、S1、π0.5 出力の最近傍）を採点し直した。
重い学習を伴う比較は、まだ取り直していない（下の表で「保留」）。

## 何が間違っていたか

- LIBERO の HDF5 デモは、カメラ画像をシミュレータが描いたままの向き（上下左右が逆）で持っている。
  閉ループ（`worker.py` が動かす `anchor_flow/run_case.py`）は、π0.5 に渡す前に `obs[...][::-1, ::-1]` で180度回している。
- 未学習行を作る `prepare_oracle.py prepare` は、HDF5 の `agentview_rgb` と `eye_in_hand_rgb` を回さずに入力変換に通していた。
  そのため `oracle-01/unseen_rows/` の `image_base` と `image_wrist`（732 行）は上下逆だった。
- 影響を受けないもの：LIBERO-40 の学習行（`run-01/rows`）は正しい向き。閉ループの評価は毎ステップの観測を正しく回している。
  行動、状態、指示文、窓の切り方、難しい行の定義は画像を使わないので変わらない。

## どう見つけたか

[実験一覧 5](experiments.md#5-型をどう選ぶかクエリ) の F1（π0-FAST の出力をクエリに使う）の診断で、画像を180度戻して π0.5 を走らせ直すと、6軸 MSE が .192 から .114 に、変位の向きと正解のコサインが .12 から .72 に変わった。
そこで LIBERO-40 の行と未学習行の画像を並べて目で見比べ、未学習行だけが逆さであることを確かめた。

## 直したこと

- `prepare_oracle.py` が HDF5 のフレームを `unseen_paths.orient_libero_frame`（`[::-1, ::-1]`、閉ループと同じ）で回してから入力変換に通すようにした。
- 直した行は新しい場所 `.skillnet-state/outputs/memory-pilot/unseen-libero/unseen-rows-02/` に書いた。旧い行 `oracle-01/unseen_rows/` は監査用にそのまま残した。
- 置き場所は `unseen_paths.py` の `UNSEEN_ROWS` 一か所にまとめ、未学習行を読む全スクリプトがそこを読むようにした。
- 直した行は、旧い行の画像をちょうど180度回したものと全画素一致し、画像以外の配列は旧い行と完全に一致した。
  テスト `tests/test_unseen_image_orientation.py` は、直した行が「生の HDF5 フレームに閉ループと同じ変換をかけたもの」と一致することを確かめる。
- 取り直しは `orientation_fix.py`（出力 `orientation-fix-01/`）。旧い行で同じ計算をすると、保存済みの K1 の π0.5 予測（差 5e-4 以内、float16 の丸め）と θ 回帰の VLM 平均（差 0）を再現した。
  π0.5 の固定ノイズは以前と同じ（K1 の鍵 `fold_in(4101, 行番号)` と、`official_normal_eval` の鍵 `fold_in(4101, 26581 + 行番号)` の両方）。
- S1 は `scale_only_query.py refresh` で新しい実行 `scale-only-02/` を作った。LIBERO-40 側（プール、学習入力、教師、学習済みクエリ、保留タスクでの選択）は `scale-only-01` のまま写し、Dev/Eval の VLM 平均と π0.5 の入力だけを差し替えた。
  新しく P0（VLM 平均だけ）を P6 と同じ学習・選択（LIBERO-40 保留タスク、3 seed、目標の鋭さ 3 通り）で学習した。Eval は選択に使っていない。

## 取り直した主な数値

6軸 MSE（全体 / 難しい行）、W（10フレーム窓）、S-shared、保留タスクで選んだ学習クエリ（3 seed 平均）。相関は、各 Eval 窓で候補のスコアと −（正解との型誤差）の Spearman の平均。

- **π0.5 そのものは、直した画像で直前保持と並ぶ**（差 +.000 [−.012, +.014]）。難しい行では直前保持より悪い（.251 対 .201）。
- **VLM 平均も π0.5 の出力も、未学習タスクで次の動きの向きを持っている。** P0 の Spearman は .04 → .54、π0.5 出力の最近傍は .08 → .65 で、履歴（P5 .66）に近い。
- **それでも直前保持をはっきり超えるものはない。** 最良は P5 × π0.5 の大きさ（.107 / .214、直前保持との差 −.007 [−.015, +.003]、難しい行 +.013 [−.019, +.046]）。VLM を足した P6 は P5 より悪いまま（.122 対 .111）。
- U（可変長単位）でも π0.5 そのままは .197 / .333 → .125 / .283、R-so3 × θπ0.5 は .286 → .210 になったが、直前保持（.116 / .158）は超えない。
- S-sep、R-so3 を含む全表と 95% 区間は `scale-only-02/production/report.md`。P5 は π0.5 の大きさを使う規則以外で、旧い実行と全行一致した。
- P6 の「Dev で選んだ状態」は、旧い（逆さの）Dev 特徴で選ばれたまま（保留タスクで選んだ主表には影響しない）。

## 保留している取り直し

重い学習を伴うので、まだ回していない。どれも、直した行（`UNSEEN_ROWS`）を読むので、そのまま回せば直した画像で計算される。

- K1〜K4 の VLM・Expert・π0.5 出力を使うクエリ（`key_query_probe.py` の `extract` 以降、`key_query_k2.py`、`k3_query.py`、`k4_query.py`）。
- θ 回帰（MLP と LoRA）、LoRA θ の型への当てはめ、θ のフローマッチング、Expert での仕上げ（`theta_regression.py`、`theta_regression_lora.py`、`lora_theta_on_selected.py`、`theta_flow.py`、`expert_refine.py`）。
- Expert のデノイズ（`compressed_denoise.py`、`low_freq_denoise.py`）と、oracle 下書きの Expert 生成（`oracle_experiment.py`）。
- M1 b12 の下書き（`oracle_experiment.py drafts`、`draft_reconstruction.py`、`compression_compare.py`）と、π0.5 から向きと大きさを取る下書き（`dct_skill_draft_eval.py`）。
- S1 の P6 を Dev で選んだ変種。
