# 運動単位の定義を変える（デノイズ前）

## 結論

外部から受けた提案のうち、デノイズ前に正解の向きと大きさを使わずに試せるものを比べた。

- **速度の極小点とグリッパーの切替で切ると、可変長で初めて固定10窓より良くなった。** まとめないとき4,516単位で .0344 / .0685（固定6,583単位 .0379 / .0858）、τ=.08 で247単位 .0614 / .1069（固定329単位 .0633 / .1278）。動き6軸だけでは、全行はほぼ同じで難しい行が良い（τ=.08 で .0710 / .1232、固定 .0666 / .1394）。
- **手先座標は、強くまとめたときだけ効く。** 固定 τ=.16 で .0812 / .1405（世界座標 .0850 / .1523）、誤差で切る τ=.08 で .0651 / .1098（.0712 / .1263）。まとめないときは少し悪い。
- **グリッパーを分けると、動きの誤差は約15%下がる。** 固定まとめないで .0384 から .0326、τ=.08 で .0666 から .0559。グリッパーが動きの照合を歪めていたことになる。ただし、分けたグリッパーの当て方は未実装で、全7軸の値は使えない（グリッパー一致 .6〜.7）。
- **再利用のされやすさで切り直しても（2回の交互最適化）、誤差で切るのと変わらなかった。**
- 選ぶ間隔を20フレームに揃えると、可変はどれも固定より良い（例：速度極小 まとめない .0543 / .1055、固定 .0664 / .1240）。

## 条件

- 未学習の評価619行（難しい134行）、LIBERO-40の400デモ。表現は DCT 3個。問い合わせ側の正解は単位の選択と採点だけに使う。検索とデノイズはなし。単位は向きと大きさを含めて保存したまま当てる。
- 選び方：10フレーム（伸縮なし）または20フレーム（伸縮あり）に1回の回数で、全体の誤差が最小の並び（動的計画法）。グリッパーを分ける条件では、動き6軸だけで選ぶ。
- 手先座標：各窓の先頭の状態（手先姿勢）で、行動の移動と回転を手先座標に回して保存し、使うときに問い合わせの状態で戻す。状態は実行時に分かる。
- 速度極小：平滑化した手先速度の極小点とグリッパーの切替で切る。最短5フレーム。
- 切り直し：誤差で切った区間から単位を作り、メモリのデモをその単位の最適な並びで切り直す（15フレームに1回の回数、2回）。
- ADE は窓内で移動を積分した位置の平均誤差、FDE は窓の終端の誤差（物理の行動単位）。向き cos と大きさ比は窓の総移動で測る。
- 区間推定はしていない。条件は結果を見る前に決めたが、結論の行は結果を見てから選んだ。Long は未実施。

## 試していない提案

- 向きと大きさ、直線成分、弧長での正規化：使うときに正解の動きが必要で、今回の条件（正解は選択と採点だけ）に合わない。
- 速度場との整合性、デノイズ後の誤差：デノイズを使うので対象外。
