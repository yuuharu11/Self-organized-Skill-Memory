# DCTの誤差基準でまとめる

## 結論

M6 の代わりに、切り出しと同じ誤差基準で区間をまとめた。向きと大きさを除いた可変長（ε=.005）で、**40単位で .0544 / .1021、161単位で .0414 / .0753**（全行 / 難しい行）。M6 の18単位 .0620 / .1536、捨てない460単位 .0370 / .0691 より、少ない単位で誤差が小さいか同等である。正解の向きと大きさを与えた上限で、デノイズで合わせられるかは未確認。

同じ統合で比べると、可変長は固定10窓より単位数が少なく誤差も小さい（161単位 .0414 / .0753、固定 189単位 .0460 / .0900）。ただし全行の差の多くはグリッパーの誤差で、移動と回転はほぼ同じである。

## 統合の手順

1. 区間ごとに向きと大きさを除いた DCT の値を持つ。
2. 区間 i を代表 j の形と i 自身の向きと大きさで戻したときの誤差を計算する。DCT は直交変換なので、重みの差からそのまま求まる（テストで復号の誤差と一致を確認）。グリッパーも誤差に含める。
3. 誤差 τ 以内で戻せる未カバーの区間が最も多い区間を代表に選ぶ。
4. 全区間がカバーされるまで3を繰り返す。

単位数は τ から決まり、区間は捨てない。代表は実在の区間で、1区間だけの単位も残る。

## 読むときの注意

- 対象、メモリ、選び方は [向きと大きさを除いてまとめる](variable_shape_memory.md) と同じ。正解で代表を選ぶ上限で、検索とデノイズはなし。
- τ はメモリの中で満たす誤差で、未学習の行では τ を保証しない。
- τ は評価行を見ずに決めた格子で、選んでいない。単位数が揃わないので、比較は近いものどうし。区間推定と多重比較の補正はしていない。
- 可変は固定より選択回数も少ない（ε=.005 で522回、固定で619回）。可変の問い合わせの切れ目は正解の動きから作っている。
- Long は未実施。
