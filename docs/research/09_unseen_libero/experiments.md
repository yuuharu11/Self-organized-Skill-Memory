- **未学習タスクの選び方：** LIBERO-90 から、公開 `pi05_libero` の微調整データ（LIBERO-40）と指示文が同じタスクと Long と同じ場面を除き、残り53タスク・11場面から seed 20261106 で各場面1タスクを機械的に選んだ。成功率を見て選び直していない。「未学習」は公開微調整データ外という意味で、基盤モデルの事前学習まで含めて未見かは確認できない。

## 2. メモリに未学習の動きはあるか（正解で選ぶ上限）

問い：LIBERO-40 のメモリから、正解に一番近い単位を選んで当てると、どこまで誤差が下がるか。どの段階で誤差が出るか。検索もデノイズもしない。

### やり方

1. デモを単位に切る。固定10フレーム窓、または可変長（DCT 3個で戻した誤差が ε を超えたら切る／速度の極小点とグリッパーの切替で切る）。切り出しは [segmentation_demo](segmentation_demo/README.md) で動画に重ねて確認した。
2. 単位を圧縮する（生、DCT、PCA、M1、キーフレーム）。
3. 似た単位をまとめる。M6（クラスタ）、または切り出しと同じ誤差基準 τ の貪欲被覆（区間を捨てない）。
4. 未学習デモの各窓で、正解に一番近い単位を選び、当てて採点する。

### 結果（active7、全体 / 難しい行）

| 段階 | 条件 | 単位数 | 誤差 |
|---|---|---:|---:|
| 圧縮だけ（メモリを使わず自分を戻す） | 固定10窓 DCT 3 | — | .0065 / .0092 |
| | 可変 ε=.005 DCT 3 | — | .0032 / .0033 |
| メモリから借りる、まとめない | 固定10窓 生 | 6,583 | .0340 / .0816 |
| | 固定10窓 DCT 3 | 6,583 | .0379 / .0858 |
| | 誤差で切った可変 DCT 3 | 3,215 | .0409 / .0795 |
| | **速度極小＋グリッパーで切った可変 DCT 3** | 4,516 | **.0344 / .0685** |
| メモリから借りる、τ=.08 でまとめる | 固定10窓 DCT 3 | 329 | .0633 / .1278 |
| | 速度極小＋グリッパー | 247 | .0614 / .1069 |
| 向きと大きさを正解から与える（上限） | 可変 ε=.005、RMS で正規化、まとめない | 3,215 | .0235 / .0471 |
| | 同、誤差基準 τ=.08 | 161 | .0414 / .0753 |
| 参考 | 通常 π0.5 の出力（直した画像） | — | .1413 / .2870 |

圧縮法の比較（固定10窓、まとめない → τ=.16）：生 .0340 → .0796、DCT 3 .0379 → .0834、PCA 12 .0397 → .0839、PCA 24 .0338 → .0805、M1 b12 .0374 → .0809†、キーフレーム3 .0404 → .0842。

### 分かったこと

- **誤差の大部分は「未学習の動きがメモリにない」こと。** 圧縮の損失は .003〜.01 で、正解で選んでも借りた動きの誤差 .034 が残る。
- **圧縮法の差は小さい。** 誤差はまとめの強さでほぼ決まる。DCT の個数（2〜5）を変えてもほとんど変わらない。保存する値の総数で見ると PCA 12 と M1 b12 が有利。
- **可変長が固定窓より良くなったのは、速度の極小点で切ったときだけ。** 誤差で切る可変長は、切れ目に正解を使えば良く見えるが、メモリの単位をそのまま当てると固定窓に負ける（τ=.16 で可変64単位 .1319 / .1956、固定81単位 .0850 / .1523）。選ぶ間隔を20フレームに揃えると可変はどれも固定より良い。
- **向きと大きさを外した「型」にすると、少ない単位で誤差が下がる。** ただし下がるのは移動で、回転はほとんど下がらない。まとめ方は M6 より誤差基準が良い（少ない単位で同等以下、区間を捨てない）。
- **グリッパーを分けると動きの誤差は約15%下がる**が、分けたグリッパーの当て方は未実装。
- 手先座標は強くまとめたときだけ少し効く。再利用のされやすさで切り直しても変わらない。

出力：`draft-reconstruction-01/`（`variable_length.json`、`variable_memory.json`、`variable_shape.json`、`dct_tolerance_merge.json`、`stored_units.json`、`optimal_units.json`、`compression_compare.json`、`dct_coefficients.json`、`motion_core.json`、`skill_draft.json`）、`oracle-01/`

## 3. デノイズは下書きを直すか

問い：正解で選んだ単位の下書きを、π0.5 の Expert で `x=(1−t0)·下書き+t0·ε` から戻すと、下書きより良くなるか。

### やり方

- 既存 Expert（公開 `pi05_libero`）を下書きごとに最大4,000更新で学習し、重みと t0 は Dev で選ぶ（17条件）。
- 圧縮表現の下書きで、白色ノイズと低周波ノイズ（DCT 最初の k 係数に射影）を比べる。

### 結果（active7、全体 / 難しい行）

| 条件 | 下書き | デノイズ後 |
|---|---:|---:|
| 生、まとめない（t0=.2） | .0340 / .0816 | .0484 / .1009† |
| 生、M6（t0=.2） | .0826 / .1986 | .1000 / .2148† |
| 向きと大きさを除いた可変、白色ノイズ（t0=.05） | .0351 / .0717 | .0335 / .0694† |
| 同、低周波ノイズ k=3 | .0351 / .0717 | .0346 / .0717† |

### 分かったこと

- **デノイズは下書きを直さない。** 17条件すべてで、選ばれた t0=.2 の生成後は下書きより悪い。白色ノイズで小さい t0 にすると −.0016 だけ下がる程度。低周波ノイズは白色を上回らない。
- ノイズを増やすほど π0.5 自身の答えへ引き戻される。閉ループでも同じ向き（[6](#6-単位メモリの閉ループ)）。
- ランダム下書きとの比較（C-rand-08）は単位長が揃わず、結論には使わない。

出力：`oracle-01/`、`compressed-denoise-01/`（低周波は `production-lowfreq/`）

## 4. 向きと大きさ（θ）を推論時に決められるか

問い：型（向きと大きさを除いた動き）を選んだ後、場面に置く θ（回転3＋対数スケール1）を、観測から決められるか。

### やり方

- θ 回帰：凍結 VLM の特徴＋状態＋型から MLP で θ を回帰。LoRA で π0.5 ごと学習し直す版も（Dev で選択、事前基準は「θ_src から θ* までの差の50%以上を埋める」）。
- θ のデノイズ：flow（ノイズから）、bridge（型の出どころの θ から）、回帰を同じネットで比べる。
- π0.5 の出力に Procrustes で合わせた θ も比べる。

### 結果（6軸＋G1 グリッパー、全体 / 難しい行、型は oracle / 履歴で選んだ型）

| θ の決め方 | oracle の型 | 履歴で選んだ型 |
|---|---:|---:|
| θ*（正解に合わせる、上限） | .088 / .129 | .110 / .202 |
| LoRA θ† | .186 / .297 | .187 / .297 |
| bridge† | .206 / .345 | .201 / .323 |
| flow† | .205 / .327 | .207 / .331 |
| 回帰† | .221 / .370 | .217 / .331 |
| π0.5 の出力に合わせる† | .244 / .370 | .237 / .360 |
| 型の出どころの θ | .261 / .378 | .245 / .384 |

基準（6軸）：直前の行動を保つ .114 / .201。

### 分かったこと

- **正解の θ なら型は十分**（θ* と oracle の型で active7 .003 まで下がる）。**推論時に作れる θ では差がほぼ消える。**
- LoRA θ は事前基準に届かず no-go（差の回収率 23.8% / 36.9%）。.186 は「ほぼ動かない予測」（振幅が正解の3割、型によらず同じ値）による。
- θ のデノイズは保留タスクでは良い（flow .041）が、未学習では悪化する。
- 下書きを Expert で仕上げても、どの θ でも改善しない（t0 を上げるほど悪化）。
- π0.5 から θ を取る下書きは、π0.5 の方向の誤りもそのまま移す。

出力：`theta-regression-01/`（LoRA は `lora/`）、`theta-flow-01/`、`expert-refine-01/`

## 5. 型をどう選ぶか（クエリ）

問い：推論時に手に入る入力（画像、指示文、状態、自分の実行行動の記録、π0.5 の内部特徴や出力）だけで、メモリから正しい型を選べるか。

### やり方

- 候補：LIBERO-40 の10フレームの型 1,595 個（W）、または速度極小で切った可変長単位 3,504 個（U）。保留タスク由来は除く。
- クエリ（入力 → MLP）とキー（型 → MLP）のコサインで並べ、型誤差から作る分布を目標に listwise 学習。自タスクの候補は除く。設定は保留タスクで選ぶ。
- 指標：選んだ型の誤差が random から oracle までの差を何割埋めたか（回収率）、候補の並びと正解の Spearman、最終の行動 MSE。

### 実験と結果

| 実験 | 何を比べたか | 主な結果 |
|---|---|---|
| K1 | 入力の総当たり：履歴＋状態（P5）、VLM 平均（P0）、トークン注目、中間層、Expert、π0.5 出力（P4）、ボトルネック | 回収率は P5 63% が最良。P0 31%†、P4 32%† |
| K2 | VLM 18層と Expert の各層 | 最良は VLM 17層 56%†。保留タスクで最良の層は未学習で 35%† |
| K3・K4 | 進捗・正規化履歴・長い履歴・カメラ別の注目・画像差分 | 厳しい top1 はどれも 15〜29% の帯。方式間の差は学習の揺れの範囲 |
| 可変長単位での検索 | U から次の単位を選ぶ | 学習クエリで回収率 53%。直前の単位の「次」をたどるだけでは 22%。確信度は当たり外れを見分けない |
| S1 | 型から大きさだけ消す（S-shared / S-sep）か、回転も消すか（R-so3） | 向きを残す S-shared が R-so3 より 6軸で .06〜.10 良い。大きさは6軸で1つでよい |
| F1 | π0-FAST の出力を学習なしのクエリに | Spearman .346 で π0.5 出力（.078）より良いが、直前保持にも P5 にも負ける。ここで画像が180度回っていたことを見つけた |

### 最終の行動 MSE（S-shared、W、6軸、全体 / 難しい行、直した画像）

| 型の選び方 | 誤差 | 候補の並び（Spearman） |
|---|---:|---:|
| 直前の行動を保つ（基準） | .114 / .201 | — |
| π0.5 そのまま | .114 / .251 | — |
| random | .251 / .351 | — |
| VLM 平均（P0） | .139 / .276 | .541 |
| π0.5 出力の最近傍（学習なし） | .134 / .280 | .649 |
| VLM 平均＋履歴＋状態（P6） | .122 / .246 | .588 |
| 履歴＋状態（P5） | .111 / .226 | .658 |
| P5、大きさを π0.5 から | .107 / .214 | — |
| oracle 型（上限） | .079 / .164 | — |

R-so3（回転も消す型）を P5 で選ぶと .199 / .317。U でも順位は同じで、P5 × π0.5 の大きさ .124 / .215 に対し直前保持 .116 / .158。

### 分かったこと

- **いちばん効く入力は「直前10ステップの実行行動＋今の状態」（履歴）。**
- **画像を直すと、VLM 平均も π0.5 の出力も次の動きの向きを持つ**（Spearman .04 → .54、.08 → .65）。旧い結論「VLM の特徴は未学習で効かない」は、画像の向きによる部分が大きい。K1〜K4 の VLM を使う数値は取り直していない。
- **それでも直前保持をはっきり超えるものはない。** 最良の P5 × π0.5 の大きさでも差 −.007 [−.015, +.003]。
- oracle 型なら .079 なので、型の価値はある。律速は選び方。
- 画像を使うクエリの探索（履歴と π0.5 出力の最近傍を足すと Spearman .683、交差注目のクエリ X1）は進行中。

出力：`key-query-01/`〜`key-query-04/`、`unit-retrieval-01/`、`scale-only-01/`・`scale-only-02/`（直した画像）、`fast-query-01/`、`orientation-fix-01/`。関連研究は [運動クエリの調査](../surveys/motion_query_survey.md)。

## 6. 単位メモリの閉ループ

問い：DCT 可変長の単位メモリで、未学習 LIBERO-90 を閉ループで解けるか。

### やり方

- **メモリ：** LIBERO-40 のデモを速度の極小点とグリッパーの切替で切り（最短5フレーム）、向きと大きさを除いて各軸 DCT 3個＋グリッパー1個で保存。τ を与えた条件は誤差基準でまとめる。保留タスク由来は除く。
- **選び方：** 直前10ステップの実行行動＋状態のクエリ（P5 と同じ形）を、メモリごとに LIBERO-40 で学習し直す。
- **実行：** 毎回 π0.5 を通常どおり動かし、選んだ型をその出力に Procrustes（回転と単一スケール）で合わせて6軸に使う。グリッパーは π0.5。5ステップごとに選び直す。
- 基準と同じ初期状態・seed。LIBERO-10 では、各タスクと同じタスク由来の単位を候補から外す。

### 結果

| 条件 | 未学習 LIBERO-90（100） | タスク別（0, 10, 13, 31, 35, 43, 57, 61, 84, 88） | LIBERO-10（50） |
|---|---:|---|---:|
| 通常 π0.5 | 32 | 0 10 0 0 1 1 10 10 0 0 | 46 |
| π0.5 の出力を DCT 3個に落とす（メモリなし） | 34 | 1 10 0 1 1 1 10 10 0 0 | 47 |
| 窓の断片メモリ（1,595個） | 39 | 6 10 0 2 2 0 9 10 0 0 | 20 |
| 単位メモリ、まとめない（3,504個） | 27 | 3 9 0 2 1 1 1 10 0 0 | 19 |
| 単位メモリ、τ=.04（282個） | **43** | 6 9 2 4 1 2 9 10 0 0 | 11 |
| 単位メモリ、τ=.08（95個） | **43** | 5 10 0 5 0 4 9 10 0 0 | 17 |
| 単位メモリ、τ=.16（31個） | 33 | 3 9 0 3 0 3 6 9 0 0 | 14 |
| τ=.08 ＋ Expert でデノイズ t0=.2 | 35 | 1 10 0 3 0 1 10 10 0 0 | 37 |
| τ=.08 ＋ Expert でデノイズ t0=.4 | 34 | 2 10 0 1 0 1 10 10 0 0 | **47** |
| τ=.08 ＋ Expert でデノイズ t0=.6 | 33 | 1 10 0 0 0 2 10 10 0 0 | 45 |

### 分かったこと

- τ=.04 と .08 は π0.5 と対にして、メモリだけ成功 14、π0.5 だけ成功 3（正確二項検定 p=.013、4条件の多重比較は補正なし）。
- 上積みは π0.5 が苦手なタスク（引き出し 0、棚の上へボウル 31・43）で出て、π0.5 が解けるタスクはほぼ落とさない。DCT 3個の粗さだけでは 34 なので、効いているのはメモリの型。
- まとめないと 27 で π0.5 より悪い。まとめすぎ（31個）は 33。オフラインの回収率（まとめない 55%、τ=.08 76%）と同じ向きで、候補を減らすと選びやすくなる。
- **LIBERO-10（π0.5 が学習済み）では 11〜19/50 に落ちる。** 得意な場面では型が足を引っ張る。
- **Expert でデノイズすると得意・不得意が入れ替わる。** LIBERO-10 は 47 に戻るが、LIBERO-90 の上積みは消える。両方で良い t0 はない。
- **τ はテストで選んだ値**（同じ100試行で4条件を比べた最良）。厳密には保留タスクか Dev で τ を決めてから1回だけ評価し直す必要がある。
- 推論時の入力は画像、指示文、状態、自分の実行行動、π0.5 の出力、LIBERO-40 のメモリだけ。π0.5 の出力を向きと大きさ・グリッパーに使っているので、メモリ単独の方策ではない。

出力：`cluster-pools-01/`、`closed-loop-memory-01/`。LIBERO-10 の成功数は `report` では 0/0 と表示されるので、各試行の `result.json` を数える（[再現手順](reproduce.md)）。
