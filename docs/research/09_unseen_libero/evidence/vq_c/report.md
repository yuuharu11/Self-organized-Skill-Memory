# VQ-C：運動の選択に要る幾何の上限

**結論**：シミュレータの真の幾何（目標物体の手先からの相対位置・距離・接触・把持、どの目標を狙う段階か）をクエリに足しても、未学習の検索は良くならない。むしろ悪くなる（20 Hz の未学習行で C1b .0517 → .0543〜.0602、3 seed、対の差の 95% CI はすべて 0 より上）。学習済みでは良くなる（.0421 → .0365〜.0382、最初の単位 .075 → .039〜.054）。幾何は学習した 40 場面を見分ける手がかりとしては効くが、新しいタスクに移せる「目標に向かう」規則としては使われていない。上限で効かなかったので、手順 2（観測から幾何を推定する）は行わない。
**この幾何は特権情報で、診断のための上限。提案の主表には入れない。**

あわせて、評価行の不具合を見つけた（§0）。未学習 Eval と旧 Dev は記憶側の半分の刻み（10 Hz）で作られていた。20 Hz に作り直すと、未学習の C1b は .0863 → .0522 になり、**直前保持（.0470）のほうが良い**。

## 0. 旧 10 Hz 行と 20 Hz 行（先に読むこと）
LIBERO-40（メモリ 4,516 単位・学習行 12,766・学習済み 621）は LeRobot のフレームで、これは HDF5 から no-op を除いた 20 Hz の制御ステップそのもの。440 エピソードすべてで、OpenVLA の規則で no-op を除くと行動が HDF5 と完全一致し、長さも一致した。LIBERO-90 の未学習 619 行と旧 Dev 217 行は、unseen-rows-02 の規則で HDF5 を 1 つおきに取っていた（frame f → step 2f、履歴・正解も 2 おき）＝10 Hz。手先の移動量は、LIBERO-40 で .0063 m／フレーム、旧未学習行で .0134 m／フレーム。10 ステップの窓は、未学習では 1 秒、メモリでは 0.5 秒だった。
同じ開始時刻で 20 Hz に作り直した（開始＝2f 以降で最初の no-op でないステップ、no-op を除いた連続 10 ステップ、正規化は従来どおり。619／217 行、欠落なし）。既存のチェックポイントを採点し直しただけで、学習はしていない。旧行の値は完全に再現した。

## 1. 手順 1：特権幾何の上限
### 幾何の作り方
- LIBERO-40 の sim 状態はローカルになかった。HF の公式 LIBERO HDF5（yifengzhu-hf/LIBERO-datasets、40 ファイル）から `actions`／`states`／`obs/ee_pos` だけを HTTP の範囲読み出しで取得した（画像は読まない。保存 271 MB）。LeRobot エピソードとデモは、no-op を除いた行動の完全一致で対応づけた（440／440、誤差 0、重複なし）。LeRobot の状態と HDF5 の手先位置をアフィンで当てはめると R² .97〜.999。LIBERO-90 はローカルの HDF5 を使った。
- 目標の規則：タスクの BDDL の `:goal` 原子を順に読む。On/In(a, b) は a、b の順、Open/Close/Turnon/Turnoff(x) は x。重複を除いて最初の 4 個を取る。物体は本体の位置、領域名はそのサイトの位置を使う。各行の特徴は 29 次元：4 枠 ×（手先からの xyz、距離、有効、指の接触）＋把持（両指が目標物体に接触）＋注目点（最初に満たされていない goal 原子の、未把持なら動かす物体、把持中なら置き先）の xyz と距離。
- 「focus」は注目点 4 個＋把持 1 個の 5 次元。「slots」は 4 枠＋把持の 25 次元。
- クエリ：C1b の塔（88→512→GELU→256）の隠れ層に FiLM をかける（γ, β＝MLP(幾何)、最終層は 0 で初期化するので、初期状態は C1b と一致）。キーは X1 固定。学習は C1b と同じ（eh 12,766 行、τ .01、同場面の負例、lr 1e-4、16 epoch、拡張なし）。
- 選択：VQ-A の Dev v2（20 Hz、12 タスク 667 行）で epoch を選んだ（行名 `_v2`）。旧 Dev で選んだ行も並べた。幾何は Dev v2 の行にも付けた。

## 2. なぜ効かないか（数字から）
1. **幾何は新しい情報ではある**：履歴＋状態から MLP で注目点の xyz を当てると、学習済みでは R² .72 だが未学習では .35、距離は −.10。把持だけは状態で既に分かる（AUC .99。指の開きだけでも .96〜.97）。足した数値のうち新しいのは「目標がどこにあるか」で、把持の有無はすでに入力に入っていた。
2. **幾何は運動の向きと関係している**：未来 10 ステップの平均移動方向と注目点方向の cos は、未学習で .66（行の 67% が .7 超）、学習行で .56。直前の運動との cos（学習行 .73）より低いが、関係はある。
3. **しかしクエリは、幾何を場面の見分けに使っている**：テスト時に幾何を行の間で入れ替えると、どの行も大きく悪化する（学習済み .036 → .079、未学習 20 Hz .060 → .100）。幾何を平均値にした場合は、学習済み .036 → .055 と悪化するが、未学習 20 Hz では .060 → .064（focus Dev v2 は .055 → .066、29 次元 Dev v2 は .0615 → .0611）とほぼ変わらない。学習済みでは幾何の中身が効いているのに、未学習では平均値を入れても同じ程度にしか働いていない。
4. **「似た幾何なら似た運動」は新しいタスクに移らない**（k 近傍で直接確かめた。学習行から k=10、未来の腕行動の平均）：履歴＋状態の近傍は学習済み .0385／未学習 20 Hz .0636。幾何 29 次元の近傍は .0430／.1328、focus 5 次元は .0622／.1314。学習済みでは幾何だけで履歴並みに当たるが、未学習では直前保持の 2.8 倍悪い。同じ相対位置でも、対象（ボウル、引き出し、電子レンジ、本）や接近の仕方が違えば次の運動は違う。40 場面からは、相対位置を運動に写す規則が場面ごとの暗記としてしか学べない。
5. **選択を誤る原因は目標の位置ではない**：20 Hz で C1b が直前保持に負けるのは、連続区間と最初の単位。切替・向き変化の直後では C1b が勝ち、幾何を足してもそこはほぼ変わらない（+.002〜+.004）。未学習で外す主因は「どこへ向かうか」ではなく、「今の運動を続けるか、別の単位に替えるか」の判断と、単位の形と大きさの細部にある、と読むのが数字と合う。

## 3. 定義と手順
- 部分集合（採点のみ、未来は定義にだけ使う）：最初の単位＝有効な履歴が 0。切替直後＝履歴の窓の中でグリッパー指令が変わる、または履歴の最後と正解の最初で符号が違う。向き変化＝直近 5 履歴の xyz 平均と、正解 10 ステップの xyz 平均の cos < .5（両方のノルム > .1、正規化単位）。post＝切替∪向き変化。
- 対の差：seed 平均の行ごと誤差の差を、(task, episode) 単位の bootstrap（2,000 回）で求めた。
- Dev：最初は旧 Dev（10 Hz、2 タスク）で seed 1 の探索をした。途中から VQ-A の Dev v2（20 Hz、667 行、未学習 20 Hz との順位相関 .956）で 3 seed を選び直した。dev20（旧 Dev の 20 Hz 版）での学習は Dev v2 ができたので途中で止め、結果に使っていない。
- コード：`unseen_libero/vq_geometry.py`（fetch40／align40／geometry／rows／ablate／rate20／compare／geo_devv2／final）。テスト：`tests/unseen_libero/test_vq_geometry.py`（6 件通過）。
- 成果物：results.json（主表・部分集合・対の差）、rate_comparison.json（§0）、unseen20_eval.json、ablation.json（Dev v2 の行。旧 Dev の行の値は本文 §2-3）、probe_hs_to_geo.txt、direction_analysis.txt、knn_transfer.txt、timescale_check.txt、align40.json、geometry/、hdf5_states/（ダウンロードした HDF5 の一部、271 MB）、unseen20/、dev20/、rows/。
- ダウンロード：HF yifengzhu-hf/LIBERO-datasets の libero_{10,goal,object,spatial}/*.hdf5 から、範囲読み出しで states・actions・obs/ee_pos だけを取得した（画像なし）。
