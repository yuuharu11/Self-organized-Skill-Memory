# VQ-B：画像と言語を分けて FiLM で入れる

## 結論
- **どの源を FiLM で入れても、未学習 20Hz の全体では FiLM なし（C1b と同じ学習）を超えなかった。** Dev v2 20Hz で選んだ最良の L1b（LLM 前の指示文埋め込み）は未学習 .0535 ± .0016 で、none .0517 より +.0017 [+.0006, +.0028] 悪い。直前保持 .0470 にはどの行も届かない。
- **LLM の前で取った源は害が小さく、π0.5 の VLM 出力から取った源は未学習を大きく壊す。** VLM 出力の画像（I2）は学習済みを .0421 → .0336 に下げるが、未学習を .0517 → .0785 に上げる（+.0268 [+.022, +.032]）。Dev は epoch 2 を選んでおり、学習が進むほど悪くなる。LLM 前の画像（I1r）は全体で ±0（+.0013 [−.0006, +.0033]）。
- **画像は最初の単位の行で効く。言語は効かない。** 最初の単位（履歴なし 100 行）で、I1r は none より −.0192 [−.0255, −.0130] 良い（.0720 → .0528）。L1b＋I1r も −.0179。これに対し、言語だけ（L1b）は +.0026 [−.0014, +.0062] で効果がない。それでも最初の単位では、0 行動を出す直前保持（.0500）とほぼ同じ水準にとどまる。
- 学習済みと未学習の差は源の「LLM を通った度合い」で決まる：none .0096、L1b .0115、I1r .0131、I2 .0449、L1a .0514（seed 1）。

## なぜそうなったか
1. **VLM 出力は「どのタスクか」を強く運ぶ。** タスク ID の 1-NN（自 episode 抜き）は、VLM 出力の指示文位置 L1a で学習行 .93、学習済み .83 に達する。π0.5 の prefix は双方向で、指示文のトークンが画像も見るためだ。画像は VLM 出力 I2 で .70、LLM 前 I1 で .77、履歴＋状態 HS で .54。FiLM はこの手がかりで LIBERO-40 の 20 タスクを当て、学習済みでは .034 まで下がる。
2. **未学習では、その手がかりが間違ったタスクを指す。** 評価時に条件を学習行の平均（中立な FiLM）に置き換えると、未学習では全モデルで良くなる：I2 .0791 → .0769、L1a .0854 → .0720、I1r .0534 → .0498、L1b＋I1r .0550 → .0488。学習済みではすべて悪くなる（I2 .034 → .076）。行間で条件を入れ替えると、両方で大きく悪化する。つまり条件は効いているが、未学習ではそれが別の LIBERO-40 タスクの運動への偏りとして働く。
3. **VLM 出力は過学習が速い。** I2・L1a・I2r の Dev 最良は epoch 2〜4 で、学習損失は none より速く下がる（10Hz 時点：L1a 2.65 対 none 3.16）。LLM 前の源は epoch 10〜16 まで Dev が下がり続ける。
4. **言語だけでは最初の単位を助けない。** L1b・L1c は1タスクにつき1本の固定ベクトルなので、FiLM はタスクごとの一定のずれになる。未学習の指示文は学習済みの指示文と別物で、最近傍との cos は Dev .72、未学習 .68（L1b、標準化後）。最初の単位では none .072 に対し L1b .075、L1c（seed 1）.076 で、評価時に学習平均へ置き換えると .064 になる。言語は「何をするか」を運ぶが、未学習の新しい指示文を既存の運動に写す手段にはなっていない。
5. **画像は最初の単位で効く。** 履歴のない行では、クエリは状態しか持たない。開始時の画像（物の配置）は、どちら向きに動き出すかの手がかりになる（−.019）。履歴がある行では、直前の運動が強い手がかりで、画像は足しても変わらないか、少し害になる。
6. **γ／β の大きさは学習済みと未学習で同程度**（例：I1r の平均 |γ| は .117 と .122）。未学習で FiLM が弱まるわけではなく、同じ強さで違う方向へ動かしている（上の 2）。
7. **Dev と未学習で、条件を使うべきかの判断が逆になる。** Dev v2 では条件をそのまま使う方がすべてのモデルで良い（例：L1b＋I1r .0565 対 学習平均 .0587）。Dev の条件は学習条件に少し近い（最近傍 cos、I1r：Dev .640、未学習 .616。L1b：.720 と .682）。このため Dev は L1b を選んだが、未学習では none のほうが良い。順位の食い違いは小さい（L1b と none の差 .0017）。それでも、Dev v2 も条件の効き方を楽観的に見せる点は注意が要る。

## 気になる点・確認したこと
- **10Hz ずれ：** 途中で判明したため、選択を Dev v2 20Hz、主表を unseen20 にして全条件を学習し直した。10Hz 選択の旧スイープは sweep_10hz_dev/ に残すが参考のみ。学習行（LIBERO-40）は元から 20Hz で影響なし。
- **開始時刻のずれ：** 20Hz の開始は「2·frame 以上の最初の非 no-op ステップ」。私の 20Hz 特徴はこの時刻の画像で取り直した。10Hz の特徴と違う行は unseen 6/619、Dev v2 6/667、旧 Dev 1/217 で、すべて episode 冒頭（frame 0）の no-op。**VQ-A の Dev v2 20Hz の VLM トークンはこの 6 行だけ 2·frame の画像のまま**（行番号で旧トークンを使い回すため）。影響は小さいが、正確ではない。
- **画像の向き・経路：** 自分の抽出は既存キャッシュと cos ≥ .9999995 で一致。目視でもロボットが上。
- **解像度：** LIBERO-40 は 256px、LIBERO-90 は 128px。学習側を 128px にそろえても特徴は行ごとの cos .9986 でほぼ同じで、学習済みと未学習の判別 AUC は .99〜1.0 のまま（場面が違うため）。そろえた I1r は I1 より未学習でわずかに良い（.0534 対 .0561、seed 1）が、主因ではない。
- **評価時に中立条件にする案は採用していない。** 「FiLM 付きで学習し、評価時は条件を学習平均にする」案は、未学習で .0488（L1b＋I1r、seed 1）と none より良く見える。しかしこれは Eval の診断から出た案で、Dev v2 では逆に悪い。規則に従って採らず、次の仮説として残す。
- 再現：FiLM なしを旧 Dev で学習すると、C1b seed 1 と同じ値（10Hz 未学習 .0836、学習済み .0412）になった。
