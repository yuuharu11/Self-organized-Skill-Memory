# VQ-A：VLM を絞って FiLM で入れる（＋新 Dev）

## 結論
- **VLM を FiLM で入れても、未学習（20 Hz）で C1b を超えなかった。** FiLM が行ごとに働く設定（γ・β が行によって変わる）は、すべて未学習で悪化した（.056〜.089、C1b は .0522）。一方で学習済みは良くなった（.026〜.037、C1b は .0425）。
- 良く見える設定は、VIB の KL を強くして z が潰れた行だけだった。KL 1.0 の 3 seed で未学習 .0515 ± .0018。このとき γ・β は全行でほぼ同じ値（行間 sd .001）になっていて、FiLM は定数の写像に退化している。中身は「C1b にスケールを掛けただけ」で、VLM は使われていない。C1b との差 −.0007 [−.0015, +.0001] も 0 をまたぐ。
- 直前保持（.0470）には、どの行も未学習全体で勝てない。勝てるのは切り替え直後と向きの変わる行だけ（直前保持 .066／.107 に対し C1b .035／.069）。
- 最初の単位の行（未学習 100 行）では、VLM を自由に通す行が C1b より良い（プーリング d=32 は .0617、C1b は .0720。連結 E-VLM+H のキー微調整は .0549）。ただし、どれも「何も動かさない」予測（直前保持は履歴がないので 0 を出す、.0500）に届かない。
- 新 Dev（Dev v2、20 Hz）は未学習 20 Hz との順位相関が .956 で、旧 Dev（10 Hz で .764、20 Hz で .872）より良い。

## 0. 時間軸の修正と注意点
- 旧 unseen 619・旧 Dev・Dev v2 の最初の版は、HDF5 を 1 フレームおき（10 Hz）に取っていた。メモリは 20 Hz なので、10 歩の目標が 2 倍の時間を覆っていた（VQ-C が発見）。主表は 20 Hz に作り直した unseen20（VQ-C 作成）で出す。旧 10 Hz の値は「旧（10Hz ずれあり）」の列に残す。選択は Dev v2 20 Hz で行った。10 Hz の Dev で選んだ最初のグリッド（rows/、4 行）は使っていない。
- **トークンの画像と開始時刻がずれている行がある（Dev v2 20 Hz で 6/667 行、unseen20 で 6/619 行）。** episode 冒頭の no-op で開始が 1〜11 ステップ後ろにずれた frame 0 の行で、トークンは 10 Hz 時点（ずれる前）の画像のまま。VQ-B が指摘し、vq-b-01/feats/ に取り直してある。Dev の 6 行を除いて計算し直しても、Dev の上位 3 設定の順は同じで、全 40 設定の Dev 値の Spearman は .9996 だった。選択は変わらないので、再学習はしていない。
- Dev v2 を 10 Hz から 20 Hz に作り直した規則は、VQ-C の vq_geometry.build_rate_matched と同じ。C1b の 3 seed の unseen20（.0509／.0519／.0537）は VQ-C の .0520 と一致した。

## 3. なぜ VLM の FiLM は未学習で効かないか
1. **FiLM が行ごとに働くほど、学習済みは良くなり、未学習は悪くなる。** 学習済みと未学習の差は、C1b では +.0096、自由な FiLM では +.041〜+.063 だった。γ・β の行間 sd は、VIB なしで .78〜.98（h のノルムに対する変化量は 2.7〜6.8 倍）、KL .1 で .14〜.22（差 +.021〜+.023）、KL .3 以上で .004 以下（差 +.009）。差と行間 sd は単調に並んでいる。
2. **絞っても場面を覚えられる。** z から k-NN（episode を抜いて評価）でタスクを当てる精度は、未学習 20 Hz（10 タスク、偶然 .10）で、VIB なしの z が .54〜.66 だった。元のプーリング VLM（2048 次元）の .79 より低いが、履歴（70 次元）の .47 より高い。d=2 まで絞るとタスクは当たらなくなる（.14）。それでも未学習は .0744 で悪いままだった。つまり、害は「タスク ID が読めること」だけではない。z は LIBERO-40 の場面ごとの「位置→運動」の対応を切り替えるスイッチになり、未学習の場面ではそのスイッチが外れる。KQ-final で、拡張ありのモデルが状態に頼って崩れたのと同じ形だ。
3. **言語だけ・画像だけ・手首だけに分けても同じ。** K=1, d=8 で、未学習／学習済みは、言語だけで .0869／.0355、画像だけで .0883／.0264、手首だけで .0878／.0269 だった。どのソースでも、LIBERO-40 の 40 場面を見分けるには足りてしまう。手首カメラに限っても防げない。
4. **VIB は、効く手前で z を消してしまう。** KL .1 では z が少し残り（行間 sd .14〜.22）、学習済みは良く（.036〜.037）、未学習は悪い（.0575〜.0604）。KL .3 以上では z が潰れ、C1b と同じ振る舞いになる（未学習 .0505〜.0515）。その間に「未学習で効く量だけ VLM を残す」帯は見つからなかった。学習目標（LIBERO-40 内の教師）にとっては場面を覚えるのが最短なので、絞りの強さだけで汎化側に寄せることはできない。
5. **最初の単位だけは VLM が役に立つ。** 履歴がない行では、場面の情報が「どちら向きに動き出すか」の手がかりになる（C1b より −.011）。ただし、この行の正解は小さい動きが多く、何も動かさない予測が最良になる。VLM は動き出しの大きさまでは当てていない。
6. KQ-final の 66 行では、未学習 10 Hz と 20 Hz の順位相関が .92 で、VLM 系が C1b に負ける結論は時間軸の修正で変わらない。ただし、直前保持との関係は逆転した。10 Hz では直前保持（.114）が最下位だったが、20 Hz では最良になった。

## 4. 疑わしい点・限界
- Dev v2 の 1 位（KL .1, d=8, seed 1）は未学習で .0604 と悪い。Dev の上位どうしの差（.0005 前後）は seed 間の幅の中にあり、Dev v2 でも C1b 周辺の細かい差は見分けられない。
- 未学習 20 Hz の部分集合は小さい（向き変化は 17 行）ので、区間は広い。
- 直前保持は、未学習と Dev v2 では C1b より良く、学習済みでは悪い。「メモリから引く」こと自体の利得は、切り替えの行に集中している。
- 「最初の単位」での直前保持は 0 を出すだけの予測で、メモリを使っていない。
- KL .3 以上の行の未学習 .0505 は、C1b より −.0016〜−.0017 [−.0027, −.0007] 良い（seed 1 本）。ただしこれは FiLM が定数になった結果で、C1b の出力に固定の線形変換を掛けて正規化したものと同じだ。VLM の効果ではない。3 seed の KL 1 では差が 0 をまたいだ。
