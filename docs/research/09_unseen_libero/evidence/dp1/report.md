## 解釈上の注意

N は現在の状態・VLM 平均・履歴と下書きを含み、Δ 版は選択単位の開始時観測との差を追加入力する。Ridge α は Dev の補正 MSE で選択し、MLP は seed 4101 の固定学習設定。結果はオフラインの10ステップ評価であり、Expert への接続や閉ループ性能を示さない。
## 解釈（最終チェックで追記）

- 下書きは KEY2-F P5 の top-1 と一致した（learned .04072／unseen .10545）。修正前の版は、P5 のメモリ側を学習されていない `VectorRanker.k` で符号化していた。KEY2-F は両側とも query 塔で符号化している。そのため選択がほぼランダムより悪くなり、下書きが .359/.366 になっていた。修正前の結果は superseded-keybug/ に残してあるが、使わないこと。
- 差分なしの N だけで、残差はかなり読める。unseen では ridge N の補正で .1055 → .0816（−23%）、learned では .0407 → .0159。ただし単位 oracle（unseen .0312）とはまだ大きく離れている。
- Δ を入れても N を明確には上回らない。Δ状態は差なし。ΔVLM と Δall は全分割で悪化した（ridge unseen +.0049／+.0026、CI は 0 を含まない）。Δ履歴だけは小さく改善した（ridge unseen −.0015 [−.0019, −.0011]、MLP −.0065 [−.0081, −.0050]、Dev ridge −.0019）。それでも、Δ履歴で補正した ridge（.0801）は N（.0816）とほぼ同じ水準で止まる。
- 学習済みと未学習の差：補正後の誤差は learned .016、unseen .080 で、未学習側の残差は大部分が読めずに残る。残差は少数の行に集中しており、誤差の多い上位25%の行が誤差全体の約53%を占める。unseen の行誤差は中央値 .080、90% 点 .195。小さなずれよりも、単位の取り違えによる大きな残差が主に効いている。
- グリッパー切替：N だけで AUC .85（unseen）／.91（learned）。Δall を入れると .77／.81 に下がる。Dev には10ステップ内の切替が1件もない（Dev 217行はすべて task 6/7 の frame 0〜75 で、グリッパーは開いたまま）。このため Dev の AUC は定義できず、None はバグではない。hold-last は定数予測なので AUC は定義上 .5。
- 限界：MLP は全バッチで80ステップしか学習しておらず、Dev で選ばれたのも最終 epoch だった。学習不足で、ridge より悪い。MLP の数値は下限の参考値として扱う。
