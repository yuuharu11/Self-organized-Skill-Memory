# KQ2：運動キーの比較と、GRU の h が VLM トークンを読むクエリ

## 結論
- **最初の判定：未学習 20 Hz で直前保持（.0470）を下回る行はなかった。** 最良は第2段の「VLM なし GRU」（i）で .0510 ± .0001（3 seed）。直前保持との差は +.0040 [+.0003, +.0078] で、有意に負けている。参考行の学習なし DCT3 キー×C1b クエリ（.0497）も、直前保持との差 +.0027 [−.0020, +.0079] で届かない。
- **提案（GRU の h が VLM トークンをクロスアテンションで読む）は未学習で大きく悪化した。** Dev v2 で選んだ構成（GRU 1層・クロス 2層・FFN）は未学習 .0742 ± .0024。C1b との差は +.0220 [+.0180, +.0264]、VLM なしの同じ GRU との差は +.0232 [+.0192, +.0277]。学習済みは .0413 で、VLM なしと同じ（差 +.0001）。注意はほぼ一様（正規化エントロピー .97〜1.00）なのに、Attn 出力のノルムは h の 1.1 倍ある。評価時に VLM を行間で入れ替えると top-1 の 97% が変わり、MSE は .12 になる。クエリは「場面の平均ベクトル」に強く引っ張られている。VQ-A の FiLM と同じ壊れ方で、層数・FFN・全履歴・MLP 化・教師 τ・学習率のどれを変えても直らなかった（未学習 .074〜.106）。
- **VLM なし GRU（i）は C1b をわずかに上回った。** 未学習 .0510 対 .0522（差 −.0011 [−.0023, −.0000]）、学習済み .0413 対 .0425（差 −.0012 [−.0025, −.0000]）。区間の上端が 0 に触れる程度の差。効いた要素は、(1) 状態の履歴を 10 ステップ分入れたこと、(2) 全候補 softmax と柔らかい目標（one-hot InfoNCE だと .0607 で大きく悪化）、(3) GRU 1層で FFN なし（同じ入力・学習の MLP は .0538、FFN ありの GRU も .0538）。
- **キー（第1段）では、現行 K-x1 を Dev v2 で超える学習キーは見つからなかった。** K-SA（セルフアテンション depth 1〜3、クロス 1〜2 層、FFN 有無）と X1 再学習を、τ∈{.005,.01,.02,.05,.1,.2} で 300 epoch 回した。C1b クエリで測る下流 (b) は τ=.05 が内側の最適で、3 seed の Dev は X1 再学習 .0578、K-SA .0585。K-x1 は .0574。選択規則（Dev v2 の 3 seed 平均）どおり、第2段のキーは K-x1 のままにした。キー空間の最近傍 (a) は τ を上げるほど少し良くなる（未学習 .0245→.0231）。一方で下流は、τ≤.02 で長く学習した鍵ほど悪化する（.059〜.066）。(a) と (b) は一致しない。
- **学習なし DCT3 キーが下流でも最良だった。** 3 seed で Dev .0550、未学習 .0497（C1b との差 −.0024 [−.0054, +.0010]）。特に最初の単位で良い（.0407。直前保持 .0500、C1b .0725）。ただし依頼で参考上限として扱う行なので、選択からは外した。第2段の学習（全候補・距離スコア）とは相性が悪く（Dev .0650）、第2段には持ち込んでいない。

## データと前処理の確認（注意点）
- **状態の履歴を作り直した。** unseen20 と Dev v2 20 Hz は、HDF5 の obs/ee_states＋gripper_states を no-op 除去後の同じステップで取り、π0.5 の q01/q99 で正規化した。行動の目標・行動の履歴・開始時の状態は、既存の行と一致した（最大差 0〜2.4e-7）。learned と eh は LeRobot parquet から作り、こちらも一致した（行動 1.4e-5、learned の状態 5.3e-5）。トークン j は [a_{τ−1}, s_τ, 行動の有無フラグ]（τ = t−9..t）。最後のトークンが現在の状態になる。
- **状態の定義を数値で確認した。** LIBERO-40 の 6 episode（3 タスク）で、LeRobot の状態と元 HDF5 の obs を、align40.json で対応を取ったステップで比べた。生値の平均絶対差は、位置 .003〜.006 m、軸角 .014〜.037 rad、グリッパー .001。正規化後の平均絶対差は .009〜.05、p99 はグリッパー以外で ≤ .14。定義（位置 3・軸角 3・グリッパー qpos 2）と正規化は一致している。残る差は、LeRobot 版が再生成（replay）されたデモであることによる小さなずれと考えられる。軸角の x 成分は π 付近にあり、符号の反転は起きていない（state_definition_check.json）。分割ごとの状態分布は state_distribution.json。
- **既存の C1b 学習データに不具合があった。** KQ-final／CT1 の eh キャッシュでは、frame を 10 で割った余りが 5 の学習行（12,766 行中 6,183 行）で、state が 5 フレーム前のものになっていた（最大差 1.45。5 フレーム前の state とは 5.5e-5 で一致）。C1b と第1段 (b) は、比較を保つため元の入力のまま学習した（損失は KQ-final と完全に一致）。第2段は正しい状態で学習した。評価用の行（learned、unseen20、Dev v2）の状態は正しい。
- VLM トークンには vq-b-01/feats を使った。20 Hz の開始時刻で取り直した版なので、開始がずれた 6 行も正しい画像になっている。全 532 トークンではなく、VLM 出力の画像トークンを 4×4 にプーリングした 32 個と、言語の平均・最後の 2 個、計 34 トークン。既存キャッシュとの平均の一致は cos 1.0000（vq-b-01/cache_check.json）。
- 第1段 (b) の実装は、KQ-final の train_row と同じ乱数列・損失・候補集合を使い、誤差行列だけを先に計算する。K-x1・seed 4101 の epoch 1・2 の損失は KQ-final と完全に一致し、選ばれた epoch（14）と未学習 .0509 も KQ-final C1b s1 の 20 Hz 採点と一致した。K-x1 の 3 seed（.0517）は、VQ-A の「C1b、Dev v2 選択」.0517 と一致する。同じ鍵で seed 1 を 2 回回すと、完全に同じ値になった（決定的）。
- 第2段の学習：
  - 候補はメモリの全 4,516 単位で softmax をとる（自 episode は除外）。目標は softmax(−腕MSE/τ)。
  - 同じタスクの別 episode の単位のうち、誤差がその行の同場面の中央値より大きく、スコアが最大のものを難しい負例とした（margin .1、重み .1）。全候補 softmax なので、同場面の単位は常に分母に入っている。
  - バッチ 256、AdamW、cosine、40 epoch。logit scale は学習し、上限 100。観測側の拡張はなし。
  - Dev v2 で epoch ごとに選択した。学習行は stride 5 の全フレーム（eh 12,766 行）。
- 第2段の予備（plan_pre.json の pre_* 行）は、seed 1・K-x1 キーで回し、学習法と層の選択に使った。
- 未学習の部分集合は小さい（向き変化は 17 行）ので、区間が広い。

## 実行コマンド（再現）
```
cd skill_moe/skillnet/examples/memory_pilot/unseen_libero
export OMP_NUM_THREADS=8 MKL_NUM_THREADS=8          # すべて nice -n 10 で実行
P=/work/.skillnet-state/envs/skillnet/bin/python
$P kq2_data.py build                 # 4 split の系列・状態履歴・VLM トークン（data/*/check.json に一致確認）
$P kq2_data.py state_check           # LeRobot と HDF5 の状態定義の比較（HF から LIBERO-40 HDF5 を range-read）
$P kq2_run.py baselines              # 直前保持・oracle・C1b 3 seed・K-x1/DCT3 の (a)
$P kq2_run.py keys  --plan <OUT>/plan_keys.json   [--names ...]   # 第1段：キー学習（300 epoch、曲線つき）
(cd <OUT> && python3 make_keyq_plan.py 1,2,3 <key names>)        # (b) の行を plan_keyq.json に追加
$P kq2_run.py keyq  --plan <OUT>/plan_keyq.json   [--names ...]   # 第1段 (b)：C1b クエリ
$P kq2_run.py query --plan <OUT>/plan_pre.json    [--names ...]   # 第2段 予備（学習法・層）
$P kq2_run.py query --plan <OUT>/plan_query.json  [--names ...]   # 第2段 最終（3 seed）
$P kq2_run.py ablate --plan <OUT>/plan_query.json --names iii_G1X2F_s1 iii_G1X2F_s2 iii_G1X2F_s3 iii_G1X1F_s1 ii_MLP_X2F_s1 iii_full_G1X2F_s1
$P kq2_report.py                     # results.json と tables.md
```
<OUT> は .skillnet-state/outputs/memory-pilot/unseen-libero/kq2-01。同じ名前の行は lock ファイルで1プロセスだけが走るので、同じ名前の列を複数のワーカーに渡してよい（実際の起動は <OUT>/run_worker.sh）。json がある行は飛ばすので、途中から再開できる。
