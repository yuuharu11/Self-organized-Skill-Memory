## 対照学習と入力・漏洩監査

soft InfoNCE: 候補集合 C は同一ミニバッチの他 unit-start keys と一様抽出したメモリ単位。自エピソード候補を mask する。q_j=softmax(exp(logit_scale)·sim(E(q),E(k_j)))、p_j=softmax(−arm6_MSE_j/τ_train)、L=−Σ_j p_j log q_j。τ_train は Dev で {.002,.005,.01,.02} から選択。logit_scale は1/.07で初期化し100で上限。H/KL/NDCGの教師分布は全方式でτ=.01固定。hard controlは許容候補内の最小arm6 MSEのみを正例とするhard InfoNCE。

モデル入力は各入力条件ごとの現在VLM token/group、現在フレーム画像からのV-JEPA token/camera group、過去に実行済みの行動履歴とmask、現在stateの指定部分だけ。タスクID・エピソードID・未来行動・正解の続き・ラベル・正解境界は入力特徴に含めない。IDはメモリ側学習の同一エピソード候補除外と episode bootstrap のみ。評価窓の行動は順位教師、指標、oracleに限る。
各方式で保存された leakage_audit を results.json に含めた。因果履歴テストは時刻 t 以後の行動を変更しても _episode_history の返す履歴・状態が不変で、将来教師だけが変わることを確認する。クエリパッカーの不変性テストは target actions、task/episode IDs、row/key、hard mask を書き換えてもクエリ埋め込みが不変であることを確認する。

評価行は固定 learned 621 (難125) / unseen 619 (難134)。学習済みデモ行の選択は既存 CMP3 evaluation-selection.json / PI0REF selection.npz を再利用し、設定選択は Dev のみ。top-k は自然長10-step再生行動を softmax 平均する。閉ループ評価は行っていない。正解行動はメモリ側教師・Dev選択・採点・oracle診断に限って用いた。

## 解釈と再現情報

入力条件: E-VLMはVLM prefixだけ、E-VLM+Hはこれに過去10ステップの行動と現在状態、E-VJ+HはV-JEPA base/wrist＋履歴/状態、E-VJ+VLM+Hは両画像特徴＋履歴/状態、E-Hは履歴/状態だけ。P0はVLM平均のMLP、P5はVLM平均＋履歴/状態のMLP。separateはクエリ側Eと、保存単位の腕6軸10step値を平坦化したメモリ側キーを分ける対照であり、クエリに未来の行動は与えない。
主MSEは腕6軸の二乗和/(10×7)、すなわちグリッパーだけ正解値に置いたactive7。同時に保存グリッパーをそのまま使うactive7も示した。top-1が主結果で、Dev選択top-kは別条件。
順位指標は全4,516候補に対して計算する。Spearmanは予測スコアと負の腕MSEの相関。Recall@kは誤差最小k件と予測上位k件の重なり率、MRRは最小誤差候補の逆順位。回収率=(random誤差−top1誤差)/(random誤差−oracle誤差)。H(p,q)/KL/NDCGの教師はp=softmax(−腕MSE/.01)固定、q=softmax(score/Dev選択温度)。学習教師τと報告教師τ、score温度を区別する。
Top20腕MSEは上位20候補それぞれの誤差の平均であり、ブレンド後の誤差ではない。oracleの選択目的も腕6軸MSEであり、その保存グリッパーを用いたactive7に対する最適性は保証しない。hard InfoNCEでは学習教師τを使わない（記録上の.005はダミー引数）。
同じ再生法oracleは各選択点での貪欲な候補選択、DIM3 oracleは列全体のDPであり、同じ上限ではない。正解行動を使う診断なので実行時の検索器ではない。
自然長DCT3の全行再計算によるCMP3一致はレビュー済みsmokeで確認済み。本番では固定行・行数・保存基準の一致を検査し、DP参考値は再学習や履歴に依存しない保存済み診断を再利用した。
attempt-25のモデル結果は履歴と教師温度の不具合で無効。参考DP値のみ、履歴・学習と独立の固定診断として再利用した。
