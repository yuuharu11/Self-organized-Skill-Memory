# θ のデノイズと Expert での仕上げ

問い：メモリから型を選んだ後、向きと大きさ（θ）を観測からデノイズで決められるか。できた下書きを π0.5 の Expert でさらにデノイズすると良くなるか。

## 結論

- **θ のフローマッチングは、同じネットの回帰よりは良いが、LoRA で学習した θ 回帰には届かない。** 未学習 LIBERO-90 の行動 MSE（6軸＋G1 グリッパー、全体 / 難しい行）で flow .207〜.214、bridge .201〜.216、回帰 .217、LoRA θ .186、π0.5 の出力から取った θ .233〜.246。π0.5 は .361 / .434。
- **保留タスクでは flow .041 なのに、未学習で悪化する。** 凍結した VLM 特徴が学習済みの場面に合わせ込まれていて、汎化しない（[型の選び方](motion_query.md) と同じ傾向）。
- **LoRA θ の .186 は「ほぼ動かない予測」。** 予測の振幅（RMS .126）が正解（.411）の3割しかなく、型の選び方によらずほぼ同じ値になる（oracle の型でも .186）。直前の行動を保つだけの基準は 6軸で .114 なので、π0.5 より良く見える数字の大半は指標の性質。
- **Expert での仕上げは、どの下書きでも改善しない。** 事前に決めた t0 では下書きと差がなく、t0 を上げるほど悪化する。正解の θ を使った下書き（.088）でも t0 とともに悪化する。

## 方法

**θ の表し方：** 選んだ型を、回転（軸角3次元）と単一スケール（対数1次元）の4次元 θ で場面に置く。θ* は正解行動に Procrustes で合わせた値で、採点側の上限。

**θ のデノイズ（`theta_flow.py`）：**

```
入力 c = [画像トークン 4×4×2カメラ, VLM 群平均3, 型 70次元, θ_src, 直前10ステップの実行行動, 状態]
flow   : θ_1 ~ N(0, I) から θ_0 へ積分（openpi の時間の向き：t=1 がノイズ）
bridge : θ_1 = θ_src + σ·ε から θ_0 へ（型の出どころの θ から出発）
regress: 同じネットで θ を直接回帰（対照）
```

- 教師：LIBERO-40 の各行で、自タスクを除いた上位3候補の型に Procrustes で合わせた θ*。
- 時点と方式の選択：K1 の保留タスク（6軸誤差）。flow と bridge は 30 エポック、回帰は 24 エポックが選ばれた。
- 推論時のノイズ：ゼロ（zero）と乱数（seed）の両方を示す。

**Expert での仕上げ（`expert_refine.py`）：** 下書き＝選んだ型×θ＋G1 グリッパー。`x=(1−t0)·下書き+t0·ε` から Expert の bridge サンプラーで戻す。Expert は公開 `pi05_libero`（base）と、[圧縮表現から始めるデノイズ](compressed_denoise.md) で学習した A-vm-none / A-raw。主な設定は事前に固定した：型＝P6（トークン＋履歴）、θ＝保留タスクで最良の θ 方式（flow）、t0＝各 Expert の Dev 選択値（A-* は .05）。他の t0 と base は診断。

**LoRA θ（`lora_theta_on_selected.py`）：** [θ回帰と型選択](theta_regression.md) で Dev 選択した L-vlm（C_vm_none）の θ ヘッドを、K1 の各方式で選んだ型にそのまま当てた。

## 結果：θ の決め方（未学習 Eval、6軸＋G1、全体 / 難しい行）

| θ の決め方 | oracle の型 | 履歴で選んだ型（P5） | トークン＋履歴（P6） | 平均（P0） |
|---|---:|---:|---:|---:|
| θ*（上限） | .088 / .129 | .110 / .202 | .118 / .206 | .145 / .268 |
| LoRA θ | .186 / .297 | .187 / .297 | .187 / .295 | .188 / .298 |
| bridge（ゼロ） | .206 / .345 | **.201** / .323 | .210 / .329 | .234 / .357 |
| flow（ゼロ） | .205 / .327 | .207 / .331 | .209 / .316 | .235 / .360 |
| 回帰 | .221 / .370 | .217 / .331 | .233 / .353 | .251 / .366 |
| π0.5 の出力に合わせた θ | .244 / .370 | .237 / .360 | .244 / .358 | .246 / .367 |
| 型の出どころの θ（θ_src） | .261 / .378 | .245 / .384 | .257 / .393 | .259 / .380 |

通常 π0.5 は .361 / .434。G1 グリッパーの寄与は .0515 / .0610。全条件の表と 95% 区間は出力の `theta-flow-01/report.md`。

## 結果：Expert での仕上げ（未学習 Eval、全体）

| Expert | 下書き | 下書きのまま | t0=.05 | t0=.2 | t0=.4 | t0=.6 |
|---|---|---:|---:|---:|---:|---:|
| base | flow | .2135 | .2128 | .2072 | .2111 | .2327 |
| base | LoRA θ | .1865 | .1871 | .1922 | .2105 | .2353 |
| base | π0.5 の θ | .2436 | .2434 | .2424 | .2434 | .2512 |
| base | θ*＋oracle の型（上限） | .0881 | .0885 | .0946 | .1292 | .1898 |
| A-vm-none | flow | .2135 | .2137（事前設定） | .2135 | .2310 | .2488 |

base で flow の下書きを t0=.2〜.3 にすると .007 ほど下がるが、これは診断の t0 で、事前に決めた設定ではない。A-raw を含む全条件は出力の `expert-refine-01/report.md`。

閉ループでも同じ向きの結果が出ている：τ=.08 の単位メモリの下書きを base Expert で戻すと、未学習 LIBERO-90 の上積みが消え、学習済みの LIBERO-10 では π0.5 の水準に戻る（[閉ループ評価](closed_loop_unit_memory.md)）。

## 読むときの注意

- オフラインの行動誤差で、閉ループの成功率ではない。
- 「直前の行動を保つ」（6軸 .114 / .201）より悪い条件が多い。π0.5 との比較だけで「良い」と判断しない。
- 未学習タスクの正解行動は採点だけに使っている。θ* と oracle の型は上限の診断。
- コードはテストとレビュー前。
